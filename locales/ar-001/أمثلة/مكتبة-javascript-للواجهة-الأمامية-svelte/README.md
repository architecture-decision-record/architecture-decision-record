# سجل قرار البنية المعمارية: مكتبة JavaScript للواجهة الأمامية Svelte

الحالة: مقبول

## السياق

نطوّر تطبيق ويب باستخدام إطار JavaScript حديث للواجهة الأمامية. ونريد اختيار مكتبة خفيفة وسريعة وسهلة الاستخدام. وقد قيّمنا عدة مكتبات منها React وVue وAngular. وسمعنا أيضًا عن Svelte، التي تدّعي أنها نوع جديد من الأطر الخفيفة. ونحتاج إلى تقييم Svelte وتقرير ما إذا كانت مناسبة لتطبيقنا.

## القرار

بعد النظر في فوائد كل مكتبة وعيوبها، قررنا استخدام Svelte مكتبةَ JavaScript للواجهة الأمامية للأسباب التالية:

1. **خفيفة:**  Svelte من أخف المكتبات المتاحة، مما سيساعدنا على إبقاء حجم تطبيقنا صغيرًا وتحسين أزمنة تحميل الصفحات.

2. **سريعة:**  تشتهر Svelte بسرعة العرض، مما سيجعل تطبيقنا يبدو متجاوبًا وخفيف الحركة.

3. **سهلة الاستخدام:**  صياغة Svelte بسيطة وسهلة الفهم، مما سيسهّل على فريقنا اعتمادها وكتابة شيفرة نظيفة.

4. **محسَّنة لعرض واجهة المستخدم:**  Svelte محسَّنة لعرض مكونات واجهة المستخدم، مما سيسهّل علينا إنشاء عناصر واجهة ديناميكية وقابلة لإعادة الاستخدام.

5. **توثيق جيد ودعم مجتمعي:**  لدى Svelte مجتمع متنامٍ وتوثيق جيد، مما سيساعدنا على البدء بسرعة وحل أي مشكلات تظهر.

## البدائل

نظرنا في React وVue وAngular، لكننا قررنا عدم اعتمادها للأسباب التالية:

1. **React:**  رغم أن لدى React قاعدة مستخدمين كبيرة وثروة من المكتبات والموارد، فقد تكون معقدة وصعبة التعلم، خصوصًا للمبتدئين.

2. **Vue:**  Vue مكتبة خفيفة سهلة التعلم والاستخدام، لكنها قد لا تكون بسرعة Svelte ولا بتحسينها.

3. **Angular:**  Angular إطار شامل يوفر ميزات وأدوات كثيرة، لكنه قد يكون ثقيلًا ومعقدًا، وقد يتطلب صيانة أكثر من Svelte.

## العواقب

سيكون لاستخدام Svelte مكتبةً للواجهة الأمامية العواقب التالية:

1. سيكون تطبيقنا خفيفًا وسريعًا، مما سيحسّن تجربة المستخدم وتفاعله.

2. سيحتاج فريقنا إلى تعلّم مكتبة جديدة، لكن صياغة Svelte بسيطة وسهلة الفهم، لذا ينبغي أن يكون منحنى التعلم قابلًا للإدارة.

3. لا تزال Svelte مكتبة حديثة نسبيًا، لذا قد نواجه بعض المشكلات غير الموثقة جيدًا أو غير المدعومة من المجتمع.

4. مجتمع مستخدمي Svelte في نمو، لذا قد نرى في المستقبل مزيدًا من المكتبات والموارد التابعة لأطراف ثالثة يمكن استخدامها لاستكمال المكتبة الأساسية.
