# ਆਰਕੀਟੈਕਚਰ ਫੈਸਲਾ ਰਿਕਾਰਡ: JSON ਬਨਾਮ gRPC ਵਰਤਣ ਵਾਲੀ API

## ਸਥਿਤੀ

ਸਵੀਕਾਰ

## ਪ੍ਰਸੰਗ

ਅਸੀਂ ਇੱਕ ਨਵੀਂ ਸੇਵਾ ਲਈ API ਡਿਜ਼ਾਈਨ ਕਰ ਰਹੇ ਹਾਂ ਜਿਸ ਨੂੰ ਕਈ ਕਲਾਇੰਟ ਵਰਤਣਗੇ। ਅਸੀਂ API ਨੂੰ ਲਾਗੂ ਕਰਨ ਲਈ ਦੋ ਵਿਕਲਪਾਂ ਉੱਤੇ ਵਿਚਾਰ ਕਰ ਰਹੇ ਹਾਂ: HTTP ਉੱਤੇ JSON ਵਰਤਣਾ ਜਾਂ gRPC ਵਰਤਣਾ।

HTTP ਉੱਤੇ JSON API ਬਣਾਉਣ ਲਈ ਇੱਕ ਵਿਆਪਕ ਤੌਰ ਉੱਤੇ ਵਰਤੀ ਜਾਂਦੀ ਪਹੁੰਚ ਹੈ, ਅਤੇ ਇਸ ਨੂੰ ਕਈ ਪ੍ਰੋਗਰਾਮਿੰਗ ਭਾਸ਼ਾਵਾਂ ਅਤੇ ਫਰੇਮਵਰਕ ਸਹਾਰਾ ਦਿੰਦੇ ਹਨ। ਇਹ ਪਹੁੰਚ ਸਾਦੀ, ਹਲਕੀ ਅਤੇ ਸਮਝਣ ਵਿੱਚ ਆਸਾਨ ਹੈ, ਜਿਸ ਕਾਰਨ ਇਹ ਕਈ ਪ੍ਰੋਜੈਕਟਾਂ ਲਈ ਚੰਗੀ ਚੋਣ ਹੈ। ਫਿਰ ਵੀ, ਇਹ ਹੋਰ ਵਿਕਲਪਾਂ ਨਾਲੋਂ ਘੱਟ ਕੁਸ਼ਲ ਹੋ ਸਕਦੀ ਹੈ, ਖਾਸ ਕਰਕੇ ਜਦੋਂ ਵੱਡੀ ਮਾਤਰਾ ਵਿੱਚ ਡਾਟਾ ਸੰਭਾਲਣ ਦੀ ਗੱਲ ਆਵੇ।

ਦੂਜੇ ਪਾਸੇ, gRPC ਇੱਕ ਨਵੀਂ ਤਕਨਾਲੋਜੀ ਹੈ ਜੋ API ਬਣਾਉਣ ਦਾ ਵਧੇਰੇ ਕੁਸ਼ਲ ਤਰੀਕਾ ਪੇਸ਼ ਕਰਦੀ ਹੈ। ਇਹ ਡਾਟਾ ਤਬਦੀਲ ਕਰਨ ਲਈ ਬਾਈਨਰੀ ਸੀਰੀਅਲਾਈਜ਼ੇਸ਼ਨ ਵਰਤਦੀ ਹੈ, ਜੋ JSON ਵਰਤਣ ਨਾਲੋਂ ਤੇਜ਼ ਅਤੇ ਵਧੇਰੇ ਸੰਖੇਪ ਹੋ ਸਕਦੀ ਹੈ। gRPC ਦੋ-ਪਾਸੀ ਸਟ੍ਰੀਮਿੰਗ ਨੂੰ ਵੀ ਸਹਾਰਾ ਦਿੰਦੀ ਹੈ, ਜਿਸ ਨਾਲ ਇਹ ਰੀਅਲ-ਟਾਈਮ ਐਪਲੀਕੇਸ਼ਨਾਂ ਲਈ ਚੰਗੀ ਚੋਣ ਬਣਦੀ ਹੈ।

## ਫੈਸਲਾ

ਦੋਵਾਂ ਵਿਕਲਪਾਂ ਦੇ ਫਾਇਦਿਆਂ ਅਤੇ ਨੁਕਸਾਨਾਂ ਉੱਤੇ ਵਿਚਾਰ ਕਰਨ ਤੋਂ ਬਾਅਦ, ਅਸੀਂ ਆਪਣੀ API ਲਈ gRPC ਵਰਤਣ ਦਾ ਫੈਸਲਾ ਕੀਤਾ ਹੈ। ਭਾਵੇਂ HTTP ਉੱਤੇ JSON ਸਾਦਾ ਵਿਕਲਪ ਹੈ, ਸਾਡਾ ਮੰਨਣਾ ਹੈ ਕਿ gRPC ਸਾਡੀ ਸੇਵਾ ਲਈ ਵਧੇਰੇ ਕੁਸ਼ਲ ਅਤੇ ਵਧਣਯੋਗ ਹੱਲ ਦੇਵੇਗੀ। ਅਸੀਂ ਇਹ ਵੀ ਅੰਦਾਜ਼ਾ ਲਾਉਂਦੇ ਹਾਂ ਕਿ ਸਾਡੀ API ਵੱਡੀ ਮਾਤਰਾ ਵਿੱਚ ਡਾਟਾ ਸੰਭਾਲੇਗੀ, ਅਤੇ gRPC ਦੀ ਬਾਈਨਰੀ ਸੀਰੀਅਲਾਈਜ਼ੇਸ਼ਨ ਇਸ ਵਰਤੋਂ ਦੇ ਕੇਸ ਲਈ ਵਧੇਰੇ ਕੁਸ਼ਲ ਹੋਵੇਗੀ।

ਇਸ ਤੋਂ ਇਲਾਵਾ, ਸਾਡਾ ਮੰਨਣਾ ਹੈ ਕਿ gRPC ਦੀ ਦੋ-ਪਾਸੀ ਸਟ੍ਰੀਮਿੰਗ ਲਈ ਸਹਾਇਤਾ ਉਨ੍ਹਾਂ ਰੀਅਲ-ਟਾਈਮ ਐਪਲੀਕੇਸ਼ਨਾਂ ਲਈ ਲਾਭਦਾਇਕ ਹੋਵੇਗੀ ਜੋ ਅਸੀਂ ਭਵਿੱਖ ਵਿੱਚ ਵਿਕਸਿਤ ਕਰ ਸਕਦੇ ਹਾਂ।

## ਨਤੀਜੇ

gRPC ਚੁਣਨ ਨਾਲ, ਸਾਨੂੰ HTTP ਉੱਤੇ JSON ਵਰਤਣ ਦੇ ਮੁਕਾਬਲੇ ਆਪਣੀ API ਬਣਾਉਣ ਲਈ ਟੂਲਾਂ ਅਤੇ ਲਾਇਬ੍ਰੇਰੀਆਂ ਦਾ ਵੱਖਰਾ ਸਮੂਹ ਵਰਤਣਾ ਪਵੇਗਾ। ਇਨ੍ਹਾਂ ਤਕਨਾਲੋਜੀਆਂ ਨੂੰ ਸਿੱਖਣ ਅਤੇ ਲਾਗੂ ਕਰਨ ਲਈ ਵਾਧੂ ਸਮਾਂ ਅਤੇ ਮਿਹਨਤ ਲੱਗ ਸਕਦੀ ਹੈ। ਇਸ ਤੋਂ ਇਲਾਵਾ, ਜਿਹੜੇ ਕਲਾਇੰਟ ਸਾਡੀ API ਵਰਤਣਾ ਚਾਹੁੰਦੇ ਹਨ, ਉਨ੍ਹਾਂ ਨੂੰ gRPC-ਅਨੁਕੂਲ ਲਾਇਬ੍ਰੇਰੀਆਂ ਵਰਤਣੀਆਂ ਪੈਣਗੀਆਂ, ਜਿਨ੍ਹਾਂ ਨੂੰ ਸ਼ਾਇਦ HTTP ਉੱਤੇ JSON ਲਾਇਬ੍ਰੇਰੀਆਂ ਜਿੰਨਾ ਵਿਆਪਕ ਸਮਰਥਨ ਪ੍ਰਾਪਤ ਨਹੀਂ ਹੈ।

ਫਿਰ ਵੀ, ਸਾਡਾ ਮੰਨਣਾ ਹੈ ਕਿ gRPC ਵਰਤਣ ਦੇ ਫਾਇਦੇ ਇਨ੍ਹਾਂ ਸੰਭਾਵੀ ਨੁਕਸਾਨਾਂ ਨਾਲੋਂ ਵੱਧ ਹਨ, ਅਤੇ ਸਾਨੂੰ ਭਰੋਸਾ ਹੈ ਕਿ ਇਹ ਫੈਸਲਾ ਵਧੇਰੇ ਕੁਸ਼ਲ ਅਤੇ ਵਧਣਯੋਗ API ਦੇ ਰੂਪ ਵਿੱਚ ਸਾਹਮਣੇ ਆਵੇਗਾ।
