# 架构决策记录：Kubernetes 容器编排

## 问题陈述

阿拉需要为日益增长个云原生应用组合选一个容器编排平台。阿拉现在个遗留平台部署太慢，勿够敏捷，跟勿上阿拉增长个需要。阿拉辣找一个系统，可以让阿拉用最高效个办法扩展服务，同时勿牺牲敏捷性或者易用性。

## 考虑过个备选方案

1. Docker Swarm

2. Kubernetes

3. Apache Mesos

## 做出个决策

对每个容器编排平台做了全面分析之后，阿拉决定采用 Kubernetes，当作满足阿拉企业需要个最好选项。阿拉选 Kubernetes 个理由如下：

1. **可扩展性：**Kubernetes 独特个设计非常适合扩展应用，而且随着阿拉对可扩展性个需求随辰光演变，Kubernetes 内置个能力可以毫无问题地满足迭眼变化。

2. **去中心化架构：**Kubernetes 个主从拓扑确保了去中心化个架构，所以呒没单点故障。

3. **社区支持：**Kubernetes 有最大、最活跃个开源社区，意味着有大量个贡献者、开发者搭供应商，让阿拉更加容易得到帮助，找着资源。

4. **生态支持：**Kubernetes 有一个不断增长个生态，有各种第三方工具，还有搭容器镜像仓库、CI/CD 流水线、数据存储等等个集成。

所以，阿拉决定现在搭近期采用 Kubernetes 作为阿拉个容器编排平台。
