# آرکیٹیکچر فیصلے کا ریکارڈ: REST API کے لیے snake_case یا camelCase؟

فیصلہ: REST API اینڈ پوائنٹس کے لیے snake_case نام رکھنے کا اصول استعمال کیا جائے گا

حالت: قبول شدہ

## سیاق و سباق

REST APIs کے لیے نام رکھنے کے اصولوں میں دو مقبول شکلیں ہیں: snake_case اور camelCase۔ snake_case کی شکل میں نام کا ہر لفظ انڈر اسکور سے الگ کیا جاتا ہے، جبکہ camelCase میں نام کا پہلا لفظ چھوٹے حروف میں ہوتا ہے، اور بعد کے الفاظ کا پہلا حرف بڑا ہوتا ہے۔ یہ فیصلہ طے کرے گا کہ REST API کے لیے کون سا نام رکھنے کا اصول استعمال کیا جائے۔

## فیصلے کے محرکات

- منصوبے میں موجودہ نام رکھنے کے اصولوں سے مطابقت

- API پر کام کرنے والے ہر کسی کے لیے پڑھنے کی آسانی اور وضاحت

- REST API کے نام رکھنے کے اصولوں کے لیے صنعت کی بہترین مشقوں سے ہم آہنگی

- نفاذ اور دیکھ بھال کی آسانی

## فیصلہ

REST API اینڈ پوائنٹس کے لیے snake_case نام رکھنے کا اصول استعمال کیا جائے گا۔ یہ انتخاب درج ذیل عوامل پر مبنی ہے:

1. **مطابقت (Consistency)**: منصوبہ پہلے ہی تمام اینڈ پوائنٹس کے لیے snake_case نام رکھنے کا اصول استعمال کرتا ہے، اور پورے منصوبے میں مطابقت یقینی بنانے کے لیے اس اصول کو برقرار رکھنا فائدہ مند ہوگا۔

2. **پڑھنے کی آسانی اور وضاحت**: snake_case کا اصول زیادہ پڑھنے کے قابل اور سمجھنے میں آسان ہے۔ انڈر اسکورز الفاظ کے درمیان واضح علیحدگی دیتے ہیں، جس سے نام کے معنی کا تجزیہ اور فہم آسان ہوتا ہے۔

3. **صنعت کی بہترین مشقوں سے ہم آہنگی**: snake_case کا اصول صنعت میں وسیع پیمانے پر استعمال ہوتا ہے اور REST APIs کے لیے بہترین مشق سمجھا جاتا ہے، جو اسے منصوبے کے لیے اچھا انتخاب بناتا ہے۔

4. **نفاذ اور دیکھ بھال کی آسانی**: موجودہ نام رکھنے کے اصول کو برقرار رکھنا نافذ اور برقرار رکھنا آسان ہے کیونکہ نیا اصول چنے جانے کی صورت میں تمام موجودہ کوڈ اور دستاویزات کو اپ ڈیٹ کرنا پڑتا۔

## نتائج

اس فیصلے کے ممکنہ نتائج ہیں۔ 

* اگر منصوبے میں شامل ہونے والے نئے ٹیم اراکین snake_case نام رکھنے کے اصول سے ناواقف ہوں تو یہ ڈویلپمنٹ میں الجھن اور غلطیوں کا باعث بن سکتا ہے۔ تاہم چونکہ snake_case ایک وسیع پیمانے پر استعمال ہونے والا اصول ہے، ایسا خطرہ کم سے کم ہے۔ 
  
* اگر منصوبے میں دوسرے ٹولز یا فریم ورکس استعمال ہوں جو بڑی حد تک camelCase اصول پر مبنی ہوں تو نام رکھنے کے اصولوں کے درمیان تبدیلی کے لیے اضافی کوشش درکار ہو سکتی ہے۔ تاہم یہ بڑی تشویش نہیں کیونکہ منصوبے نے snake_case اصول کو معیار بنا لیا ہے۔ 
 
مجموعی طور پر REST API اینڈ پوائنٹس کے لیے snake_case نام رکھنے کا اصول استعمال کرنے کا فیصلہ ایک مطابقت رکھنے والا، پڑھنے کے قابل اور صنعت کے معیار کے مطابق طریقہ دیتا ہے، ساتھ ہی نافذ کرنا اور برقرار رکھنا آسان ہے۔
