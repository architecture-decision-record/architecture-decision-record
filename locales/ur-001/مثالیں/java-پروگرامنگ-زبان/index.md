# آرکیٹیکچر فیصلے کا ریکارڈ: Java پروگرامنگ زبان

عنوان: منصوبے کے لیے Java پروگرامنگ زبان کا انتخاب

فیصلہ: متعدد پروگرامنگ زبانوں کا جائزہ لینے کے بعد ہم نے اپنے منصوبے کے لیے Java استعمال کرنے کا فیصلہ کیا ہے۔

### پس منظر

ہم ایک ویب پر مبنی ایپلیکیشن بنانا چاہتے تھے جو متعدد آپریٹنگ سسٹمز پر چل سکے۔ ہمارے منصوبے کو ایسی زبان درکار تھی جو مضبوط سیکیورٹی خصوصیات فراہم کر سکے، concurrency سنبھال سکے، بڑے کوڈ بیسز کو سپورٹ کرے اور ہمارے مستقبل کی نشوونما کے تقاضے پورے کرنے کے لیے کافی ہمہ جہت ہو۔ Java پر فیصلہ کرنے سے پہلے ہم نے متعدد زبانوں کی طاقتوں اور حدود پر غور کرتے ہوئے ان کا جائزہ لیا۔

### غور و فکر

1. **سیکیورٹی:**  Java اپنی اچھی طرح متعین سیکیورٹی پالیسیوں اور رسائی کے کنٹرول کے ذریعے بہترین سیکیورٹی خصوصیات فراہم کرتی ہے۔ اس میں بائٹ کوڈ کی تصدیق جیسی خصوصیات بھی شامل ہیں، جو نقصان دہ سافٹ ویئر کو سسٹم پر چلنے سے روکنے میں مدد دیتی ہیں۔

2. **Concurrency:**  Java میں ملٹی تھریڈنگ کی اندرونی سپورٹ ہے، جو ایپلیکیشنز کو بیک وقت کئی کام انجام دینے دیتی ہے۔ یہ خصوصیت Java کو متعدد خصوصیات اور فعالیتوں والی بڑی، پیچیدہ ایپلیکیشنز بنانے کے لیے بہترین انتخاب بناتی ہے۔

3. **بڑے کوڈ بیسز:**  Java آبجیکٹ اورینٹڈ پروگرامنگ کو سپورٹ کرتی ہے، جو اسے بڑے کوڈ بیسز بنانے کے لیے موزوں انتخاب بناتا ہے۔ اس کی ماڈیولر نوعیت اور انکیپسولیشن اور ایبسٹریکشن پیٹرنز کا استعمال سافٹ ویئر ڈویلپمنٹ کے عمل کی آسانی میں مزید اضافہ کرتا ہے۔

4. **ہمہ جہتی:**  Java ہمہ جہت ہے اور لائبریریوں اور فریم ورکس کی وسیع رینج استعمال کرنے کی صلاحیت فراہم کرتی ہے، جو اسے ویب پر مبنی اور انٹرپرائز سطح کی دونوں ایپلیکیشنز کے لیے بہترین انتخاب بناتی ہے۔

### فیصلے کا نتیجہ

ہم نے اپنے منصوبے کے لیے Java پروگرامنگ زبان استعمال کرنے کا فیصلہ کیا ہے، اس کی سیکیورٹی خصوصیات، concurrency کی سپورٹ، بڑے کوڈ بیسز سنبھالنے کی صلاحیت اور ہمہ جہتی کو مدنظر رکھتے ہوئے۔ یہ فیصلہ ہمارے منصوبے کے تقاضوں سے ہم آہنگ ہے، اور ہمیں یقین ہے کہ Java کا انتخاب اس کی کامیابی یقینی بنائے گا۔ 

### نتائج

1. ہمیں ایسے ڈویلپرز کی ضرورت ہوگی جنہیں Java کا تجربہ ہو اور جو اسے مہارت سے استعمال کر سکیں۔

2. اس زبان میں لکھا گیا کوئی بھی کوڈ Java ورچوئل مشین (JVM) سے ہم آہنگ ہونا چاہیے۔

3. نئی خصوصیات، فعالیتوں یا فریم ورکس کو شامل کرنا کچھ چیلنجز پیش کر سکتا ہے۔

4. Java میں بڑے، پیچیدہ منصوبوں کی ڈویلپمنٹ میں زیادہ وقت اور وسائل درکار ہو سکتے ہیں۔
