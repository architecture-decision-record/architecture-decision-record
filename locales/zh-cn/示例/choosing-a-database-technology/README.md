# 架构决策记录:选择数据库技术

## 状态

已接受

## 背景

我们正在设计一个新的应用,它需要以可扩展且高性能的方式存储和检索数据。我们确定了三类常用的数据库技术:关系型数据库、文档型数据库和事件数据库。

关系型数据库将数据存储在具有固定模式的表中,并强制执行严格的数据完整性约束。它们适用于需要复杂数据关系和事务的应用。示例包括 MySQL、PostgreSQL 和 Oracle。

文档型数据库将数据存储在类似 JSON 的文档中,并且无模式。它们非常适合需要灵活数据模型和水平扩展的应用。示例包括 MongoDB、Couchbase 和 Amazon DynamoDB。

事件数据库将数据存储为一系列事件,记录对数据的每一次更改。它们适用于需要审计、事件溯源和复杂数据处理的应用。示例包括 Apache Kafka、Apache Pulsar 和 AWS Kinesis。

## 决策

在仔细评估了我们应用的需求和约束之后,我们决定使用文档型数据库。

## 理由

我们选择文档型数据库,是因为:

1. 我们的应用需要一个能够随时间演进的灵活数据模型。文档型数据库允许我们以无模式的格式存储数据,这意味着我们可以添加新字段或更改现有文档的结构,而无需修改数据库模式。

2. 我们的应用需要水平扩展,以处理海量数据和流量。文档型数据库内置了对分片和复制的支持,这使我们能够将数据分布到多台服务器上,并处理高读写吞吐量。

3. 我们的应用需要快速高效地检索数据。文档型数据库提供强大的索引和查询能力,使我们能够快速高效地检索数据。

4. 我们的应用不需要复杂的事务或数据关系。虽然关系型数据库在强制执行数据完整性约束和处理复杂事务方面表现出色,但我们的应用并没有这样的需求。文档型数据库可以为我们的使用场景提供足够的一致性和持久性保证。

## 后果

选择文档型数据库后,我们需要投入精力学习和了解所选用的具体技术。此外,我们需要确保应用的数据模型与文档型数据库的数据模型相契合,以最大限度地提高性能和可扩展性。

不过,我们相信使用文档型数据库的好处超过其代价,并且它最适合我们应用的需求和约束。
