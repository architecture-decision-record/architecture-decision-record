# 商業論證的決策記錄範本

這個 ADR 範本強調為決策構建商業論證,包括評估標準、候選方案和成本。


## 頂層結構

* 標題
* 狀態
* 評估標準
* 待考慮的候選方案
* 對每個候選方案的調研與分析
  * 是否滿足標準及原因
  * 成本分析
  * SWOT 分析
  * 意見與反饋
* 建議


## 底層詳解

**標題**:

  * 一個簡短的一般現在時祈使短語,少於 50 個字元,類似 git 提交資訊。

**狀態**:

  * 已提議、已接受、已拒絕、已棄用、已取代等之一。

**評估標準**:

  * 概要:簡要說明我們要探尋什麼以及原因。

  * 具體內容

**待考慮的候選方案**:

  * 概要:簡要說明我們是如何發現候選方案的,並提請注意任何異常值。

  * 列出所有候選方案和相關選項;我們要評估哪些潛在的解決方案?

  * 具體內容

**對每個候選方案的調研與分析**:

  * 概要:簡要說明調研方法,並提請注意其中的模式、聚類和異常值。

  * 是否滿足標準及原因

    * 概要

    * 具體內容

  * 成本分析

    * 概要

    * 範例

      * 許可,例如合同通訊協定和法律承諾

      * 培訓,例如技能提升和變更管理

      * 運營,例如支援和維護

      * 計量,例如頻寬和 CPU 使用量

  * SWOT 分析

    * 概要

    * 優勢(Strengths)

    * 劣勢(Weaknesses)

    * 機會(Opportunities)

    * 威脅(Threats)

  * 內部意見與反饋

    * 概要

    * 範例

      * 來自團隊,最好由當事人親自撰寫

      * 來自其他利益相關者

      * 品質屬性,也稱為跨職能需求

  * 外部意見與反饋

    * 概要

    * 誰在提供這些意見?

    * 你考慮過哪些其他候選方案?

    * 你在構建什麼?

      * 範例

        * B2B 還是 B2C

        * 面向外部還是僅限員工使用

        * 桌面端還是移動端

        * 試點還是生產

        * 單體應用還是微服務

    * 你是如何評估候選方案的?

    * 你為什麼選擇了勝出者?

    * 自那以後情況如何?

      * 範例

        * 勝出者的表現如何?

        * 真實生產環境使用者流量中有多大比例經過勝出者?

        * 涉及哪些型別的整合,例如與持續交付流水線、內容管理系統、分析與指標系統等的整合?

        * 以你現在所知,你會建議大家在哪些方面採取不同的做法?

  * 軼事

**建議**:

  * 概要

  * 具體內容
