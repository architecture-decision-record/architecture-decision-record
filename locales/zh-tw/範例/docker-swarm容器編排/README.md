## 決策

我們決定使用 Docker Swarm 作為我們的容器編排工具。Docker Swarm 提供了一種簡單直觀的方式,來管理跨節點叢集的容器化應用。它還使我們能夠利用現有的基於 Docker 的工作流和基礎設施。藉助 Docker Swarm,我們可以輕鬆地部署、擴充套件和管理應用,同時利用內建的負載均衡。

## 優勢

- **簡單性:**  Docker Swarm 遵循與 Docker 相同的原則,因此無需學習新技術。對於熟悉 Docker 的開發者來說,學習曲線相對平緩。

- **整合:**  Docker Swarm 與 Docker Compose 等 Docker 工具無縫整合,使我們更容易在同一個地方管理所有容器和服務。

- **負載均衡:**  Docker Swarm 提供內建的負載均衡,確保我們的應用始終可用,並均勻分佈在叢集中。

- **可擴充套件性:**  透過在叢集中新增或移除節點,Docker Swarm 使我們能夠輕鬆地水平擴充套件應用。

- **高可用性:**  Docker Swarm 會自動將我們的服務分佈到各個節點上,在節點發生故障時提供高可用性。

## 風險

- **功能有限:**  Docker Swarm 可能缺少 Kubernetes 或 Mesosphere DC/OS 中的一些高階功能,例如自動擴縮容或自我修復。

- **以 Docker 為中心:**  Docker Swarm 與 Docker 緊密耦合,如果我們將來需要脫離基於 Docker 的解決方案,這可能會限制我們的靈活性。

- **不夠成熟:**  Docker Swarm 仍是一項相對較新的技術,可能存在一些穩定性問題或文件缺口。

- **Kubernetes:**  Kubernetes 是使用最廣泛的容器編排平臺,提供高階功能和更成熟的生態系統。然而,它的學習曲線更陡峭,對於我們的需求來說可能是小題大做。

- **Mesosphere DC/OS:**  Mesosphere DC/OS 是一款功能強大的工具,提供多雲支援以及原生的大資料和 AI 平臺能力等高階功能。然而,實施它需要大量的專業知識,對於我們的需求來說可能過於複雜。

## 結論

經過慎重考慮,我們決定使用 Docker Swarm 作為我們的容器編排工具。Docker Swarm 提供了我們管理容器化應用所需的簡單性、整合和內建負載均衡。雖然它可能缺少一些高階功能,但我們相信,就我們當前的需求而言,Docker Swarm 的優勢超過其風險。
