# Modelo de Registro de Decisão de Arquitetura (ADR) <!-- Substitua pelo título da ADR -->

Este é um modelo para ADR do EdgeX Foundry.

Fonte: https://docs.edgexfoundry.org/2.3/design/adr/template/


### Submetedores

Liste os submetedores da ADR.

Formato:

- Nome (Organização)


## Log de alterações

Liste as alterações no documento, incluindo estado, data e URL do PR.

O estado é um de: pendente, aprovado, emendado, obsoleto.

A data é uma string ISO 8601 (YYYY-MM-DD).

O PR é o pull request que submeteu a alteração, incluindo informações como diff, contribuidores e revisores.

Formato:

- \[Status da ADR, por exemplo, aprovado, emendado etc.\]\(URL do pull request\) YYYY-MM-DD


## Caso(s) de uso referenciado(s)

Liste todos os documentos relevantes de caso de uso / requisitos.

A ADR exige pelo menos um caso de uso relevante e aprovado.

Formato:

- \[Nome do caso de uso\]\(URL\)

Adicione explicações se a ADR não abordar todos os requisitos de um caso de uso.


## Contexto

Descreva:

- como o design é arquiteturalmente significativo - justificando uma ADR (em vez de uma simples issue e PR para corrigir um problema)

- a abordagem de design de alto nível (detalhes descritos no design proposto abaixo)


## Design proposto

Detalhes do design (sem entrar em implementação quando possível).

Esboço:

- serviços/módulos a serem impactados (alterados)

- novos serviços/módulos a serem adicionados

- impacto em modelo e DTO (alterações/adições/remoções)

- impacto em API (alterações/adições/remoções)

- impacto em configuração geral (estabelecimento de novas seções, alterações/adições/remoções)

- impacto em devops


## Considerações

Documente alternativas, preocupações, questões auxiliares ou relacionadas, perguntas que surgiram no debate da ADR.

Indique se/como elas foram resolvidas ou atenuadas.


## Decisão

Documente qualquer detalhe de implementação importante acordado, ressalvas, considerações futuras, questões de design restantes ou adiadas.

Documente qualquer parte dos requisitos não satisfeita pelo design proposto.


## Outras ADRs relacionadas

Liste quaisquer ADRs relevantes - como uma decisão de design para um subcomponente de uma funcionalidade, um design tornado obsoleto como resultado deste design etc..

Formato:

- \[Título da ADR\]\(URL\) - Relevância


## Referências

Liste referências adicionais.

Formato:

- \[Título\]\(URL\)
