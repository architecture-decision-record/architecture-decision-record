# Registro de decisão de arquitetura: biblioteca JavaScript de front-end Svelte

Estado: aceito

## Contexto

Estamos desenvolvendo uma aplicação web usando um framework JavaScript de front-end moderno. Queremos escolher uma biblioteca que seja leve, rápida e fácil de usar. Avaliamos várias bibliotecas, incluindo React, Vue e Angular. Também ouvimos falar do Svelte, que afirma ser um novo tipo de framework leve. Precisamos avaliar o Svelte e decidir se ele é adequado para a nossa aplicação.

## Decisão

Após considerar os benefícios e as desvantagens de cada biblioteca, decidimos usar o Svelte como nossa biblioteca JavaScript de front-end pelos seguintes motivos:

1. **Leve:**  o Svelte é uma das bibliotecas mais leves disponíveis, o que nos ajudará a manter o tamanho da nossa aplicação pequeno e a melhorar os tempos de carregamento das páginas.

2. **Rápido:**  o Svelte é conhecido por sua velocidade de renderização, o que fará nossa aplicação parecer responsiva e ágil.

3. **Fácil de usar:**  a sintaxe do Svelte é simples e fácil de entender, o que facilitará para a nossa equipe adotá-lo e escrever código limpo.

4. **Otimizado para renderização de UI:**  o Svelte é otimizado para renderizar componentes de UI, o que facilitará para nós criar elementos de UI dinâmicos e reutilizáveis.

5. **Boa documentação e apoio da comunidade:**  o Svelte tem uma comunidade em crescimento e boa documentação, o que nos ajudará a começar rapidamente e a resolver quaisquer problemas que surjam.

## Alternativas

Consideramos React, Vue e Angular, mas decidimos não adotá-los pelos seguintes motivos:

1. **React:**  embora o React tenha uma grande base de usuários e uma riqueza de bibliotecas e recursos, ele pode ser complexo e difícil de aprender, especialmente para iniciantes.

2. **Vue:**  o Vue é uma biblioteca leve, fácil de aprender e usar, mas pode não ser tão rápido nem tão otimizado quanto o Svelte.

3. **Angular:**  o Angular é um framework abrangente que oferece muitos recursos e ferramentas, mas pode ser pesado e complexo, e pode exigir mais manutenção do que o Svelte.

## Consequências

Usar o Svelte como nossa biblioteca JavaScript de front-end terá as seguintes consequências:

1. Nossa aplicação será leve e rápida, o que melhorará a experiência e o engajamento do usuário.

2. Nossa equipe precisará aprender uma nova biblioteca, mas a sintaxe do Svelte é simples e fácil de entender, então a curva de aprendizado deve ser administrável.

3. O Svelte ainda é uma biblioteca relativamente nova, então podemos encontrar alguns problemas que não sejam bem documentados ou suportados pela comunidade.

4. A comunidade de usuários do Svelte está crescendo, então podemos ver mais bibliotecas e recursos de terceiros se tornarem disponíveis no futuro, que podem ser usados para complementar a biblioteca principal.

## Conclusão

Com base na nossa avaliação, decidimos usar o Svelte como nossa biblioteca JavaScript de front-end para a nossa aplicação web. Acreditamos que a natureza leve e rápida do Svelte, a facilidade de uso e a renderização de UI otimizada fazem dele a melhor escolha para as nossas necessidades.
