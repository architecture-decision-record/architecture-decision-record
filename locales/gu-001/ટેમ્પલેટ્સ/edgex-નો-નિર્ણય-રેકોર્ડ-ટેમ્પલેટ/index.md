# આર્કિટેક્ચર નિર્ણય રેકોર્ડ (ADR) ટેમ્પલેટ <!-- Replace with ADR title -->

સ્રોત: https://docs.edgexfoundry.org/2.3/design/adr/template/


### સબમિટર્સ

ADR સબમિટર્સની યાદી આપો.

ફોર્મેટ:

- નામ (સંસ્થા)


## ફેરફાર લોગ

દસ્તાવેજમાંના ફેરફારોની યાદી આપો, સ્થિતિ, તારીખ અને PR URL સહિત.

સ્થિતિ આમાંથી એક છે: બાકી, મંજૂર, સુધારેલ, અપ્રચલિત.

તારીખ ISO 8601 (YYYY-MM-DD) સ્ટ્રિંગ છે.

PR એ પુલ રિક્વેસ્ટ છે જેણે ફેરફાર સબમિટ કર્યો, જેમાં diff, યોગદાનકર્તાઓ અને સમીક્ષકો જેવી માહિતી શામેલ છે.

ફોર્મેટ:

- \[ADR ની સ્થિતિ દા.ત. મંજૂર, સુધારેલ, વગેરે\]\(પુલ રિક્વેસ્ટનો URL\) YYYY-MM-DD


## સંદર્ભિત ઉપયોગ કેસ

બધા સંબંધિત ઉપયોગ કેસ / જરૂરિયાત દસ્તાવેજોની યાદી આપો.

ADR ને ઓછામાં ઓછો એક સંબંધિત, મંજૂર ઉપયોગ કેસ જોઈએ.

ફોર્મેટ:

- \[ઉપયોગ કેસનું નામ\]\(URL\)

જો ADR ઉપયોગ કેસની તમામ જરૂરિયાતોને સંબોધતો ન હોય તો સમજૂતીઓ ઉમેરો.


## સંદર્ભ

વર્ણવો:

- ડિઝાઇન આર્કિટેક્ચરલ રીતે કેવી રીતે મહત્વપૂર્ણ છે - ADR ને યોગ્ય ઠેરવતી (સમસ્યા ઠીક કરવા માટે સરળ issue અને PR ની સામે)

- ઉચ્ચ-સ્તરીય ડિઝાઇન અભિગમ (વિગતો નીચે પ્રસ્તાવિત ડિઝાઇનમાં વર્ણવેલ છે)


## પ્રસ્તાવિત ડિઝાઇન

ડિઝાઇનની વિગતો (જ્યાં શક્ય હોય ત્યાં અમલીકરણમાં ગયા વિના).

રૂપરેખા:

- અસરગ્રસ્ત (બદલાતી) સેવાઓ/મોડ્યુલ્સ

- ઉમેરવામાં આવનારી નવી સેવાઓ/મોડ્યુલ્સ

- મોડેલ અને DTO પર અસર (ફેરફારો/ઉમેરા/દૂર કરવા)

- API પર અસર (ફેરફારો/ઉમેરા/દૂર કરવા)

- સામાન્ય રૂપરેખાંકન પર અસર (નવા વિભાગોની સ્થાપના, ફેરફારો/ઉમેરા/દૂર કરવા)

- devops પર અસર


## વિચારણાઓ

ADR ની ચર્ચામાં ઉદ્ભવેલા વિકલ્પો, ચિંતાઓ, આનુષંગિક અથવા સંબંધિત મુદ્દાઓ અને પ્રશ્નો નોંધો. 

જણાવો કે તે ઉકેલાયા કે હળવા થયા કે નહીં અને કેવી રીતે.


## નિર્ણય

સંમત થયેલી કોઈપણ મહત્વપૂર્ણ અમલીકરણ વિગત, ચેતવણીઓ, ભવિષ્યની વિચારણાઓ, બાકી અથવા મોકૂફ ડિઝાઇન મુદ્દાઓ નોંધો.

પ્રસ્તાવિત ડિઝાઇન દ્વારા સંતોષાયેલી ન હોય તેવી જરૂરિયાતોનો કોઈપણ ભાગ નોંધો.


## અન્ય સંબંધિત ADR

કોઈપણ સંબંધિત ADR ની યાદી આપો - જેમ કે કોઈ સુવિધાના પેટા-ઘટક માટેનો ડિઝાઇન નિર્ણય, આ ડિઝાઇનના પરિણામે અપ્રચલિત થયેલી ડિઝાઇન, વગેરે.
