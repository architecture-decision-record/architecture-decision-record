# רשומת החלטה ארכיטקטונית: תזמור קונטיינרים עם Kubernetes

## הצגת הבעיה 

אנו צריכים לבחור פלטפורמת תזמור קונטיינרים לתיק יישומי הענן-מקומיים (cloud-native) הגדל שלנו. הפריסה הנוכחית שלנו בפלטפורמת המורשת איטית מדי ואינה אג'ילית מספיק כדי לעמוד בצרכינו הגדלים. אנו מחפשים מערכת שתאפשר לנו להרחיב את השירותים שלנו בדרך היעילה ביותר האפשרית בלי לוותר על זריזות או על קלות שימוש.

## חלופות שנשקלו

1. Docker Swarm

2. Kubernetes

3. Apache Mesos

## ההחלטה שהתקבלה

לאחר ניתוח יסודי של כל פלטפורמת תזמור קונטיינרים, החלטנו לאמץ את Kubernetes כאפשרות הטובה ביותר לצרכי הארגון שלנו. הסיבות שלנו לבחירה ב-Kubernetes הן:

1. **יכולת הרחבה:**  העיצוב הייחודי של Kubernetes מושלם להרחבת יישומים, וככל שדרישות יכולת ההרחבה שלנו יתפתחו עם הזמן, ל-Kubernetes יש יכולת מובנית לעמוד בשינויים האלה בלי בעיות.

2. **ארכיטקטורה מבוזרת:**  טופולוגיית ה-master-worker של Kubernetes מבטיחה ארכיטקטורה מבוזרת שמבטיחה שאין נקודת כשל יחידה.

3. **תמיכת קהילה:**  ל-Kubernetes יש את קהילת הקוד הפתוח הגדולה והפעילה ביותר, מה שאומר שיש לה מספר רב של תורמים, מפתחים וספקים, וזה מקל עלינו לקבל עזרה ולמצוא משאבים.

4. **תמיכת אקוסיסטם:**  ל-Kubernetes יש אקוסיסטם גדל עם מגוון כלי צד שלישי, אינטגרציות עם רישומי קונטיינרים, צינורות CI/CD, אחסון נתונים ועוד.

לכן החלטנו לאמץ את Kubernetes כפלטפורמת תזמור הקונטיינרים שלנו להווה ולעתיד הקרוב.
