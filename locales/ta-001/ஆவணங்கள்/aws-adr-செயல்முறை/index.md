# AWS கட்டமைப்பு முடிவு பதிவுகள் செயல்முறை

https://docs.aws.amazon.com/prescriptive-guidance/latest/architectural-decision-records/adr-process.html

கட்டமைப்பு முடிவு பதிவு (ADR) என்பது ஒரு குழு உருவாக்கத் திட்டமிட்டுள்ள மென்பொருள் கட்டமைப்பின் ஒரு குறிப்பிடத்தக்க அம்சம் பற்றிச் செய்யும் தேர்வை விவரிக்கும் ஆவணம். ஒவ்வொரு ADR உம் கட்டமைப்பு முடிவு, அதன் சூழல், அதன் விளைவுகளை விவரிக்கிறது. ADR களுக்கு நிலைகள் உண்டு, எனவே அவை ஒரு வாழ்க்கைச்சுழற்சியைப் பின்பற்றுகின்றன. ADR இன் எடுத்துக்காட்டுக்கு, பின்னிணைப்பைப் பார்க்கவும்.

ADR செயல்முறை கட்டமைப்பு முடிவு பதிவுகளின் தொகுப்பை வெளியிடுகிறது. இந்தத் தொகுப்பு முடிவுப் பேரேட்டை உருவாக்குகிறது. முடிவுப் பேரேடு திட்டச் சூழலையும், விரிவான நடைமுறைப்படுத்தல் மற்றும் வடிவமைப்புத் தகவலையும் வழங்குகிறது. திட்டச் சூழலின் மேலோட்டத்தைப் பெற திட்ட உறுப்பினர்கள் ஒவ்வொரு ADR இன் தலைப்புகளையும் பார்வையிடுகிறார்கள். திட்ட நடைமுறைப்படுத்தல்கள், வடிவமைப்புத் தேர்வுகளில் ஆழமாக ஆராய அவர்கள் ADR களைப் படிக்கிறார்கள்.

குழு ஒரு ADR ஐ ஏற்றுக்கொள்ளும்போது, அது மாற்ற இயலாததாகிறது. புதிய நுண்ணறிவுகளுக்கு வேறு முடிவு தேவைப்பட்டால், குழு புதிய ADR ஐ முன்மொழிகிறது. குழு புதிய ADR ஐ ஏற்றுக்கொள்ளும்போது, அது முந்தைய ADR ஐ மாற்றியமைக்கிறது.

## ADR செயல்முறையின் நோக்கம்

மென்பொருள் திட்டம் அல்லது தயாரிப்பைப் பாதிக்கும் ஒவ்வொரு கட்டமைப்பு ரீதியாக முக்கியமான முடிவுக்கும் திட்ட உறுப்பினர்கள் ADR ஐ உருவாக்க வேண்டும், இவற்றை உள்ளடக்கி (Richards and Ford 2020):

* அமைப்பு (எடுத்துக்காட்டாக, microservices போன்ற வடிவங்கள்)

* செயல்பாடற்ற தேவைகள் (பாதுகாப்பு, உயர் கிடைப்புத்திறன், பிழை சகிப்புத்தன்மை)

* சார்புகள் (கூறுகளின் இணைப்பு)

* இடைமுகங்கள் (API கள் மற்றும் வெளியிடப்பட்ட ஒப்பந்தங்கள்)

* கட்டுமான நுட்பங்கள் (நூலகங்கள், கட்டமைப்புகள், கருவிகள், செயல்முறைகள்)

* செயல்பாட்டு மற்றும் செயல்பாடற்ற தேவைகள் ADR செயல்முறையின் மிகவும் பொதுவான உள்ளீடுகள்.


## ADR உள்ளடக்கங்கள்

குழு ADR இன் தேவையை அடையாளம் காணும்போது, ஒரு குழு உறுப்பினர் திட்டம் முழுவதும் பொருந்தும் வார்ப்புருவின் அடிப்படையில் ADR ஐ எழுதத் தொடங்குகிறார். (எடுத்துக்காட்டு வார்ப்புருக்களுக்கு ADR GitHub நிறுவனத்தைப் பார்க்கவும்.) வார்ப்புரு ADR உருவாக்கத்தை எளிதாக்குவதோடு, ADR தொடர்புடைய அனைத்துத் தகவலையும் கைப்பற்றுவதை உறுதிசெய்கிறது. குறைந்தபட்சம், ஒவ்வொரு ADR உம் முடிவின் சூழல், முடிவு, திட்டம் மற்றும் அதன் வழங்கல்களுக்கான முடிவின் விளைவுகளை வரையறுக்க வேண்டும். (இந்தப் பகுதிகளின் எடுத்துக்காட்டுகளுக்கு, பின்னிணைப்பைப் பார்க்கவும்.) ADR அமைப்பின் மிக வலுவான அம்சங்களில் ஒன்று, குழு அதை எவ்வாறு நடைமுறைப்படுத்தியது என்பதை விட முடிவுக்கான காரணத்தில் கவனம் செலுத்துவது. குழு முடிவை ஏன் எடுத்தது என்பதைப் புரிந்துகொள்வது மற்ற குழு உறுப்பினர்கள் முடிவை ஏற்றுக்கொள்வதை எளிதாக்குகிறது, மேலும் முடிவெடுக்கும் செயல்முறையில் ஈடுபடாத பிற கட்டமைப்பாளர்கள் எதிர்காலத்தில் அந்த முடிவைத் தலைகீழாக்குவதைத் தடுக்கிறது.


## ADR ஏற்புச் செயல்முறை

ஒவ்வொரு குழு உறுப்பினரும் ADR ஐ உருவாக்கலாம், ஆனால் குழு ADR க்கான உரிமையின் வரையறையை நிறுவ வேண்டும். ADR இன் உரிமையாளரான ஒவ்வொரு ஆசிரியரும் ADR உள்ளடக்கத்தைச் செயலூக்கத்துடன் பராமரித்துத் தெரிவிக்க வேண்டும். இந்த உரிமையைத் தெளிவுபடுத்த, இந்த வழிகாட்டி பின்வரும் பகுதிகளில் ADR ஆசிரியர்களை ADR உரிமையாளர்கள் என்று குறிப்பிடுகிறது. பிற குழு உறுப்பினர்கள் எப்போதும் ADR க்குப் பங்களிக்கலாம். குழு ADR ஐ ஏற்கும் முன் ADR உள்ளடக்கம் மாறினால், உரிமையாளர் இந்த மாற்றங்களை ஒப்புக்கொள்ள வேண்டும்.

குழு ஒரு கட்டமைப்பு முடிவையும் அதன் உரிமையாளரையும் அடையாளம் கண்ட பிறகு, ADR உரிமையாளர் செயல்முறையின் தொடக்கத்தில் ADR ஐ **முன்மொழியப்பட்டது** நிலையில் வழங்குகிறார். முன்மொழியப்பட்டது நிலையில் உள்ள ADR கள் மதிப்பாய்வுக்குத் தயாராக உள்ளன.

பின்னர் ADR உரிமையாளர் ADR க்கான மதிப்பாய்வுச் செயல்முறையைத் தொடங்குகிறார். ADR மதிப்பாய்வுச் செயல்முறையின் குறிக்கோள், குழு ADR ஐ ஏற்கிறதா, அதற்கு மறுவேலை தேவை என்று தீர்மானிக்கிறதா, அல்லது ADR ஐ நிராகரிக்கிறதா என்பதை முடிவுசெய்வது. உரிமையாளர் உட்பட திட்டக் குழு ADR ஐ மதிப்பாய்வு செய்கிறது. மதிப்பாய்வுக் கூட்டம் ADR ஐப் படிப்பதற்காக ஒதுக்கப்பட்ட நேரத்துடன் தொடங்க வேண்டும். சராசரியாக, 10 முதல் 15 நிமிடங்கள் போதுமானவை. இந்த நேரத்தில், ஒவ்வொரு குழு உறுப்பினரும் ஆவணத்தைப் படித்து, தெளிவற்ற தலைப்புகளைக் குறிக்கக் கருத்துகளையும் கேள்விகளையும் சேர்க்கிறார். மதிப்பாய்வுக் கட்டத்திற்குப் பிறகு, ADR உரிமையாளர் ஒவ்வொரு கருத்தையும் குழுவுடன் வாசித்து விவாதிக்கிறார்.

ADR ஐ மேம்படுத்த குழு செயல் புள்ளிகளைக் கண்டறிந்தால், ADR இன் நிலை **முன்மொழியப்பட்டது** ஆகவே இருக்கும். ADR உரிமையாளர் செயல்களை வகுத்து, குழுவுடன் இணைந்து, ஒவ்வொரு செயலுக்கும் ஒரு ஒதுக்கப்பட்டவரைச் சேர்க்கிறார். ஒவ்வொரு குழு உறுப்பினரும் செயல் புள்ளிகளுக்குப் பங்களித்து அவற்றைத் தீர்க்கலாம். மதிப்பாய்வுச் செயல்முறையை மீண்டும் திட்டமிடுவது ADR உரிமையாளரின் பொறுப்பு.

குழு ADR ஐ நிராகரிக்கவும் முடிவு செய்யலாம். இந்த நிலையில், அதே தலைப்பில் எதிர்கால விவாதங்களைத் தடுக்க ADR உரிமையாளர் நிராகரிப்பிற்கான காரணத்தைச் சேர்க்கிறார். உரிமையாளர் ADR நிலையை **நிராகரிக்கப்பட்டது** என மாற்றுகிறார்.

குழு ADR ஐ அங்கீகரித்தால், உரிமையாளர் நேரமுத்திரை, பதிப்பு, பங்குதாரர்களின் பட்டியலைச் சேர்க்கிறார். பின்னர் உரிமையாளர் நிலையை **ஏற்கப்பட்டது** எனப் புதுப்பிக்கிறார்.

ADR களும் அவை உருவாக்கும் முடிவுப் பேரேடும் குழு எடுத்த முடிவுகளைப் பிரதிநிதித்துவப்படுத்தி, அனைத்து முடிவுகளின் வரலாற்றை வழங்குகின்றன. சாத்தியமான இடங்களில் குறியீடு மற்றும் கட்டமைப்பு மதிப்பாய்வுகளின்போது குழு ADR களைக் குறிப்பாகப் பயன்படுத்துகிறது. குறியீட்டு மதிப்பாய்வுகள், வடிவமைப்புப் பணிகள், நடைமுறைப்படுத்தல் பணிகளைச் செய்வதோடு கூடுதலாக, தயாரிப்பின் உத்திசார் முடிவுகளுக்கு குழு உறுப்பினர்கள் ADR களை அணுக வேண்டும்.

நல்ல நடைமுறையாக, ஒவ்வொரு மென்பொருள் மாற்றமும் சக மதிப்பாய்வுகள் வழியாகச் சென்று குறைந்தது ஒரு ஒப்புதலைக் கோர வேண்டும். குறியீட்டு மதிப்பாய்வின்போது, ஒரு குறியீட்டு மதிப்பாய்வாளர் ஒன்று அல்லது அதற்கு மேற்பட்ட ADR களை மீறும் மாற்றங்களைக் காணலாம். இந்த நிலையில், மதிப்பாய்வாளர் குறியீட்டு மாற்றத்தின் ஆசிரியரைக் குறியீட்டைப் புதுப்பிக்கும்படி கேட்டு, ADR இன் இணைப்பைப் பகிர்கிறார். ஆசிரியர் குறியீட்டைப் புதுப்பிக்கும்போது, சக மதிப்பாய்வாளர்களால் அது அங்கீகரிக்கப்பட்டு முதன்மைக் குறியீட்டு அடிப்படையில் இணைக்கப்படுகிறது.


## ADR மதிப்பாய்வுச் செயல்முறை

குழு ADR களை ஏற்றுக்கொண்ட அல்லது நிராகரித்த பிறகு அவற்றை மாற்ற இயலாத ஆவணங்களாகக் கருத வேண்டும். ஏற்கனவே உள்ள ADR இல் மாற்றங்களுக்குப் புதிய ADR ஐ உருவாக்கி, புதிய ADR க்கான மதிப்பாய்வுச் செயல்முறையை நிறுவி, ADR ஐ அங்கீகரிக்க வேண்டும். குழு புதிய ADR ஐ அங்கீகரித்தால், உரிமையாளர் பழைய ADR இன் நிலையை **மாற்றியமைக்கப்பட்டது** என மாற்ற வேண்டும்.
