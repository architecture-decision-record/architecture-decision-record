# கட்டமைப்பு முடிவு பதிவு: JSON அல்லது gRPC பயன்படுத்தும் API

## நிலை

ஏற்கப்பட்டது

## சூழல்

பல வாடிக்கையாளர்களால் பயன்படுத்தப்படும் புதிய சேவைக்கான API ஐ நாங்கள் வடிவமைக்கிறோம். API ஐ நடைமுறைப்படுத்த இரண்டு விருப்பங்களை நாங்கள் பரிசீலித்து வருகிறோம்: HTTP மீது JSON அல்லது gRPC.

HTTP மீது JSON என்பது API களை உருவாக்க பரவலாகப் பயன்படுத்தப்படும் அணுகுமுறை, பல நிரலாக்க மொழிகளும் கட்டமைப்புகளும் இதை ஆதரிக்கின்றன. இந்த அணுகுமுறை எளிமையானது, எடை குறைந்தது, புரிந்துகொள்ள எளிதானது, இது பல திட்டங்களுக்கு நல்ல தேர்வாகிறது. இருப்பினும், பிற விருப்பங்களை விடக் குறைவான திறன் கொண்டதாக இருக்கலாம், குறிப்பாகப் பெரிய அளவிலான தரவைக் கையாளும்போது.

gRPC, மறுபுறம், API களை உருவாக்க மிகவும் திறமையான வழியை வழங்கும் புதிய தொழில்நுட்பம். இது தரவை மாற்ற பைனரி தொடராக்கத்தைப் பயன்படுத்துகிறது, இது JSON ஐப் பயன்படுத்துவதை விட வேகமாகவும் சிறியதாகவும் இருக்கும். gRPC இருதிசை ஸ்ட்ரீமிங்கையும் ஆதரிக்கிறது, இது நிகழ்நேரப் பயன்பாடுகளுக்கு நல்ல தேர்வாக்குகிறது.

## முடிவு

இரண்டு விருப்பங்களின் நன்மை தீமைகளைப் பரிசீலித்த பிறகு, எங்கள் API க்கு gRPC ஐப் பயன்படுத்த முடிவு செய்துள்ளோம். HTTP மீது JSON எளிமையான விருப்பமாக இருந்தாலும், எங்கள் சேவைக்கு gRPC மிகவும் திறமையான, அளவிடக்கூடிய தீர்வை வழங்கும் என்று நம்புகிறோம். எங்கள் API அதிக அளவிலான தரவைக் கையாளும் என்றும் எதிர்பார்க்கிறோம், இந்தப் பயன்பாட்டிற்கு gRPC இன் பைனரி தொடராக்கம் மிகவும் திறமையானதாக இருக்கும்.

கூடுதலாக, எதிர்காலத்தில் நாங்கள் உருவாக்கக்கூடிய நிகழ்நேரப் பயன்பாடுகளுக்கு gRPC இன் இருதிசை ஸ்ட்ரீமிங் ஆதரவு நன்மை பயக்கும் என்று நம்புகிறோம்.

## விளைவுகள்

gRPC ஐத் தேர்ந்தெடுப்பதன் மூலம், HTTP மீது JSON ஐப் பயன்படுத்துவதோடு ஒப்பிடும்போது எங்கள் API ஐ உருவாக்க வேறுபட்ட கருவிகள் மற்றும் நூலகங்களின் தொகுப்பைப் பயன்படுத்த வேண்டும். இந்தத் தொழில்நுட்பங்களைக் கற்று நடைமுறைப்படுத்த கூடுதல் நேரமும் முயற்சியும் தேவைப்படலாம். கூடுதலாக, எங்கள் API ஐப் பயன்படுத்த விரும்பும் வாடிக்கையாளர்கள் gRPC-இணக்கமான நூலகங்களைப் பயன்படுத்த வேண்டும், அவை HTTP மீது JSON நூலகங்களைப் போல அவ்வளவு பரவலாக ஆதரிக்கப்படாமல் இருக்கலாம்.

இருப்பினும், gRPC பயன்பாட்டின் நன்மைகள் இந்தச் சாத்தியமான குறைபாடுகளை விட அதிகம் என்று நம்புகிறோம், இந்த முடிவு மிகவும் திறமையான, அளவிடக்கூடிய API க்கு வழிவகுக்கும் என்பதில் நம்பிக்கை கொண்டுள்ளோம்.
