## சுருக்கம்


### சிக்கல்

எங்கள் திட்டங்களை உருவாக்கவும், ஒருங்கிணைக்கவும், வரிசைப்படுத்தவும், ஹோஸ்ட் செய்யவும் devops ஐப் பயன்படுத்த விரும்புகிறோம். Microsoft Azure DevOps ஐப் பரிசீலிக்கிறோம்.

  * devops இன் அமைவுக்கு எ.கா. உள்ளமைத்தல், தொடர்ச்சியான பயன்பாட்டுக்கு எ.கா. வேகமான உருவாக்க நேரங்கள், உருவாக்குநர் அனுபவம் வேகமாகவும் நம்பகமாகவும் இருக்க விரும்புகிறோம்.
  
  * திட்டப் பயன்பாடுகள், தரவுத்தளங்கள் போன்றவற்றை ஹோஸ்ட் செய்ய Microsoft Azure ஐ முழுவதுமாகப் பயன்படுத்துவதைப் பரிசீலிக்க விரும்புகிறோம்.


### முடிவு

Microsoft Azure DevOps க்கு எதிராக முடிவு செய்யப்பட்டது.


### நிலை

முடிவு செய்யப்பட்டது. புதிய குறிப்பிடத்தக்க தகவல் வரும்போது/வந்தால் மீண்டும் பார்வையிடத் திறந்துள்ளோம்.


## விவரங்கள்


### அனுமானங்கள்

Accelerate நூலில் உள்ளது போன்ற வழக்கமான அனைத்து devops அனுமானங்களும்.

  * வேகமான உருவாக்கங்கள் குறிப்பிடத்தக்க உதவி. இது பின்னூட்டச் சுழற்சிகளை விரைவுபடுத்துகிறது.

  * மாற்று விற்பனையாளர்களிடமிருந்து பகுதிகளை உள்ளே/வெளியே மாற்றலாம், அதாவது நாங்கள் எங்கள் அதிவேக உருவாக்கச் சேவையகங்களைக் கொண்டுவர, அல்லது எங்கள் விருப்பமான பதிப்புக் கட்டுப்பாட்டு அமைப்பைப் பயன்படுத்த, அல்லது சுயமாக ஹோஸ்ட் செய்யப்பட்ட தொடர்ச்சியான ஒருங்கிணைப்புச் சேவையகத்துடன் ஒருங்கிணைக்க விரும்பலாம்.
  
  * ஒழுங்குபடுத்தப்பட்ட பயன்பாட்டுத்திறன் குறிப்பிடத்தக்க உதவி, உருவாக்குநர் அனுபவத்துக்கும், அதன் மூலம் நிலைத்தன்மை, தெளிவு, பாதுகாப்பு, கற்றல் வளைவின் எளிமை போன்ற நுட்பமான பகுதிகளுக்கும்.

  * எதுவும் உடைந்தாலோ சிக்கலாக இருந்தாலோ, சிக்கலைப் புகாரளிக்க பயனுள்ள வழி வேண்டும். இது பாதுகாப்பு தொடர்பான எந்தச் சிக்கல்களுக்கும் குறிப்பாக முக்கியம்.


### கட்டுப்பாடுகள்

அறியப்பட்டவை எதுவும் இல்லை. வெளிப்புறக் கருவிகளுடன் நன்றாக இணைந்து செயல்படுவதாக Azure க்கு வெளியிடப்பட்ட உறுதிப்பாடு உள்ளது.


### நிலைப்பாடுகள்

தற்போதைய AWS க்கு எதிராக Microsoft Azure Devops ஐப் பயன்படுத்துவதைப் பரிசீலித்தோம்.

Azure DevOps, Azure Pipelines, Azure Repo, Terraform வழியாக புதிய சேவையகத்தை Azure இல் இயக்குவது ஆகியவற்றைச் சோதித்தோம்.

Microsoft பிரதிநிதிகளிடமிருந்து ஆதரவைப் பெறுவதைச் சோதித்தோம்.

வலைப்பதிவுகள் மற்றும் Hacker News இல் சக ஊழியர்களிடமிருந்து தகவலைச் சேகரித்தோம்.


### வாதம்

Azure DevOps சிறந்த சலுகைகளின் தொகுப்பை விளம்பரப்படுத்துகிறது, ஆனால் அவை நிலைக்கவில்லை, ஒன்றோடொன்று நன்றாக வேலை செய்யவில்லை, ஆதரவு மோசமாக உள்ளது.

எங்கள் நேரடி அனுபவம்:

  * Azure அமைவு UI களின் குழப்பம், அவற்றில் சில Microsoft கணக்குகளுடன் ஒன்றுடன் ஒன்று பொருந்துகின்றன, சில பொருந்தவில்லை. எ.கா. Azure உள்நுழைவு, Microsoft.com உள்நுழைவு, Live.com உள்நுழைவு போன்றவை உள்ளன, அனைத்தும் ஒரே நேரத்தில் செயல்பாட்டில் உள்ளன.

  * அமைவின் போது ஒரு சிறிய பாதுகாப்புச் சிக்கலைச் சந்தித்தோம், தீர்வு கிடைக்கவில்லை. அதைப் புகாரளிக்க பல Microsoft பிரதிநிதிகளிடம் பல வழிகளை முயற்சித்தோம், வெற்றி கிடைக்கவில்லை. Microsoft பாதுகாப்புக்கு வெற்றிகரமாகப் புகாரளித்தோம், அது won't fix என்று பதிலளித்தது.

  * ஆவணங்கள் பெரும்பாலும் தவறானவை அல்லது காலாவதியானவை. இதில் குறைந்தது சில Microsoft இன் மோசமான தேடுபொறியால், சில தரம் குறைந்த SEO வால்.
  
  * Terraform அமைவு நன்கு ஆவணப்படுத்தப்பட்டுள்ளது, வேலை செய்கிறது. இருப்பினும், AWS உடன் ஒப்பிடும்போது Terraform ஆதரவு பலவீனமானது, ஏனெனில் Microsoft தொடர்-வழி Terraform அமைவு எடுத்துக்காட்டுகளைச் செய்ய விற்பனையாளர்களுடன் வணிக உறவுகளை உருவாக்கி வருகிறது.

எங்கள் சக ஊழியர்களின் அனுபவங்கள்:

  * நாங்கள் சொந்தமாக ஒரு குருட்டு மதிப்பீடு செய்த பிறகு, சக ஊழியர்களின் அனுபவங்களைத் தேடினோம். நாங்கள் கண்டது எங்கள் அனுபவங்களை உறுதிப்படுத்தியது.

  * சக ஊழியர்கள் உருவாக்க நேரங்கள் குறித்தும் உங்கள்-சொந்த-உருவாக்கச்-சேவையகம்-கொண்டு-வருவது குறித்தும் கூடுதல் சிக்கல்களைப் புகாரளித்தனர். இந்தச் சிக்கல்கள் UI சிக்கல்களை விடக் குறிப்பிடத்தக்க அளவு கடுமையானவை, ஏனெனில் உருவாக்கங்களைச் செய்வதுதான் உருவாக்கப் பைப்லைனின் முக்கிய நோக்கம், நாளொன்றுக்குப் பலவற்றைச் செய்வோம் என எதிர்பார்க்கிறோம்.

  * விவாதப் பகுதிகளில் Azure குழுத் தோழர்களின் சிறந்த பங்கேற்பைக் கண்டறிந்தோம். இதற்காக Microsoft க்குப் பாராட்டுகள். Azure PM மற்றும் நிரலாளரான Edward Thomson ஆல் அவரது பங்கேற்பு, நேரடித்தன்மை, தொழில்நுட்ப விளக்கங்கள் காரணமாக நாங்கள் குறிப்பாகக் கவரப்பட்டோம்.


### தாக்கங்கள்

Microsoft Azure DevOps ஐத் தேர்ந்தெடுப்பது Azure ஐத் தேர்ந்தெடுக்காததை விட நேரத்திலும் செலவிலும் (~3x) அதிக விலை கொண்டதாக இருக்கும் எனத் தெரிகிறது.


## தொடர்புடையவை


### தொடர்புடைய முடிவுகள்

Azure DevOps ஐத் தேர்ந்தெடுத்தால், Azure Repo, Azure Pipeline போன்ற பல தொடர்புடைய சலுகைகள் உள்ளன. Azure Devops ஐத் தேர்ந்தெடுத்தால், இது மேலும் Azure திறன்களைப் பயன்படுத்துவதை எளிதாக்கலாம், அல்லது பிற விற்பனையாளர்களின் திறன்களைப் பயன்படுத்துவதைக் கடினமாக்கலாம் என்று நம்புகிறோம்.

Microsoft உருவாக்குநர் அனுபவத்தில் பெரும் முன்னேற்றம் கண்டு வருவதாக நம்புகிறோம், மேலும் Microsoft உருவாக்குநர் கருவிகளின் (எ.கா. GitHub) மற்றும் சார்புகளின் (எ.கா. Citus) பெரிய கையகப்படுத்துதல்களைச் செய்வதைக் காண்கிறோம்.

Azure DevOps ஐத் தேர்ந்தெடுத்தால், Microsoft கையகப்படுத்திய சலுகைகளைத் தேர்ந்தெடுப்பதில் முக்கியத்துவம் கொடுக்க விரும்பலாம், மேலும் சாத்தியமான திசு-நிராகரிப்பு எ.கா. ஊழியர் வெளியேற்ற ஆபத்து காரணமாக கையகப்படுத்தப்பட்ட சலுகைகளை அதிக கவனத்துடன்/மதிப்பீட்டுடன் அணுக விரும்பலாம்.


### தொடர்புடைய தேவைகள்

உருவாக்க நேரங்கள் மிக வேகமாக இருக்க வேண்டும் என விரும்புகிறோம். இதற்காக அதிகக் கூடுதல் கட்டணம் செலுத்த ஒப்புக்கொள்கிறோம். ஏனெனில் நாங்கள் மிக வேகமாக மீள்செயல் செய்ய விரும்புகிறோம்.

நம்பகத்தன்மை மிக உயர்வாக இருக்க வேண்டும் என விரும்புகிறோம். இதற்காக அதிகக் கூடுதல் கட்டணம் செலுத்த ஒப்புக்கொள்கிறோம். ஏனெனில் நிதிப் பரிவர்த்தனைகள், ரகசியப் பரிவர்த்தனைகள் உட்பட உயர் மதிப்புப் பயன்பாட்டு நிகழ்வுகளைச் சோதிக்கிறோம்.

எங்கள் முதல் 4 devops KPI களில் சராசரி மீட்பு நேரம் அடங்கும், இதற்கு வேகமான உருவாக்கங்களும் உயர் நம்பகத்தன்மையும் தேவை.


### தொடர்புடைய படைப்புகள்

உருவாக்க அமைப்பு Artifactory போன்ற பிற அமைப்புகளில் பயன்படுத்த ஏற்ற படைப்புகளை வெளியிட விரும்புகிறோம்.


### தொடர்புடைய கொள்கைகள்

எளிதில் மாற்றியமைக்கக்கூடியது. தற்போதைய AWS உடன் இணையாக Azure DevOps ஐ மதிப்பீடு செய்யலாம்.

Microsoft இன் Azure DevOps (முன்பு Visual Studio Team Services என அறியப்பட்டது), தெளிவாக நல்ல நோக்கங்கள் இருந்தபோதிலும், மோசமான முடிவுகளினதும் மோசமான செயல்படுத்தலினதும் சரியான புயல்."


### Hacker News விவாத சிறப்பம்சங்கள்

https://news.ycombinator.com/item?id=18983586

"நாங்கள் எங்கள் பணியிடத்தில் Azure DevOps ஐ விரிவாகப் பயன்படுத்துகிறோம், GitHub, Gitlab, சுயமாக ஹோஸ்ட் செய்யப்பட்ட தீர்வுகள், Jenkins, TeamCity ஆகியவற்றைப் பயன்படுத்திய பிறகு... Azure DevOps கடைசி இடத்தில் உள்ளது."

"UI எல்லா இடங்களிலும் பயங்கரமாக விகாரமாக உள்ளது. எனக்கு மிக மோசமானது pull request கள். ஒரு pull request இல் மக்களுடன் வேலை செய்வது நம்பமுடியாத அளவு கடினம். என்னால் "ஒரு" குறிப்பிட்ட சிக்கலைக் கூடச் சுட்டிக்காட்ட முடியாது - எங்களுக்கு எல்லா இடங்களிலும் உடைந்துள்ளது."

"Azure Devops நான் நேசிக்க விரும்பும் ஒன்று. UI மாறிக்கொண்டே இருக்கிறது, ஆனால் பல ஆண்டுகளாக இருக்கும் அடிப்படைப் பிழைகளைச் சரிசெய்யவில்லை."

"கருவிகள் நன்றாக ஒருங்கிணைக்கப்படவில்லை, UI மிகவும் மெதுவானது, என் விருப்பமான repos க்கான செயலில் உள்ள pull request கள், உருவாக்கங்கள், வெளியீடுகள் போன்றவற்றுக்கு டாஷ்போர்டு காட்சி இல்லை. உருவாக்க/வரிசைப்படுத்தல் நேரங்கள் பைத்தியக்காரத்தனமாக மெதுவானவை."

"Azure Boards (Work Items, Boards, Backlogs, போன்றவை) ஐயும் பயன்படுத்த முயன்றோம். ஐயோ. இது தொடர்பற்ற யோசனைகளின் முழுமையான UI குழப்பம். ஒன்றை நன்றாகச் செயல்படுத்துவதற்குப் பதிலாக, இரண்டு டஜன் விஷயங்களை மோசமாகச் செயல்படுத்தியுள்ளனர்."


### Windows Development MVP

Windows Development MVP இங்கே. இந்தப் பிரச்சினைகளைப் பற்றி இன்னும் சத்தமாகப் பேசாததற்கு சில பொறுப்பை நான் ஏற்க வேண்டும் என்று உணர்கிறேன். ஆனால் நான் சொல்ல வேண்டும், UX சிக்கல்களைப் பற்றி நீங்கள் "ஆச்சரியப்படுவதாக" கேள்விப்பட்டு ஏமாற்றமடைந்தேன். உங்கள் ஆட்களிடம் UX பயங்கரமாக இருக்கிறது என்று (எ.கா. வெளியீட்டுக்கு முன்பிருந்தே) சொல்லிக்கொண்டே வருகிறேன், "எங்களுக்குத் தெரியும், சரிசெய்கிறோம்" என்று திரும்பத் திரும்ப கேட்டுக்கொண்டிருந்தேன். நான் பின்னூட்டத்தை முறைப்படுத்தி குழாய்கள் வழியாகத் தள்ளத் தொடங்குவேன், காத்திருங்கள். நான் உள்ளூரிலும் இருக்கிறேன் (Bellevue), எங்கள் ஒப்பீட்டளவில் எளிய oss .net/wpf/uwp பயன்பாட்டை பைப்லைன் செய்து பார்க்க வர விரும்புவேன். இது நம் இருவருக்கும் கண்களைத் திறக்கும் என்று சந்தேகிக்கிறேன்.

சில எடுத்துக்காட்டுகள்:

* submodules கொண்ட git repo வுடன் ஒரு பைப்லைனை உருவாக்க முடியாது

* சில தனிப்பயன் கருவிகளுக்கு PATH ஐத் திருத்துவது சாத்தியமற்றது எனக் கண்டேன்

* புதிய பைப்லைன் அனுபவம் அவ்வளவு அர்த்தமுள்ளதாக இல்லை, சுற்றிக் கிளிக் செய்யும் புதிய பயனர்கள் இறுதியில் தவறான Docs க்குச் சென்றடைவார்கள்.
