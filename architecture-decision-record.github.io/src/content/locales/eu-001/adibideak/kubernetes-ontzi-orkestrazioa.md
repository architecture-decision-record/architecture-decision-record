# Arkitektura-erabakien erregistroa: Kubernetes ontzi-orkestrazioa

## Arazoaren adierazpena 

Hodei-natiboa den gure aplikazio-portfolio hazkorrerako ontzi-orkestrazio plataforma bat aukeratu behar dugu. Gure oraingo plataforma zaharraren hedapena motelegia da, eta ez da nahikoa arina gure behar hazkorrei jarraitzeko. Gure zerbitzuak ahalik eta modu eraginkorrenean eskalatzen uziko digun sistema bat bilatzen ari gara, arintasunari edo erabiltzeko erraztasunari uko egin gabe.

## Aztertutako alternatibak

1. Docker Swarm

2. Kubernetes

3. Apache Mesos

## Hartutako erabakia

Ontzi-orkestrazio plataforma bakoitzaren analisi sakona egin ondoren, Kubernetes gure enpresa-beharretarako aukerarik onena gisa hartzea erabaki dugu. Kubernetes aukeratzeko arrazoiak hauek dira:

1. **Eskalagarritasuna:**  Kubernetes-en diseinu bereziak ezin hobea da aplikazioak eskalatzeko, eta denboran zehar gure eskalagarritasun-eskakizunak eboluzionatzen duten heinean, Kubernetes-ek aldaketa horiei arazorik gabe erantzuteko gaitasun integratua du.

2. **Arkitektura deszentralizatua:**  Kubernetes-en master-worker topologiak arkitektura deszentralizatua bermatzen du, eta horrek huts-puntu bakarrik ez dagoela ziurtatzen du.

3. **Komunitatearen laguntza:**  Kubernetes-ek kode irekiko komunitate handiena eta aktiboena du, eta horrek esan nahi du laguntzaile, garatzaile eta hornitzaile kopuru handia duela, guretzat laguntza lortzea eta baliabideak aurkitzea errazten duena.

4. **Ekosistemaren laguntza:**  Kubernetes-ek ekosistema hazkorra du hirugarrenen hainbat tresnarekin, ontzi-erregistroekin, CI/CD hodiekin, datu-biltegiratzearekin eta gehiagorekin integrazioak dituena.

Beraz, Kubernetes gure ontzi-orkestrazio plataforma gisa hartzea erabaki dugu orain eta etorkizun hurbilerako.
