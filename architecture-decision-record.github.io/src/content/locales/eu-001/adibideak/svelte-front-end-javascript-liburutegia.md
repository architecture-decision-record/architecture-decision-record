# Arkitektura-erabakien erregistroa: Svelte front-end JavaScript liburutegia

Egoera: Onartua

## Testuingurua

Web aplikazio bat garatzen ari gara front-end JavaScript esparru modernoa erabiliz. Arina, azkarra eta erabiltzeko erraza den liburutegi bat aukeratu nahi dugu. Hainbat liburutegi ebaluatu ditugu, React, Vue eta Angular barne. Svelte-ri buruz ere entzun dugu, esparru arin mota berria dela aldarrikatzen duena. Svelte ebaluatu eta erabaki behar dugu gure aplikaziorako egokia den.

## Erabakia

Liburutegi bakoitzaren alde onak eta txarrak kontuan hartu ondoren, Svelte gure front-end JavaScript liburutegi gisa erabiltzea erabaki dugu arrazoi hauengatik:

1. **Arina:**  Svelte eskuragarri dauden liburutegirik arinenetako bat da, eta horrek gure aplikazioaren tamaina txikian mantentzen eta orrien karga-denborak hobetzen lagunduko digu.

2. **Azkarra:**  Svelte bere errendatze-abiadura azkarragatik ezaguna da, eta horrek gure aplikazioa erantzunkor eta bizkor sentiarazi egingo du.

3. **Erabiltzeko erraza:**  Svelte-ren sintaxia sinplea eta ulertzeko erraza da, eta horrek gure taldeak hura hartzea eta kode garbia idaztea errazago egingo du.

4. **UI errendatzeko optimizatua:**  Svelte UI osagaiak errendatzeko optimizatuta dago, eta horrek UI elementu dinamiko eta berrerabilgarriak sortzea errazten digu.

5. **Dokumentazio eta komunitate-laguntza ona:**  Svelte-k komunitate hazkorra eta dokumentazio ona du, eta horrek azkar hasten eta sortzen den edozein arazo konpontzen lagunduko digu.

## Alternatibak

React, Vue eta Angular aztertu ditugu, baina arrazoi hauengatik baztertu ditugu:

1. **React:**  React-ek erabiltzaile-oinarri handia eta liburutegi eta baliabide ugari dituen arren, konplexua eta ikasteko zaila izan daiteke, bereziki hasiberrientzat.

2. **Vue:**  Vue ikasteko eta erabiltzeko erraza den liburutegi arina da, baina baliteke Svelte bezain azkarra edo optimizatua ez izatea.

3. **Angular:**  Angular ezaugarri eta tresna asko eskaintzen dituen esparru osoa da, baina astuna eta konplexua izan daiteke, eta Svelte baino mantentze-lan gehiago behar izan dezake.

## Ondorioak

Svelte gure front-end JavaScript liburutegi gisa erabiltzeak ondorio hauek izango ditu:

1. Gure aplikazioa arina eta azkarra izango da, eta horrek erabiltzaile-esperientzia eta inplikazioa hobetuko ditu.

2. Gure taldeak liburutegi berri bat ikasi beharko du, baina Svelte-ren sintaxia sinplea eta ulertzeko erraza denez, ikaskuntza-kurba kudeagarria izan beharko litzateke.

3. Svelte oraindik liburutegi nahiko berria da, beraz baliteke ondo dokumentatuta ez dauden edo komunitateak onartzen ez dituen arazo batzuk aurkitzea.

4. Svelte erabiltzaileen komunitatea hazten ari da, beraz baliteke etorkizunean hirugarrenen liburutegi eta baliabide gehiago eskuragarri egotea, liburutegi nagusia osatzeko erabil daitezkeenak.

## Ondorioa

Gure ebaluazioan oinarrituta, Svelte gure web aplikaziorako front-end JavaScript liburutegi gisa erabiltzea erabaki dugu. Uste dugu Svelte-ren izaera arinak eta azkarrak, erabiltzeko erraztasunak eta UI errendatze optimizatuak gure beharretarako aukerarik onena bihurtzen dutela. Svelte-ren eta bere komunitatearen garapena monitorizatzen jarraituko dugu eta behar izanez gero gure aukera aldatuko dugu.
