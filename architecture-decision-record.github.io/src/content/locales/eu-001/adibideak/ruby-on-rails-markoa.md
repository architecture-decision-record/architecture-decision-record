# Arkitektura-erabakien erregistroa: Ruby on Rails markoa

## Testuingurua

- Erakundea negozio-logika konplexua eta hirugarren zerbitzuekin integrazio anitz dituen web aplikazio bat garatzen ari da.

- Taldeak Ruby on Rails-ekin web aplikazioak eraikitzeko esperientzia du.

- Garapen azkarra, eskalagarritasuna eta mantentzeko gaitasuna sustatzen dituen web marko bat aukeratu behar da.

## Erabakia

- Ruby on Rails erabili web aplikazioa garatzeko marko gisa.

## Justifikazioa

- Ruby on Rails web marko heldu, egonkor eta zabal hartua da, web aplikazio konplexuak eraikitzeko bere eraginkortasuna frogatu duena.

- Markoak Model-View-Controller (MVC) arkitektura-eredua jarraitzen du, kezken bereizketa sustatzen duena eta kodearen berrerabilgarritasuna eta mantentzeko gaitasuna hobetzen dituena.

- Rails-ek ezaugarri integratu asko eskaintzen ditu, hala nola ActiveRecord datu-baseko elkarreraginetarako eta ActionMailer posta elektronikoaren kudeaketarako, garapen-denbora aurrezten eta kodea sinplifikatzen dutenak.

- Markoak komunitate handi eta aktiboa du, funtzionalitatea hobetzeko eta arazo arruntak konpontzeko modulu eta plugin berrerabilgarri asko eskuragarri dituena.

- Ruby on Rails-ek Test-Driven Development (TDD) eta Behavior-Driven Development (BDD) onartzen ditu, garatzaileei beren kodearentzat proba automatizatuak idazteko aukera emanez, espero bezala funtzionatzen duela ziurtatuz eta akatsak eta erregresioak murriztuz.

- Ruby goi-mailako lengoaia da, garatzailearen produktibitatea eta kodearen irakurgarritasuna sustatzen dituena, eta hirugarren zerbitzu eta API sorta zabalarekin integratzeko kola-lengoaia ahaltsua dena.

## Ondorioak

- Taldeak ziurtatu behar du web aplikazioaren arkitektura eta diseinua Rails-en konbentzioak eta jardunbide onak jarraitzen dituela, markoaren onurak maximizatzeko.

- Garatzaileek Ruby lengoaia eta Rails marko ondo ulertu behar dituzte, nahiz eta Rails-en dokumentazioak eta komunitateak orientazioa eta laguntza eman ditzaketen.

- Ruby eta Rails-en berriak diren garatzaileentzat ikaskuntza-kurba bat egon daiteke, nahiz eta markoaren onurek prestakuntza eta onboarding-ean inbertitzea justifika dezaketen.

- Taldeak aplikazioaren errendimendua eta eskalagarritasuna monitorizatu behar du, eta baliteke datu-baseko kontsultak fintzea eta cache-a optimizatzea datu eta trafiko kopuru handiak kudeatzeko.
