## சுருக்கம்


### சிக்கல்

நேரமுத்திரைகளையும், எங்கள் அனைத்து அமைப்புகள் மற்றும் மூன்றாம் தரப்பு அமைப்புகள் முழுவதும் நன்றாக வேலை செய்யும் சீரான நேரமுத்திரை வடிவத்தையும் பயன்படுத்தி, விஷயங்கள் எப்போது நடக்கின்றன என்பதைக் கண்காணிக்க விரும்புகிறோம்.

வெவ்வேறு நேரமுத்திரை வடிவங்களைக் கொண்ட அமைப்புகளுடன் நாங்கள் தொடர்பு கொள்கிறோம்:

* JSON செய்திகளுக்கு உள்ளார்ந்த நேரமுத்திரை வடிவம் இல்லை, எனவே ஒரு நேரமுத்திரையை சரமாக எவ்வாறு மாற்றுவது, சரத்தை நேரமுத்திரையாக எவ்வாறு மாற்றுவது, அதாவது எவ்வாறு serialize/deserialize செய்வது என்பதை நாங்கள் தேர்ந்தெடுக்க வேண்டும்.

* சில பயன்பாடுகள் UTC நேரத்துக்குப் பதிலாக உள்ளூர் நேரத்தைப் பயன்படுத்துமாறு அமைக்கப்பட்டுள்ளன. உள்ளூர் நேரத்தை அடிப்படையாகக் கொண்ட நிகழ்வுகளைத் தூண்டும் திட்டங்கள் போன்ற உள்ளூர் நேரத்துக்கு ஏற்ப சரிசெய்ய வேண்டிய திட்டங்களுக்கு இது வசதியாக இருக்கலாம்.

* சில அமைப்புகள் வினாடிகள், மில்லிவினாடிகள், நானோவினாடிகள் போன்ற நேரத் தெளிவுத்திறனைப் பயன்படுத்துவது போன்ற வெவ்வேறு நேரத் துல்லியத் தேவைகளையும் திறன்களையும் கொண்டுள்ளன. எடுத்துக்காட்டாக, Linux இயக்க முறைமையின் `date` கட்டளை இயல்புநிலை நேரத் துல்லியமாக வினாடிகளைப் பயன்படுத்துகிறது, அதேசமயம் Nasdaq பங்குச் சந்தை இயல்புநிலை நேரத் துல்லியமாக நானோவினாடிகளை விரும்புகிறது.


### முடிவு

நானோவினாடித் துல்லியத்துடன் ISO 8601 தரநிலை நேரமுத்திரை வடிவத்தைத் தேர்ந்தெடுக்கிறோம், குறிப்பாக "YYYY-MM-DDTHH:MM:SS.NNNNNNNNNZ".

இந்த வடிவம் ஆண்டு, மாதம், நாள், மணி, நிமிடம், வினாடி, நானோவினாடிகள், Zulu நேர மண்டலம் அதாவது UTC, GMT ஆகியவற்றைக் காட்டுகிறது.


### நிலை

முடிவு செய்யப்பட்டது.


## விவரங்கள்


### அனுமானங்கள்

ஒரு நேரமுத்திரையிலிருந்து சரமாக மாற்ற (அதாவது serialize) மற்றும் சரத்திலிருந்து நேரமுத்திரையாக மாற்ற (அதாவது deserialize) இந்த நேரமுத்திரை உரைச் சரங்களை நாங்கள் கையாள வேண்டும்.

பொதுவாகப் பயன்படுத்த எளிதான, மாற்ற எளிதான, ஒரு நபர் படிக்க எளிதான வடிவத்தை நாங்கள் விரும்புகிறோம்.

பகுப்பாய்வு அமைப்புகள், தரவுத்தள அமைப்புகள், நிதி அமைப்புகள் போன்ற, எங்களால் கட்டுப்படுத்த முடியாத பரந்த வெளிப்புற அமைப்புகளுடன் இணக்கத்தன்மையை நாங்கள் விரும்புகிறோம்.


### கட்டுப்பாடுகள்

சில அமைப்புகளுக்கு நேரத் துல்லிய வரம்புகள் உள்ளன. எடுத்துக்காட்டாக, macOS இயக்க முறைமையின் `date` கட்டளை வினாடிகளில் நேரத் துல்லியத்தை அச்சிட முடியும், ஆனால் நானோவினாடிகளில் இல்லை.


### நிலைப்பாடுகள்

விருப்பங்களின் வரம்பைப் பரிசீலித்தோம்:

* Unix epoch அதாவது ஒரு அதிகரிக்கும் எண்.

* சுருக்கமான உரை வடிவம் "YYYYMMDDTHHMMSSNNNNNNNNN".

* உள்ளூர் நேர மண்டலம் மற்றும் UTC நேர மண்டலத்தைப் பயன்படுத்துதல்.


### வாதம்

வழக்கமான பயன்பாட்டிற்கு, மூல வேகம்/அளவை விட மனிதர்கள் படிக்க/எழுத எளிதாக இருப்பதை மதிக்கிறோம்.

வழக்கமான பயன்பாட்டிற்கு, இயந்திர அமைப்புகளில் நன்றாக வேலை செய்யும், மாதிரித் தரவு எழுதுதல், JSON வெளியீட்டைப் படித்தல், log கோப்பை grep செய்தல் போன்ற கைமுறையிலும் நன்றாக வேலை செய்யும் வடிவத்தை விரும்புகிறோம்.

உயர் செயல்திறன் கணினி போன்ற வழக்கத்திற்கு மாறான பயன்பாட்டிற்கு, நாங்கள் தேர்ந்தெடுக்கும் எந்த உரை வடிவத்தையும் நிரலாக்க மொழியின் உள்ளமைந்த தேதிப் பொருள் வகை போன்ற வேகமான வடிவத்துக்கு உரையை மாற்றுவதன் மூலம் உகந்ததாக்க விரும்புவோம் என எதிர்பார்க்கிறோம். எனவே HPC க்கு உரை வடிவம் அவ்வளவு முக்கியமில்லை.


### தாக்கங்கள்

எங்கள் பல்வேறு உரை அமைப்புகளும் நேர அமைப்புகளும் இந்த வடிவத்தில் ஒருங்கிணையும்.


## தொடர்புடையவை


### தொடர்புடைய முடிவுகள்

கால அளவுகளையும் கண்காணிக்க வேகமான/எளிய வழியையும் நாங்கள் விரும்பலாம். Unix epoch நேரமுத்திரைகளுடன் இவை எளிது.


### தொடர்புடைய தேவைகள்

எ.கா. Splunk, Sumo, ELK போன்றவற்றுக்கான குறிப்பிட்ட வகை log செய்தி முத்திரைக்கான தொடர்புடைய தேவை இருந்தால் எங்கள் முடிவை சரிசெய்ய விரும்பலாம்.


### தொடர்புடைய படைப்புகள்

மொழி வடிவமைப்பாளர்கள் மற்றும் பகுப்பாய்விகள்:

  * [date-fns: Modern JavaScript date utility library](https://date-fns.org/)
  * [Crono: date and time library for Rust](https://github.com/chronotope/chron)
  
Rosetta Code எடுத்துக்காட்டுகள்:

  * [System time](https://www.rosettacode.org/wiki/System_time)
  * [Data format](https://www.rosettacode.org/wiki/Date_format)
  * [Show the epoch](https://www.rosettacode.org/wiki/Show_the_epoch)

SixArm எடுத்துக்காட்டுகள்:

  * [now_string](https://github.com/SixArm/rosetta_code/tree/master/tasks/now_string)


### தொடர்புடைய கொள்கைகள்

எளிதில் மாற்றியமைக்கக்கூடியது. Unix epoch போன்ற வேறு வடிவத்துக்கு நாங்கள் மிக எளிதாக மாற முடியும்.

முன்கூட்டிய உகந்ததாக்கலைத் தள்ளிவைக்கவும். வழக்கமான பயன்பாட்டிற்கு, இடைக்கோடுகளையும் முக்காற்புள்ளிகளையும் பயன்படுத்தும் வடிவம் போன்ற சில கூடுதல் எழுத்துகளைப் பற்றி நாங்கள் அதிகம் கவலைப்படுவதில்லை.
