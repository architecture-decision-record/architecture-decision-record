## கட்டமைப்பு முடிவு பதிவு: E2E சோதனைக்கான உலாவி தானியக்கம் (Playwright அல்லது Selenium)

### 1. **சூழல்**

எங்கள் முனை-முதல்-முனை (E2E) சோதனைப் பைப்லைனுக்கான உலாவி தானியக்கக் கட்டமைப்பைத் தேர்ந்தெடுக்கும் செயல்முறையில் உள்ளோம். இந்தக் கட்டமைப்பு எங்கள் CI/CD செயல்முறைகளின் ஒருங்கிணைந்த பகுதியாக இருக்கும், எங்கள் தளத்தில் உண்மையான பயனர் தொடர்புகளைப் பிரதிபலிக்கும் சோதனைகளை இயக்கும். குறிப்பாக, சோதனைகள் பயனர் பதிவு/உள்நுழைவு, கோப்புப் பதிவேற்றங்கள், டாஷ்போர்டு தொடர்புகள், அறிக்கைப் பதிவிறக்கங்கள் போன்ற காட்சிகளை உள்ளடக்கும்.

**புதிய நிறுவனமாக**, எங்கள் கவனம் **சுறுசுறுப்பான மேம்பாட்டில்** உள்ளது, விரைவான மீள்செயல் மற்றும் பரிணாமம் தேவை. எங்கள் குழு பெரும்பாலும் **TypeScript** மற்றும் **Python** உடன் வேலை செய்கிறது, இந்த மொழிகளில் சோதனைகளை எழுதும் திறன் அத்தியாவசியம். கூடுதலாக, தளத்தில் **ஊடாடும் விளக்கப்படங்களும் டாஷ்போர்டுகளும்** உள்ளன, இதனால் தானியக்கக் கருவி வளமான, இயங்குநிலை UI களை நன்றாக ஆதரிப்பது மிக முக்கியம்.

இந்தப் பணிக்கான இரண்டு போட்டியாளர்கள் **Playwright** மற்றும் **Selenium**, ஒவ்வொன்றுக்கும் அதன் சொந்த பலங்களும் சமரசங்களும் உள்ளன. கீழே குறிப்பிடப்பட்டுள்ள அம்சங்கள் மற்றும் தேவைகளின் அடிப்படையில் இந்தக் கட்டமைப்புகளை மதிப்பிட வேண்டும்.

### 2. **பரிசீலிக்கப்பட்ட விருப்பங்கள்**

- **Playwright** (Microsoft இன்)
- **Selenium** (Selenium திட்டத்தின்)

### 3. **முடிவுக்கான உந்து காரணிகள்**

எங்கள் முடிவைப் பாதிக்கும் காரணிகள் பின்வருமாறு:

1. **சுறுசுறுப்பான மேம்பாடு**: தேர்ந்தெடுக்கப்பட்ட கருவி வேகமான, நெகிழ்வான மேம்பாட்டுச் சுழற்சிகளை செயல்படுத்த வேண்டும்.
2. **மொழி ஆதரவு**: எங்கள் குழுவுக்கு **TypeScript** மற்றும் **Python** இரண்டுக்கும் ஆதரவு தேவை.
3. **ஊடாடும் UI சோதனை**: ஊடாடும் விளக்கப்படங்கள், டாஷ்போர்டுகள், இயங்குநிலைக் கூறுகளை நம்பகமாகச் சோதிக்கும் திறன் அத்தியாவசியம்.
4. **இயக்கநேர வேகம்**: முதன்மைக் கவலை இல்லையென்றாலும், CI/CD பைப்லைன்களில் செயல்திறன் ஒரு பரிசீலனை.
5. **அளவிடுதிறன்**: உடனடி எதிர்காலத்தில் பாரிய அளவிடுதலைத் திட்டமிடவில்லை, ஆனால் தீர்வு எதிர்கால வளர்ச்சியைக் கையாள முடியும் என்பதை உறுதிசெய்ய விரும்புகிறோம்.
6. **பின்னோக்கிய இணக்கத்தன்மை**: பழைய அமைப்புகளும் பழைய உலாவிகளுடன் இணக்கத்தன்மையும் தற்போது எங்கள் திட்டத்துக்கு முக்கியமல்ல.
7. **கைபேசிச் சோதனை**: உடனடி கவனம் இல்லையென்றாலும், கட்டமைப்பு கைபேசிக்கு-துலங்கும் அம்சங்களைச் சோதிக்கும் திறன் கொண்டிருக்க வேண்டும் அல்லது அத்தகைய பயன்பாடுகளுக்கு விரிவாக்கக்கூடியதாக இருக்க வேண்டும்.
8. **பல-திரைச் சோதனை**: பல-திரை உள்ளமைவுகளுக்கான ஆதரவு இரண்டாம் நிலைத் தேவை, குறிப்பாக மிகவும் சிக்கலான பயனர் பணிப்பாய்வுகளைச் சோதிக்கும் அளவுக்கு எப்போதாவது அளவிட்டால்.
9. **கோப்புப் பதிவேற்றச் சோதனை**: கட்டமைப்பு கோப்புப் பதிவேற்றங்களைத் திறமையாகக் கையாள வேண்டும், இது எங்கள் சோதனைத் தேவைகளின் முக்கியத் தேவை.

### 4. **மதிப்பீட்டு அளவுகோல்கள்**

- **பயன்பாட்டு எளிமை**: சோதனைகளை எழுதவும் பராமரிக்கவும் எவ்வளவு எளிது?
- **மொழி ஆதரவு**: எங்கள் குழு மிகவும் அடிக்கடி பயன்படுத்தும் இரண்டு மொழிகளான TypeScript மற்றும் Python ஐ கட்டமைப்பு ஆதரிக்கிறதா?
- **ஊடாடும் UI சோதனை**: விளக்கப்படங்கள், கோப்புப் பதிவேற்றங்கள், இயங்குநிலைத் தரவு போன்ற சிக்கலான ஊடாடும் பயனர் இடைமுகங்களை கட்டமைப்பு எவ்வளவு நன்றாகக் கையாள்கிறது?
- **CI/CD ஒருங்கிணைப்பு**: பொதுவான CI/CD கருவிகள் மற்றும் சேவைகளுடன் கட்டமைப்பு எவ்வளவு நன்றாக ஒருங்கிணைகிறது?
- **குறுக்கு-உலாவி ஆதரவு**: எந்த உலாவிகள் ஆதரிக்கப்படுகின்றன, அவை எவ்வளவு நன்றாகச் செயல்படுகின்றன?
- **செயல்திறனும் வேகமும்**: குறிப்பாக CI/CD பைப்லைனில் சோதனைகள் எவ்வளவு விரைவாக இயங்குகின்றன?
- **அளவிடுதிறன்**: மேலும் சோதனைகள் அல்லது மிகவும் சிக்கலான காட்சிகள் சேர்க்கப்பட்டால் கட்டமைப்பு எவ்வளவு நன்றாக அளவிட முடியும்?
- **சமூகமும் சூழல்மண்டலமும்**: கட்டமைப்பின் சமூகம் எவ்வளவு செயலில் உள்ளது? ஏராளமான ஒருங்கிணைப்புகளும் நீட்டிப்புகளும் கிடைக்கின்றனவா?

### 5. **பரிசீலனைகள்**

#### 5.1 **Playwright**

##### **நன்மைகள்**:
1. **உள்ளூர்க் கோப்புப் பதிவேற்றங்களுக்கு புத்திசாலியான API**: உள்ளூர்க் கோப்புகளுடன் தொடர்புகொள்வதற்கும் கோப்புப் பதிவேற்றங்களைச் செய்வதற்கும் Playwright இன் API எளிமையானது, உள்ளுணர்வு மிக்கது. இது கோப்புப் பதிவேற்றச் சோதனையை நடைமுறைப்படுத்தவும் பராமரிக்கவும் எளிதாக்கும்.
2. **தொடரியலும் குறியீட்டு உருவாக்கமும்**: Playwright க்கு குறுகிய, மிகவும் சுருக்கமான தொடரியல் உள்ளது. இது குறைவான boilerplate குறியீட்டில் விளைகிறது, இது பராமரிப்புத்திறனையும் உருவாக்குநர் செயல்திறனையும் மேம்படுத்துகிறது. கூடுதலாக, இந்தக் குறுகிய தொடரியல் OpenAI குறியீடு உருவாக்கத்தின் தரத்தை மேம்படுத்துகிறது, சோதனை ஸ்கிரிப்ட்களைத் தானாக உருவாக்குவதை எளிதாக்குகிறது.
3. **ஊடாடும் UI சோதனை**: வளமான விளக்கப்படங்கள், சிக்கலான பயனர் தொடர்புகள், நிகழ்நேரப் புதுப்பிப்புகள் கொண்டவை போன்ற இயங்குநிலை, ஊடாடும் வலைப் பயன்பாடுகளைச் சோதிப்பதில் Playwright சிறந்து விளங்குகிறது. இது WebSockets, WebRTC, shadow DOM கள், பிற நவீன வலைத் தொழில்நுட்பங்களை மிகத் திறம்படக் கையாள்கிறது.
4. **குறுக்கு-உலாவி ஆதரவு**: Playwright **Chromium**, **WebKit**, **Firefox** ஐ ஆதரிக்கிறது. இந்த உலாவிகளில் இதற்குச் சீரான செயல்திறன் உள்ளது, இது எங்கள் பெரும்பாலான சோதனைத் தேவைகளை உள்ளடக்க வேண்டும்.
5. **CI/CD ஒருங்கிணைப்பு**: Playwright நவீன CI/CD தளங்களுடன் (GitHub Actions, Jenkins, போன்றவை) தடையின்றி ஒருங்கிணைகிறது. இது வெவ்வேறு உலாவிகளில் சோதனைகளை இணையாக இயக்க முடியும், சோதனை இயக்க நேரங்களை உகந்ததாக்கி விரைவான மேம்பாட்டுக்கு ஏற்றதாக்குகிறது.
6. **வேகமானதும் நம்பகமானதும்**: Playwright பொதுவாக Selenium ஐ விட வேகமானது, குறிப்பாக headless பயன்முறையில், ஒத்திசைவற்ற வலைக் கூறுகளைக் கையாளும்போது அதிக நெகிழ்வுத்தன்மை கொண்டது.

##### **தீமைகள்**:
1. **வரையறுக்கப்பட்ட கைபேசிச் சோதனை**: Playwright உலாவிகளுக்கான கைபேசி எமுலேஷனை ஆதரித்தாலும், உண்மையான கைபேசிச் சோதனைக்கு Selenium இன் Appium உடனான ஒருங்கிணைப்பு போன்ற நேட்டிவ் கைபேசிச் சோதனைத் திறன்கள் இதில் இல்லை.
2. **சிறிய சூழல்மண்டலம்**: Playwright இன்னும் புதியது, Selenium ஐ விடக் குறைவாக நிறுவப்பட்டது. வேகமாக வளர்ந்து வரும் சமூகமும் நல்ல ஆவணங்களும் இருந்தாலும், Selenium வழங்கும் செருகுநிரல்கள் மற்றும் ஒருங்கிணைப்புகளின் பரந்த சூழல்மண்டலம் இதில் இன்னும் இல்லாமல் இருக்கலாம்.
3. **வரையறுக்கப்பட்ட உலாவி ஆதரவு**: Playwright முக்கிய நவீன உலாவிகளை (Chrome, Safari, Firefox) உள்ளடக்கினாலும், பழைய உலாவிகளுக்கான (எ.கா. Internet Explorer) அதன் ஆதரவு Selenium ஐப் போல வலுவாக இல்லை.

#### 5.2 **Selenium**

##### **நன்மைகள்**:
1. **நீண்ட வரலாறும் முதிர்ச்சியும்**: Selenium நீண்ட காலமாக உள்ளது, நிரூபிக்கப்பட்ட சாதனைப் பதிவைக் கொண்டுள்ளது. இது பல குழுக்களிலும் தொழில்களிலும் பரவலாகப் பயன்படுத்தப்படுகிறது, இது செருகுநிரல்கள், ஒருங்கிணைப்புகள், வளங்களின் பரந்த சூழல்மண்டலத்துக்கு வழிவகுத்துள்ளது.
2. **குறுக்கு-உலாவி மற்றும் குறுக்கு-தள ஆதரவு**: Selenium **Internet Explorer** உட்பட **பலவகை உலாவிகளையும் பதிப்புகளையும்** ஆதரிக்கிறது, மேலும் பகிரப்பட்ட சோதனைக்கு **Docker**, **Selenium Grid**, **கிளவுட் சேவைகள்** போன்ற பல்வேறு கருவிகளுடன் ஒருங்கிணைக்கலாம்.
3. **கைபேசிச் சோதனை**: Selenium, **Appium** உடனான ஒருங்கிணைப்பு மூலம், Android மற்றும் iOS பயன்பாடுகள் இரண்டையும் உள்ளடக்கிய கைபேசிச் சோதனைக்கு மிகவும் வலுவானது. இது கைபேசி-முதல் அல்லது கைபேசி-அதிகம் கொண்ட திட்டங்களுக்குச் சிறந்த தேர்வாக்குகிறது.
4. **பல-திரைச் சோதனை**: Selenium **பல திரைகள்** அல்லது சிக்கலான பல-சாளரத் தொடர்புகளை உள்ளடக்கிய காட்சிகளுக்குச் சிறந்த ஆதரவை வழங்குகிறது.

##### **தீமைகள்**:
1. **சிக்கல்**: Selenium இன் API மிகவும் சொல்வளமுள்ளது, வெளிப்படையானது. சில சந்தர்ப்பங்களில் இது நன்மையாக இருக்கலாம் என்றாலும், இது எழுதவும் பராமரிக்கவும் அதிகக் குறியீட்டைக் குறிக்கிறது, இது உருவாக்குநர் சுறுசுறுப்பைக் குறைக்கலாம்—குறிப்பாகப் புதிய நிறுவனச் சூழலில் முக்கியம்.
2. **செயல்திறன்**: Selenium பொதுவாக Playwright ஐ விட மெதுவாக இயங்குகிறது, குறிப்பாக headless பயன்முறையில். இது CI/CD பைப்லைன்களைப் பாதிக்கலாம், குறிப்பாகச் சோதனைகளின் எண்ணிக்கை வளரும்போது.
3. **ஊடாடும் UI சோதனை**: நவீன, ஊடாடும் வலை UI களைச் சோதிக்கும்போது, குறிப்பாக விளக்கப்படங்கள் மற்றும் நிகழ்நேரத் தரவுப் புதுப்பிப்புகளுடன், Selenium Playwright ஐப் போல சீராக இல்லை. இயங்குநிலை உள்ளடக்கத்துடன் நம்பகமாகத் தொடர்புகொள்ள அதிக அமைவும் கையாளுதலும் தேவை.

### 7. **முடிவு**

தேவைகளையும் சமரசங்களையும் பரிசீலித்த பிறகு, எங்கள் தற்போதைய தேவைகளுக்கு **Playwright** சிறந்த தேர்வு. உள்ளூர்க் கோப்புப் பதிவேற்றச் சோதனைக்கான அதன் புத்திசாலியான API, சுருக்கமான தொடரியல், ஊடாடும் UI சோதனைக்கான வலுவான ஆதரவு ஆகியவை எங்கள் சுறுசுறுப்பான மேம்பாட்டுச் சுழற்சிக்கு அதை ஒரு சிறந்த பொருத்தமாக்குகின்றன. இது **TypeScript** மற்றும் **Python** இரண்டையும் ஆதரிப்பது எங்கள் குழுவுக்கு முக்கியமானது, சோதனைக்கான கட்டமைப்பின் நவீன அணுகுமுறை தூய்மையான, பராமரிக்கக்கூடிய குறியீட்டை எழுத எங்களை அனுமதிக்கும்.

**Selenium** குறிப்பாகக் கைபேசிச் சோதனை, பழைய உலாவி ஆதரவு, பல-திரை அமைவுகளுக்கு ஒரு சிறந்த கருவியாகவே தொடர்ந்தாலும், எங்கள் தற்போதைய தேவைகளுக்கு அது குறைவாகவே ஏற்றது. அதன் சொல்வளம், மெதுவான செயல்திறன், விளக்கப்படங்கள் போன்ற இயங்குநிலை UI களின் சிக்கலான கையாளுதல் எங்கள் பயன்பாட்டிற்கு அதைக் குறைந்த உகந்ததாக்குகின்றன.

### 8. **விளைவுகள்**

- **உடனடி நடவடிக்கை**: பதிவு, உள்நுழைவு, கோப்புப் பதிவேற்றங்கள், டாஷ்போர்டுகள், அறிக்கைப் பதிவிறக்கங்களை உள்ளடக்கிய பயனர் ஓட்டங்களைச் சோதிப்பதில் கவனம் செலுத்தி, எங்கள் E2E சோதனைக்கு **Playwright** ஐ ஏற்போம்.
- **நீண்டகாலப் பரிசீலனைகள்**: வளர்ந்து வரும் Playwright சூழல்மண்டலத்தை நாங்கள் கண்காணிப்போம். எங்கள் தேவைகள் மாறினால், குறிப்பாகக் கைபேசிச் சோதனை அல்லது பழைய உலாவிகளுக்கான ஆதரவு குறித்து, Selenium ஐ மீண்டும் பார்வையிடலாம்.
- **பயிற்சியும் ஆவணப்படுத்தலும்**: மேம்பாட்டுக் குழுக்கள் Playwright இன் API உடன், குறிப்பாக இயங்குநிலை UI களையும் கோப்புப் பதிவேற்றங்களையும் கையாள்வதற்கு, பரிச்சயம் பெற வேண்டும்.
- **இடம்பெயர்தல்**: இருக்கும் Selenium சோதனைகள் (இருந்தால்) படிப்படியாக Playwright க்கு இடம்பெயர்க்கப்படும்.
