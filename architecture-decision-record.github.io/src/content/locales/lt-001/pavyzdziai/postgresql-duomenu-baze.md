# Architektūros sprendimo įrašas: PostgreSQL duomenų bazė

Pavadinimas: PostgreSQL duomenų bazės naudojimas

## Kontekstas

Mūsų organizacija šiuo metu vertina galimybes pasirinkti tinkamiausią duomenų bazių valdymo sistemą būsimam projektui. Paiešką susiaurinome iki dviejų variantų – PostgreSQL ir MySQL. Kruopščiai apsvarstę, nusprendėme naudoti PostgreSQL dėl jos pažangių funkcijų ir našumo galimybių.

## Sprendimas

Savo organizacijos būsimam projektui kaip pageidaujamą duomenų bazių valdymo sistemą naudosime PostgreSQL.

## Pagrindimas

Išanalizavę ir palyginę tiek PostgreSQL, tiek MySQL funkcijas, priėjome išvados, kad PostgreSQL yra geresnis variantas dėl šių priežasčių:

1. **Pažangios funkcijos:**  PostgreSQL turi daug pažangių funkcijų, tokių kaip JSON palaikymas, pilno teksto paieška ir erdvinių duomenų valdymas, kurios yra būtinos mūsų projektui.

2. **Našumas:**  PostgreSQL turi įrodytą puikių našumo galimybių istoriją, kuri užtikrins, kad mūsų projektas veiktų sklandžiai be jokių našumo problemų.

3. **Bendruomenės parama:**  PostgreSQL turi didelę ir aktyvią bendruomenę, teikiančią reguliarius atnaujinimus ir paramą, todėl lengviau išspręsti bet kokias projekto kūrimo etape iškilusias problemas.

4. **Mastelio keitimas:**  PostgreSQL labai gerai keičia mastelį ir lengvai gali tvarkyti didelius duomenų kiekius, o tai bus būtina mūsų projektui.

5. **Saugumas:**  PostgreSQL turi tvirtą saugumo mechanizmą, kuris užtikrins, kad mūsų projekto duomenys visada būtų saugūs, ir jis atitinka visus mūsų organizacijos saugumo reikalavimus.

## Alternatyvos

Kitas svarstytas variantas buvo MySQL. MySQL taip pat yra labai pajėgi duomenų bazių valdymo sistema, bet jai trūksta kai kurių pažangių funkcijų, kurias siūlo PostgreSQL, o jos našumo talpa nėra tokia gera kaip PostgreSQL.
