# Architektūros sprendimo įrašas: Svelte priekinės dalies JavaScript biblioteka

Būsena: priimtas

## Kontekstas

Kuriame interneto programą naudodami šiuolaikinį priekinės dalies JavaScript karkasą. Norime pasirinkti biblioteką, kuri būtų lengva, greita ir paprasta naudoti. Įvertinome kelias bibliotekas, įskaitant React, Vue ir Angular. Taip pat girdėjome apie Svelte, kuri teigia esanti naujo tipo lengvas karkasas. Turime įvertinti Svelte ir nuspręsti, ar ji tinka mūsų programai.

## Sprendimas

Apsvarstę kiekvienos bibliotekos privalumus ir trūkumus, nusprendėme kaip savo priekinės dalies JavaScript biblioteką naudoti Svelte dėl šių priežasčių:

1. **Lengva:**  Svelte yra viena lengviausių turimų bibliotekų, o tai padės išlaikyti mūsų programos dydį mažą ir pagerinti puslapių įkėlimo laiką.

2. **Greita:**  Svelte žinoma dėl greito atvaizdavimo, todėl mūsų programa atrodys greitai reaguojanti ir sklandi.

3. **Paprasta naudoti:**  Svelte sintaksė paprasta ir lengvai suprantama, todėl mūsų komandai bus lengviau ją perimti ir rašyti švarų kodą.

4. **Optimizuota UI atvaizdavimui:**  Svelte optimizuota UI komponentams atvaizduoti, todėl mums bus lengviau kurti dinamiškus ir pakartotinai naudojamus UI elementus.

5. **Gera dokumentacija ir bendruomenės parama:**  Svelte turi augančią bendruomenę ir gerą dokumentaciją, kurios padės mums greitai pradėti ir išspręsti iškilusias problemas.

## Alternatyvos

Svarstėme React, Vue ir Angular, bet jų atsisakėme dėl šių priežasčių:

1. **React:**  nors React turi didelę naudotojų bazę ir daugybę bibliotekų bei išteklių, ji gali būti sudėtinga ir sunkiai išmokstama, ypač pradedantiesiems.

2. **Vue:**  Vue yra lengva biblioteka, kurią lengva išmokti ir naudoti, bet ji gali būti ne tokia greita ar optimizuota kaip Svelte.

3. **Angular:**  Angular yra išsamus karkasas, siūlantis daug funkcijų ir įrankių, bet jis gali būti sunkus ir sudėtingas ir gali reikalauti daugiau priežiūros nei Svelte.

## Pasekmės

Naudojant Svelte kaip priekinės dalies JavaScript biblioteką, bus šios pasekmės:

1. Mūsų programa bus lengva ir greita, o tai pagerins naudotojo patirtį ir įsitraukimą.

2. Mūsų komandai reikės išmokti naują biblioteką, bet Svelte sintaksė paprasta ir lengvai suprantama, todėl mokymosi kreivė turėtų būti valdoma.

3. Svelte vis dar yra gana nauja biblioteka, todėl galime susidurti su problemomis, kurios nėra gerai dokumentuotos ar bendruomenės palaikomos.

4. Svelte naudotojų bendruomenė auga, todėl ateityje galime sulaukti daugiau trečiųjų šalių bibliotekų ir išteklių, kuriuos bus galima naudoti pagrindinei bibliotekai papildyti.

## Išvada

Remdamiesi savo vertinimu, nusprendėme savo interneto programos priekinės dalies JavaScript biblioteka naudoti Svelte. Manome, kad Svelte lengvumas ir greitis, paprastumas naudoti ir optimizuotas UI atvaizdavimas daro ją geriausiu pasirinkimu mūsų poreikiams. Toliau stebėsime Svelte ir jos bendruomenės raidą ir prireikus keisime savo pasirinkimą.
