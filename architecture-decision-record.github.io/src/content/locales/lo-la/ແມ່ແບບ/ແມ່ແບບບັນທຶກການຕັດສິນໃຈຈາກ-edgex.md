## ບໍລິບົດ

ອະທິບາຍ:

- ການອອກແບບມີນັຍສຳຄັນຕໍ່ສະຖາປັດຕະຍະກຳແນວໃດ - ຈຶ່ງຕ້ອງມີ ADR (ແທນທີ່ຈະເປັນພຽງ issue ແລະ PR ທຳມະດາເພື່ອແກ້ບັນຫາ)

- ແນວທາງການອອກແບບລະດັບສູງ (ລາຍລະອຽດຢູ່ໃນການອອກແບບທີ່ສະເໜີຂ້າງລຸ່ມ)


## ການອອກແບບທີ່ສະເໜີ

ລາຍລະອຽດຂອງການອອກແບບ (ໂດຍບໍ່ເຂົ້າສູ່ການປະຕິບັດ ເມື່ອເປັນໄປໄດ້).

ໂຄງຮ່າງ:

- ບໍລິການ/ໂມດູນທີ່ໄດ້ຮັບຜົນກະທົບ (ຖືກປ່ຽນແປງ)

- ບໍລິການ/ໂມດູນໃໝ່ທີ່ຈະເພີ່ມ

- ຜົນກະທົບຕໍ່ແບບຈຳລອງ ແລະ DTO (ການປ່ຽນແປງ/ການເພີ່ມ/ການລຶບ)

- ຜົນກະທົບຕໍ່ API (ການປ່ຽນແປງ/ການເພີ່ມ/ການລຶບ)

- ຜົນກະທົບຕໍ່ການຕັ້ງຄ່າທົ່ວໄປ (ການສ້າງພາກໃໝ່, ການປ່ຽນແປງ/ການເພີ່ມ/ການລຶບ)

- ຜົນກະທົບຕໍ່ devops


## ຂໍ້ພິຈາລະນາ

ບັນທຶກທາງເລືອກ, ຄວາມກັງວົນ, ປະເດັນເສີມ ຫຼື ປະເດັນທີ່ກ່ຽວຂ້ອງ, ແລະ ຄຳຖາມທີ່ເກີດຂຶ້ນໃນການໂຕ້ວາທີກ່ຽວກັບ ADR. 

ລະບຸວ່າພວກມັນຖືກແກ້ໄຂ ຫຼື ບັນເທົາແລ້ວຫຼືບໍ່ ແລະ ແນວໃດ.


## ການຕັດສິນໃຈ

ບັນທຶກລາຍລະອຽດການປະຕິບັດທີ່ສຳຄັນທີ່ຕົກລົງກັນ, ຂໍ້ຄວນລະວັງ, ຂໍ້ພິຈາລະນາໃນອະນາຄົດ, ປະເດັນການອອກແບບທີ່ເຫຼືອ ຫຼື ເລື່ອນໄວ້.

ບັນທຶກສ່ວນໃດຂອງຄວາມຕ້ອງການທີ່ການອອກແບບທີ່ສະເໜີບໍ່ໄດ້ຕອບສະໜອງ.
