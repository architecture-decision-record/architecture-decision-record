# Arhitektūras lēmuma ieraksts: Kubernetes konteineru orķestrēšana

## Problēmas formulējums 

Mums jāizvēlas konteineru orķestrēšanas platforma mūsu augošajam mākoņdabisko lietojumprogrammu portfelim. Mūsu pašreizējā mantotās platformas izvietošana ir pārāk lēna un nav pietiekami aģila, lai sekotu mūsu augošajām vajadzībām. Mēs meklējam sistēmu, kas ļaus mērogot mūsu pakalpojumus pēc iespējas efektīvākā veidā, nekompromitējot aģilitāti vai lietošanas vieglumu.

## Apsvērtās alternatīvas

1. Docker Swarm

2. Kubernetes

3. Apache Mesos

## Pieņemtais lēmums

Pēc rūpīgas katras konteineru orķestrēšanas platformas analīzes mēs nolēmām pieņemt Kubernetes kā labāko iespēju mūsu uzņēmuma vajadzībām. Mūsu iemesli Kubernetes izvēlei ir šādi:

1. **Mērogojamība:**  Kubernetes unikālais dizains ir ideāls lietojumprogrammu mērogošanai, un, mūsu prasībām attiecībā uz mērogojamību laika gaitā mainoties, Kubernetes ir iebūvēta spēja bez problēmām pielāgoties šīm izmaiņām.

2. **Decentralizēta arhitektūra:**  Kubernetes galvenais–darba mezgla (master-worker) topoloģija nodrošina decentralizētu arhitektūru, kas nodrošina, ka nav vienota atteices punkta.

3. **Kopienas atbalsts:**  Kubernetes ir lielākā un aktīvākā atvērtā pirmkoda kopiena, kas nozīmē, ka tai ir liels skaits līdzstrādnieku, izstrādātāju un piegādātāju, atvieglojot mums palīdzības iegūšanu un resursu atrašanu.

4. **Ekosistēmas atbalsts:**  Kubernetes ir augoša ekosistēma ar dažādiem trešo pušu rīkiem, integrācijām ar konteineru reģistriem, CI/CD cauruļvadiem, datu glabāšanu un citu.

Tāpēc mēs nolēmām pieņemt Kubernetes kā savu konteineru orķestrēšanas platformu tagadnei un tuvākajai nākotnei.
