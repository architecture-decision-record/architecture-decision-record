## ಬದಲಾವಣೆ ಲಾಗ್

ಸ್ಥಿತಿ, ದಿನಾಂಕ ಮತ್ತು PR URL ಸೇರಿದಂತೆ, ದಾಖಲೆಯ ಬದಲಾವಣೆಗಳನ್ನು ಪಟ್ಟಿ ಮಾಡಿ.

ಸ್ಥಿತಿ ಇವುಗಳಲ್ಲಿ ಒಂದು: pending, approved, amended, deprecated.

ದಿನಾಂಕ ISO 8601 (YYYY-MM-DD) ಸ್ಟ್ರಿಂಗ್ ಆಗಿರುತ್ತದೆ.

PR ಎಂದರೆ ಬದಲಾವಣೆಯನ್ನು ಸಲ್ಲಿಸಿದ ಪುಲ್ ರಿಕ್ವೆಸ್ಟ್; ಇದರಲ್ಲಿ ಡಿಫ್, ಕೊಡುಗೆದಾರರು ಮತ್ತು ಪರಿಶೀಲಕರಂತಹ ಮಾಹಿತಿ ಇರುತ್ತದೆ.

## ಸಂದರ್ಭ

ವಿವರಿಸಿ:

- ವಿನ್ಯಾಸವು ವಾಸ್ತುಶಿಲ್ಪದ ದೃಷ್ಟಿಯಿಂದ ಹೇಗೆ ಮಹತ್ವದ್ದಾಗಿದೆ - ಸರಳ ಇಶ್ಯೂ ಮತ್ತು PR ನಿಂದ ಸಮಸ್ಯೆ ಪರಿಹರಿಸುವ ಬದಲು ADR ಬೇಕಾಗುವುದನ್ನು ಸಮರ್ಥಿಸುತ್ತದೆ

- ಉನ್ನತ ಮಟ್ಟದ ವಿನ್ಯಾಸ ವಿಧಾನ (ವಿವರಗಳನ್ನು ಕೆಳಗಿನ ಪ್ರಸ್ತಾಪಿತ ವಿನ್ಯಾಸದಲ್ಲಿ ವಿವರಿಸಲಾಗಿದೆ)


## ಪ್ರಸ್ತಾಪಿತ ವಿನ್ಯಾಸ

ವಿನ್ಯಾಸದ ವಿವರಗಳು (ಸಾಧ್ಯವಿರುವಲ್ಲಿ ಅನುಷ್ಠಾನಕ್ಕೆ ಹೋಗದೆ).

ರೂಪರೇಖೆ:

- ಪ್ರಭಾವಿತವಾಗುವ (ಬದಲಾಗುವ) ಸೇವೆಗಳು/ಮಾಡ್ಯೂಲ್‌ಗಳು

- ಸೇರಿಸಬೇಕಾದ ಹೊಸ ಸೇವೆಗಳು/ಮಾಡ್ಯೂಲ್‌ಗಳು

- ಮಾದರಿ ಮತ್ತು DTO ಪ್ರಭಾವ (ಬದಲಾವಣೆಗಳು/ಸೇರ್ಪಡೆಗಳು/ತೆಗೆದುಹಾಕುವಿಕೆಗಳು)

- API ಪ್ರಭಾವ (ಬದಲಾವಣೆಗಳು/ಸೇರ್ಪಡೆಗಳು/ತೆಗೆದುಹಾಕುವಿಕೆಗಳು)

- ಸಾಮಾನ್ಯ ಸಂರಚನಾ ಪ್ರಭಾವ (ಹೊಸ ವಿಭಾಗಗಳ ಸ್ಥಾಪನೆ, ಬದಲಾವಣೆಗಳು/ಸೇರ್ಪಡೆಗಳು/ತೆಗೆದುಹಾಕುವಿಕೆಗಳು)

- devops ಪ್ರಭಾವ


## ಪರಿಗಣನೆಗಳು

ADR ನ ಚರ್ಚೆಯಲ್ಲಿ ಉದ್ಭವಿಸಿದ ಪರ್ಯಾಯಗಳು, ಕಾಳಜಿಗಳು, ಪೂರಕ ಅಥವಾ ಸಂಬಂಧಿತ ವಿಷಯಗಳು, ಪ್ರಶ್ನೆಗಳನ್ನು ದಾಖಲಿಸಿ. 

ಅವನ್ನು ಹೇಗೆ/ಹೇಗೆ ಪರಿಹರಿಸಲಾಯಿತು ಅಥವಾ ತಗ್ಗಿಸಲಾಯಿತು ಎಂಬುದನ್ನು ಸೂಚಿಸಿ.


## ನಿರ್ಧಾರ

ಒಪ್ಪಿಕೊಂಡ ಯಾವುದೇ ಪ್ರಮುಖ ಅನುಷ್ಠಾನ ವಿವರ, ಎಚ್ಚರಿಕೆಗಳು, ಭವಿಷ್ಯದ ಪರಿಗಣನೆಗಳು, ಉಳಿದ ಅಥವಾ ಮುಂದೂಡಲಾದ ವಿನ್ಯಾಸ ಸಮಸ್ಯೆಗಳನ್ನು ದಾಖಲಿಸಿ.

ಪ್ರಸ್ತಾಪಿತ ವಿನ್ಯಾಸದಿಂದ ಪೂರೈಸದ ಅವಶ್ಯಕತೆಗಳ ಯಾವುದೇ ಭಾಗವನ್ನು ದಾಖಲಿಸಿ.
