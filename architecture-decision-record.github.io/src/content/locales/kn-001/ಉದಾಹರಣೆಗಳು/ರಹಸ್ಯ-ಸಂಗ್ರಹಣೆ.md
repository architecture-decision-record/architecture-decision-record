## ಸಾರಾಂಶ


### ಸಮಸ್ಯೆ

ಗುಪ್ತಪದಗಳು, ಖಾಸಗಿ ಕೀಗಳು, ದೃಢೀಕರಣ ಟೋಕನ್‌ಗಳು ಇತ್ಯಾದಿ ರಹಸ್ಯಗಳನ್ನು ನಾವು ಸಂಗ್ರಹಿಸಬೇಕು.

ಕೆಲವು ರಹಸ್ಯಗಳು ಬಳಕೆದಾರ-ಕೇಂದ್ರಿತ. ಉದಾಹರಣೆಗೆ, ನಮ್ಮ ಡೆವಲಪರ್ ಸೇವೆಯೊಂದರ ಗುಪ್ತಪದವನ್ನು ನೋಡಲು ತಮ್ಮ ಮೊಬೈಲ್ ಫೋನ್ ಬಳಸಲು ಸಾಧ್ಯವಾಗಬೇಕೆಂದು ಬಯಸುತ್ತಾರೆ.

ಕೆಲವು ರಹಸ್ಯಗಳು ವ್ಯವಸ್ಥೆ-ಕೇಂದ್ರಿತ. ಉದಾಹರಣೆಗೆ, ನಮ್ಮ ನಿರಂತರ ವಿತರಣೆ ಪೈಪ್‌ಲೈನ್ ನಮ್ಮ ಕ್ಲೌಡ್ ಹೋಸ್ಟಿಂಗ್‌ನ ರುಜುವಾತುಗಳನ್ನು ನೋಡಲು ಸಾಧ್ಯವಾಗಬೇಕು.


### ನಿರ್ಧಾರ

ಬಳಕೆದಾರ-ಕೇಂದ್ರಿತ ರಹಸ್ಯಗಳಿಗೆ Bitwarden

ವ್ಯವಸ್ಥೆ-ಕೇಂದ್ರಿತ ರಹಸ್ಯಗಳಿಗೆ Vault by HashiCorp.


### ಸ್ಥಿತಿ

ನಿರ್ಧರಿಸಲಾಗಿದೆ. ಹೊಸ ಪರ್ಯಾಯಗಳು ಬಂದಂತೆ ಅವಕ್ಕೆ ನಾವು ಮುಕ್ತರಾಗಿದ್ದೇವೆ.


## ವಿವರಗಳು


### ಊಹೆಗಳು

ಈ ಉದ್ದೇಶಕ್ಕಾಗಿ ಮತ್ತು ನಮ್ಮ ಪ್ರಸ್ತುತ ಸ್ಥಿತಿಗೆ, ಬಳಸಬಹುದಾದ ಮೊಬೈಲ್ ಅಪ್ಲಿಕೇಶನ್‌ಗಳಂತಹ ಬಳಕೆದಾರ-ಕೇಂದ್ರಿತ ಅನುಕೂಲವನ್ನು ನಾವು ಮೌಲ್ಯೀಕರಿಸುತ್ತೇವೆ.

  * ಕರೆಯ ಮೇರೆಗೆ ವ್ಯವಸ್ಥೆ ವಿಶ್ವಾಸಾರ್ಹತೆ ಎಂಜಿನಿಯರಿಂಗ್ ಮಾಡುವ ಡೆವಲಪರ್‌ನಂತೆ, ಪ್ರಯಾಣದಲ್ಲಿರುವಾಗ ವೇಗದ ಸುಲಭ ಪ್ರವೇಶವನ್ನು ಖಚಿತಪಡಿಸಲು ನಾವು ಬಯಸುತ್ತೇವೆ.

  * ತಂಡದಂತೆ, ಆಯ್ದ ಜನರ ನಡುವೆ ಕೆಲವು ರಹಸ್ಯಗಳನ್ನು ಹಂಚಿಕೊಳ್ಳಲು ನಾವು ಬಯಸುತ್ತೇವೆ.

ಎಲ್ಲಾ ರಹಸ್ಯಗಳನ್ನು Amazon ಅಥವಾ Azure ಅಥವಾ Google ನಲ್ಲಿ ಮಾತ್ರ ಸಂಗ್ರಹಿಸುವಂತೆ, ಏಕ-ಪೂರೈಕೆದಾರಕ್ಕಾಗಿ ಪರಿಹರಿಸಲು ನಾವು ಪ್ರಯತ್ನಿಸುತ್ತಿಲ್ಲ.

"ನೆನಪಿಟ್ಟುಕೊಳ್ಳಿ" ಅಥವಾ "ಚೀಟಿಯಲ್ಲಿ ಬರೆಯಿರಿ" ಅಥವಾ "ಸಂಗ್ರಹಿಸಲು ನಿಮ್ಮದೇ ಮಾರ್ಗ ಕಂಡುಕೊಳ್ಳಿ" ಎಂಬಂತಹ ತಾತ್ಕಾಲಿಕ ವಿಧಾನಗಳನ್ನು ನಾವು ಬಯಸುವುದಿಲ್ಲ.

ಈ ಉದ್ದೇಶಕ್ಕಾಗಿ ನಮ್ಮ ಭದ್ರತಾ ಮಾದರಿಯು SaaS ಗುಪ್ತಪದ ನಿರ್ವಹಣಾ ಸಾಧನಗಳಂತಹ ಚೆನ್ನಾಗಿ ಗೌರವಿಸಲ್ಪಟ್ಟ COTS ಮಾರಾಟಗಾರರನ್ನು ಬಳಸುವುದರೊಂದಿಗೆ ಸರಿಯಾಗಿದೆ.


### ನಿರ್ಬಂಧಗಳು

ಸದ್ಯಕ್ಕೆ ನಮಗೆ ಸುಲಭವಾದದ್ದು ಬೇಕು, ಅಂದರೆ ಕೋಡ್ ಬರೆಯುವ ಅಗತ್ಯವಿಲ್ಲ, ಸರ್ವರ್‌ಗಳನ್ನು ಸ್ಥಾಪಿಸುವ ಅಗತ್ಯವಿಲ್ಲ, ದೊಡ್ಡ ಬದ್ಧತೆ ಮಾಡುವ ಅಗತ್ಯವಿಲ್ಲ, ಎಲ್ಲರನ್ನೂ ಪ್ರಮಾಣೀಕರಿಸುವ ಅಗತ್ಯವಿಲ್ಲ.


### ನಿಲುವುಗಳು

ನಾವು ಪರಿಗಣಿಸಿದ್ದು:

1. ಬಳಕೆದಾರ-ಕೇಂದ್ರಿತ ಸಿದ್ಧ ಗುಪ್ತಪದ ನಿರ್ವಾಹಕಗಳು: LastPass, 1Password, Bitwarden, Dashlane, KeePass, pass, GPG, ಇತ್ಯಾದಿ.

2. ವ್ಯವಸ್ಥೆ-ಕೇಂದ್ರಿತ COTS ಗುಪ್ತಪದ ನಿರ್ವಾಹಕಗಳು: AWS KMS, Vault by HashiCorp, EnvKy, Secret Server by Thycotic, Devolutions Password Server, Confidant by Lyft.

3. ಹಂಚಿಕೆ-ಕೇಂದ್ರಿತ ವಿಧಾನಗಳು: ಹಂಚಿಕೊಂಡ Google ಡಾಕ್ಯುಮೆಂಟ್, ಅಥವಾ ಹಂಚಿಕೊಂಡ Slack ಚಾನಲ್, ಅಥವಾ ಹಂಚಿಕೊಂಡ ನೆಟ್‌ವರ್ಕ್ ಫೋಲ್ಡರ್ ಇತ್ಯಾದಿ ಬಳಸುವುದು.

4. ನೆನಪಿಟ್ಟುಕೊಳ್ಳುವುದು, ಚೀಟಿ ಬರೆಯುವುದು, ಅಥವಾ ಪ್ರತಿ ಬಳಕೆದಾರರು ತಮ್ಮದೇ ವಿಧಾನವನ್ನು ಕಂಡುಕೊಳ್ಳುವುದನ್ನು ಅವಲಂಬಿಸುವುದರಂತಹ ಕಡಿಮೆ-ತಂತ್ರಜ್ಞಾನದ ತಾತ್ಕಾಲಿಕ ವಿಧಾನಗಳು.


### ವಾದ

Bitwarden, LastPass, 1Password ಮತ್ತು Dashlane ಎಲ್ಲವೂ ವಾಣಿಜ್ಯ ಸಿದ್ಧ ಉತ್ಪನ್ನಗಳು.

  * ಬಳಕೆದಾರರು, ತಂಡಗಳು, ಸಂಸ್ಥೆಗಳು ಇತ್ಯಾದಿಗಳಿಗೆ ಒಂದೇ ರೀತಿಯ ವೈಶಿಷ್ಟ್ಯಗಳು.

  * Windows ಮತ್ತು Mac ಗೆ ಡೆಸ್ಕ್‌ಟಾಪ್ ಸಾಮರ್ಥ್ಯ, ಮತ್ತು Android ಮತ್ತು iOS ಗೆ ಮೊಬೈಲ್ ಸಾಮರ್ಥ್ಯ.

  * ಸ್ವಯಂಚಾಲಿತ ಫಾರ್ಮ್ ತುಂಬುವಿಕೆ ಇತ್ಯಾದಿಗಳಿಗೆ Chrome ಮತ್ತು Firefox ಗೆ ಬ್ರೌಸರ್ ವಿಸ್ತರಣೆಗಳು.

Bitwarden ಇತರರಿಗಿಂತ ಎರಡು ಅನುಕೂಲಗಳನ್ನು ಹೊಂದಿದೆ:

  * Bitwarden ಮುಕ್ತ ಮೂಲ, ಅಂದರೆ ಭದ್ರತೆಯನ್ನು ಸಹೋದ್ಯೋಗಿಗಳು ಪರಿಶೀಲಿಸಬಹುದು ಮತ್ತು ಕಂಪನಿಯು ಭದ್ರತೆ-ಕೇಂದ್ರಿತ ಡೆವಲಪರ್‌ಗಳಿಂದ ವ್ಯಾಪಕವಾಗಿ ಮೆಚ್ಚುಗೆ ಪಡೆದಿದೆ.

  * ಇತರರಿಗಿಂತ Bitwarden ಗೆ ಗಣನೀಯ ಆದ್ಯತೆಯನ್ನು ತಂತ್ರಾಂಶ ಕೆಲಸಗಾರರ ಉಪಾಖ್ಯಾನಗಳು ವಿವರಿಸುತ್ತವೆ.

ವಿಶಿಷ್ಟ ಉತ್ತಮ ಉದಾಹರಣೆ ಬರಹ: https://jcs.org/2017/11/17/bitwarden

ವಿಶಿಷ್ಟ ಅಕ್ಕಪಕ್ಕದ ಮತದಾನ ತಾಣ: https://stackshare.io/stackups/bitwarden-vs-dashlane

ಹೆಚ್ಚುವರಿ ಸಂಕೀರ್ಣತೆ ಇರುವುದರಿಂದ ನಾವು KeyPass, pass, GPG ಇತ್ಯಾದಿಗಳನ್ನು ಮುಂದೂಡುತ್ತೇವೆ. ಇವೆಲ್ಲವೂ ತಾಂತ್ರಿಕ ಬಳಕೆದಾರರಿಗೆ ಉತ್ತಮ ಪರಿಹಾರಗಳಂತೆ ಕಾಣುತ್ತವೆ. ವ್ಯವಸ್ಥೆಗಳಾದ್ಯಂತ ಆದೇಶ-ಕೇಂದ್ರಿತ ಸಾಮರ್ಥ್ಯಗಳನ್ನು ಬಯಸುವ ತಾಂತ್ರಿಕ ಬಳಕೆದಾರರಿಗೆ GPG ವಿಶೇಷವಾಗಿ ಉತ್ತಮವಾಗಿ ಕಾಣುತ್ತದೆ.

ಏಕ-ಪೂರೈಕೆದಾರ ಬಂಧನ ಇರುವುದರಿಂದ ನಾವು KMS ಅನ್ನು ಮುಂದೂಡುತ್ತೇವೆ.

ವಿಮರ್ಶೆಗಳು ಅದ್ಭುತವಾಗಿ ಧನಾತ್ಮಕವಾಗಿರುವುದರಿಂದ, ಮತ್ತು HashiCorp ಉನ್ನತ ಗುಣಮಟ್ಟದ ತಂತ್ರಾಂಶ ಮತ್ತು ಬೆಂಬಲದ ಅತ್ಯುತ್ತಮ ಇತಿಹಾಸವನ್ನು ಹೊಂದಿರುವುದರಿಂದ, ವ್ಯವಸ್ಥೆ-ಕೇಂದ್ರಿತ ಅಗತ್ಯಗಳಿಗೆ ನಾವು Vault ಅನ್ನು ಆರಿಸುತ್ತೇವೆ.

ಹಂಚಿಕೊಂಡ ಡಾಕ್ಯುಮೆಂಟ್‌ಗಳು, ಹಂಚಿಕೊಂಡ ಚಾನಲ್‌ಗಳು, ಹಂಚಿಕೊಂಡ ನೆಟ್‌ವರ್ಕ್ ಫೋಲ್ಡರ್‌ಗಳು ಇತ್ಯಾದಿಗಳ ಮೂಲಕದಂತಹ ಹಂಚಿಕೆ ವಿಧಾನಗಳನ್ನು ನಾವು ವೀಟೋ ಮಾಡುತ್ತೇವೆ. ಇವು ನಾವು ಬಯಸುವ ಭದ್ರತಾ ಗುಣಗಳನ್ನು ಒದಗಿಸುವುದಿಲ್ಲ.

ತಾತ್ಕಾಲಿಕ ಕಡಿಮೆ-ತಂತ್ರಜ್ಞಾನದ ವಿಧಾನಗಳನ್ನು ನಾವು ವೀಟೋ ಮಾಡುತ್ತೇವೆ, ಏಕೆಂದರೆ ಇದು ದೀರ್ಘಕಾಲೀನ ಮುಂದಿನ ದಾರಿಯಲ್ಲ ಎಂದು ನಾವೆಲ್ಲರೂ ಒಪ್ಪುತ್ತೇವೆ.


### ಪರಿಣಾಮಗಳು

ಡೆವಲಪರ್‌ಗಳು ರಹಸ್ಯಗಳನ್ನು ಎರಡು ಸ್ಥಳಗಳಲ್ಲಿ ಟ್ರ್ಯಾಕ್ ಮಾಡಬೇಕಾಗಬಹುದು: ಬಳಕೆದಾರ-ಕೇಂದ್ರಿತ ಪ್ರವೇಶಕ್ಕೆ Bitwarden, ಮತ್ತು ವ್ಯವಸ್ಥೆ-ಕೇಂದ್ರಿತ ಪ್ರವೇಶಕ್ಕೆ Vault.


## ಸಂಬಂಧಿತ


### ಸಂಬಂಧಿತ ನಿರ್ಧಾರಗಳು

ಯಾವ CI/CD ಸರ್ವರ್ ಎಂಬ ನಿರ್ಧಾರವು ರಹಸ್ಯಗಳನ್ನು ಪ್ರವೇಶಿಸುವ ಸಾಮರ್ಥ್ಯದ ಪುರಾವೆಯನ್ನು ಒಳಗೊಂಡಿರಬೇಕು.

ನೀತಿಗಳು, ತಿರುಗುವಿಕೆಗಳು, ಸಂಸ್ಥೆಗಳು ಇತ್ಯಾದಿಗಳ ದೃಷ್ಟಿಯಿಂದ ರಹಸ್ಯಗಳನ್ನು ಹೇಗೆ ನಿರ್ವಹಿಸಬೇಕು ಎಂಬುದನ್ನು ನಾವು ನಿರ್ಧರಿಸಬೇಕಾಗುತ್ತದೆ.


### ಸಂಬಂಧಿತ ಅವಶ್ಯಕತೆಗಳು

ರಹಸ್ಯಗಳು ಅನುಸರಣೆ, ಲೆಕ್ಕಪರಿಶೋಧನೆ ಮತ್ತು HR ಆನ್‌ಬೋರ್ಡಿಂಗ್/ಆಫ್‌ಬೋರ್ಡಿಂಗ್‌ಗೆ ಸಂಬಂಧಿತ ಅವಶ್ಯಕತೆಗಳನ್ನು ಹೊಂದಿರುತ್ತವೆ.


### ಸಂಬಂಧಿತ ಆರ್ಟಿಫ್ಯಾಕ್ಟುಗಳು

ಕೆಲವು ರಹಸ್ಯಗಳನ್ನು ಪರಿಸರ ಚರಗಳಿಗೆ ರಫ್ತು ಮಾಡಬಹುದು ಎಂದು ನಾವು ನಿರೀಕ್ಷಿಸುತ್ತೇವೆ.


### ಸಂಬಂಧಿತ ತತ್ವಗಳು

ಸುಲಭವಾಗಿ ಹಿಂದಿರುಗಿಸಬಹುದಾದ.

ಸುಲಭವಾಗಿ ಸಮಾನಾಂತರ, ಅಂದರೆ ವಿವಿಧ ಗುಪ್ತಪದ ನಿರ್ವಾಹಕಗಳನ್ನು ಬಳಸುವುದು ಸುಲಭ.

ಪ್ರಯತ್ನಿಸಲು ಅಗ್ಗ, ಅಂದರೆ ಉಚಿತ ಪ್ರಯೋಗವಿದೆ ಮತ್ತು ಯಾವುದೇ ಬದ್ಧತೆಯಿಲ್ಲ.


## ಟಿಪ್ಪಣಿಗಳು

### Vault by HashiCorp

Vault ನಿಖರವಾಗಿ ನೀವು ಇಲ್ಲಿ ಬಯಸುವುದು. 

ಆದರೂ Vault ಅನ್ನು ಸುಮ್ಮನೆ ಉತ್ಪಾದನೆಗೆ ಹಾಕಬೇಡಿ, ಮೊದಲು ಪರೀಕ್ಷಾ ಪರಿಸರದಲ್ಲಿ ಅದನ್ನು ಸ್ಥಾಪಿಸಿ, ಏಕೆಂದರೆ HashiCorp ನ ಉತ್ಪನ್ನಗಳು ಅದ್ಭುತವಾಗಿದ್ದರೂ ಅವರ ದಾಖಲಾತಿ ಸಾಕಷ್ಟು ಕೊರತೆಯಿಂದ ಕೂಡಿರಬಹುದು.

ಬಹಳ ಕಡಿದಾದ ಕಲಿಕೆಯ ರೇಖೆ ಮತ್ತು ಸ್ಥಾಪಿಸುವುದು ಸುಲಭವಲ್ಲ. 

ಆರಂಭಿಕ ಸೆಟಪ್ ಸ್ವಲ್ಪ ತೊಂದರೆ. ಆದರೂ ಅದು ಸಂಪೂರ್ಣ ಯೋಗ್ಯ, ಮತ್ತು ನೀವು ಹೇಗೋ ನಿಭಾಯಿಸಲು ಸಾಕಷ್ಟು ಚೆನ್ನಾಗಿ ಸಮುದಾಯ ಅದನ್ನು ಬೆಂಬಲಿಸುತ್ತದೆ.

ಭಯಾನಕ ದಾಖಲೆಗಳು ಆದರೆ ಅದನ್ನು ಸ್ಥಾಪಿಸುತ್ತಿರುವ ಜನರ ಬಗ್ಗೆ ಆನ್‌ಲೈನ್‌ನಲ್ಲಿ ಬಹಳಷ್ಟು ಮಾರ್ಗದರ್ಶಿಗಳಿವೆ ಮತ್ತು ಅವುಗಳಲ್ಲಿ ಕೆಲವನ್ನು ಒಟ್ಟಿಗೆ ಸೇರಿಸಿದರೆ ನಿಮಗೆ ಕೆಲಸ ಮಾಡುವ ಸೆಟಪ್ ಸಿಗುತ್ತದೆ.

ಆರಂಭಿಕ ಸೆಟಪ್‌ಗೆ ಅವರ helm ಚಾರ್ಟ್‌ಗಳೊಂದಿಗೆ (vault ಮತ್ತು consul) ಕೈಯಾಡಿಸಬೇಕಾಯಿತು. ತಾಂತ್ರಿಕವಾಗಿ ನೀವು ಇನ್ನೂ ಅನೇಕ ಬ್ಯಾಕ್-ಎಂಡ್‌ಗಳನ್ನು ಬಳಸಬಹುದಾದರೂ, ನಾನು ನಿಜವಾಗಿಯೂ ಶಿಫಾರಸು ಮಾಡುವುದಿಲ್ಲ. ಸಂಗ್ರಹಿಸಲು ನಿಮ್ಮಲ್ಲಿ ಬಹಳಷ್ಟು ಡೇಟಾ ಇಲ್ಲದಿದ್ದರೆ ಬ್ಯಾಕ್-ಎಂಡ್/consul ಬಹಳ ಚಿಕ್ಕದಾಗಿರಬಹುದು.

CLI ಬಳಸುವುದರಲ್ಲಿ ಖಂಡಿತವಾಗಿ ಸುಖವಾಗಿ/ಪರಿಚಿತರಾಗಿ, ಏಕೆಂದರೆ GUI ಅವರ ಎಂಟರ್‌ಪ್ರೈಸ್ ಆವೃತ್ತಿಯ ಪರಿಕಲ್ಪನೆಯ ಪುರಾವೆ/ಜಾಹೀರಾತು ಪೋರ್ಟಲ್‌ನಂತಿದೆ.

ನೀವು ಅದನ್ನು ಸುಮ್ಮನೆ "ತುಂಬಲು" ಸಾಧ್ಯವಿಲ್ಲ ಎಂಬುದು ತೊಂದರೆ. ಉದಾಹರಣೆಗೆ ನಿಮ್ಮಲ್ಲಿ 5 ಕ್ಷೇತ್ರಗಳಿದ್ದರೆ ಪ್ರತಿ ಐಟಂಗೆ ಪ್ರತಿ ಕ್ಷೇತ್ರವನ್ನು ನೀವು ಹಸ್ತಚಾಲಿತವಾಗಿ ಸೇರಿಸಬೇಕು. ಆದ್ದರಿಂದ ನೀವು ನಿರ್ದಿಷ್ಟ ವರ್ಗಕ್ಕೆ ಕ್ಷೇತ್ರಗಳನ್ನು ಮೊದಲೇ ವ್ಯಾಖ್ಯಾನಿಸಿ, ಆ ವರ್ಗದ ಎಲ್ಲಾ ಐಟಂಗಳಿಗೆ ಆ ಕ್ಷೇತ್ರಗಳನ್ನು ತುಂಬುವುದಲ್ಲ, ಇದು "ನೀವು ಪ್ರತಿ ಬಾರಿ ಎಲ್ಲವನ್ನೂ ರಚಿಸುತ್ತೀರಿ" ಎಂಬಂತೆ, ಇದು (ನನ್ನ ಮನಸ್ಸಿನಲ್ಲಿ) ತಲೆನೋವು.

vault ಮೇಲ್ಭಾಗದಲ್ಲಿ UI ಆಗಿ goldfish ಅನ್ನೂ ನೀವು ನೋಡಲು ಬಯಸಬಹುದು. ನಿಮ್ಮ ತಂಡವನ್ನು ಅದರೊಂದಿಗೆ ಸೇರಿಸಿಕೊಳ್ಳುವುದನ್ನು ಸಾಕಷ್ಟು ಚೆನ್ನಾಗಿ ಮಾಡುತ್ತದೆ. ಅವರ ಬಳಿ ಡೆಮೊ ಕೂಡ ಇದೆ. 1. consul ಹೊಂದಿಸಿ. 2. consul ಕಡೆಗೆ ತೋರಿಸುವ vault ಹೊಂದಿಸಿ. 3. vault ಕಡೆಗೆ ತೋರಿಸುವ goldfish ಹೊಂದಿಸಿ. 3. ಬ್ಯಾಕಪ್‌ಗಳಿಗಾಗಿ consul snapshot ಚಲಾಯಿಸಲು ಕೆಲವು cron ಕೆಲಸವನ್ನು ಹೊಂದಿಸಿ.



### LastPass

LastPass Teams. ನಾವು ಇದನ್ನು ಬಳಸುತ್ತೇವೆ, ಕಸ್ಟಮ್ ಟೆಂಪ್ಲೇಟುಗಳು, ACL ಇವೆ, ನನ್ನ ಅಭಿಪ್ರಾಯದಲ್ಲಿ ಏನೂ ಕೊರತೆಯಿಲ್ಲ.

ನಾನು LastPass ಅನ್ನು ನನ್ನ ಸಂಸ್ಥೆಯಲ್ಲಿ ಅನುಷ್ಠಾನಗೊಳಿಸಿದ್ದೇನೆ ಮತ್ತು ಅದಕ್ಕೆ C+/B- ನೀಡುತ್ತೇನೆ. ಇತ್ತೀಚಿನ ಅತಿದೊಡ್ಡ ಸಮಸ್ಯೆ ವಿಶ್ವಾಸಾರ್ಹತೆಯ ಕೊರತೆ. ಕಳೆದ 90 ದಿನಗಳಲ್ಲಿ ವಾಲ್ಟ್‌ಗಳನ್ನು ಆಫ್‌ಲೈನ್ ಮೋಡ್‌ಗೆ ಒತ್ತಾಯಿಸಿದ ಹಲವಾರು ಗಂಟೆಗಳಿವೆ. ಅಕ್ಷರಶಃ 20+ ಹಂಚಿದ ಫೋಲ್ಡರ್‌ಗಳಲ್ಲಿ 4,000+ ಗುಪ್ತಪದಗಳನ್ನು ಸಂಗ್ರಹಿಸಿರುವುದರಿಂದ ಇದು ನನ್ನ ಸಂಸ್ಥೆಗೆ ಆದರ್ಶವಲ್ಲ. ಅಷ್ಟೊಂದು ಗುಪ್ತಪದಗಳೊಂದಿಗೆ ದಿನವೂ ಕನಿಷ್ಠ ಕೆಲವು ನವೀಕರಿಸಲ್ಪಡುತ್ತವೆ ಅಥವಾ ಸೇರಿಸಲ್ಪಡುತ್ತವೆ ಎಂದು ನೀವು ಊಹಿಸಬಹುದು. ಸಮಸ್ಯೆಗಳು ಒಂದೆರಡು ಗಂಟೆಗಳಿಗಿಂತ ಹೆಚ್ಚು ಕಾಲ ಇದ್ದರೆ ನಮ್ಮಲ್ಲಿ DR ಯೋಜನೆ ಇದೆ: ಪ್ರತಿ ರಾತ್ರಿ ವಾಲ್ಟ್‌ನ CSV ಡಂಪ್ ಅನ್ನು ಸ್ಕ್ರಿಪ್ಟ್ ಸಹಿ ಮಾಡಿ ಎನ್‌ಕ್ರಿಪ್ಟ್ ಮಾಡುತ್ತದೆ, ಅದನ್ನು keepass ಗೆ ಆಮದು ಮಾಡಬಹುದು.

LastPass ವರದಿ ಮಾಡದ ಕುಸಿದ ಸೇವೆಯ ಕ್ಷಣಿಕ ಸಮಸ್ಯೆಗಳನ್ನು ಹೊಂದಿದೆ: ಲಾಗಿನ್ 'ಕೆಲಸ ಮಾಡುತ್ತದೆ' ಆದರೆ ಸೈಟ್‌ಗಳನ್ನು ಎಳೆಯುವುದಿಲ್ಲ, ನಿರ್ವಾಹಕ ಫಲಕದಲ್ಲಿ ಯಾದೃಚ್ಛಿಕ ವೈಶಿಷ್ಟ್ಯಗಳು ಮುರಿದಿವೆ, ಮತ್ತು ಹೊಸ ಉನ್ನತ ಮಟ್ಟದ ಹಂಚಿದ ಫೋಲ್ಡರ್‌ಗಳಿಗೆ ಕೀಗಳನ್ನು ಸರಿಯಾಗಿ ಹಂಚುತ್ತಿಲ್ಲ. ನನ್ನಲ್ಲಿ ಪ್ರತಿ ಗುಂಪಿನಲ್ಲೂ ಇರುವ ನಿರ್ದಿಷ್ಟ 'ಕೀ ಪುಶ್'/ಬ್ಯಾಕಪ್ ಬಳಕೆದಾರರಿದ್ದಾರೆ. ಸಾಮಾನ್ಯವಾಗಿ ಆ ಬಳಕೆದಾರರಾಗಿ ಲಾಗಿನ್ ಮಾಡುವುದು ಯಾವುದೇ ಕೀ ಹಂಚಿಕೆ ಸಮಸ್ಯೆಗಳನ್ನು ಸರಿಪಡಿಸುತ್ತದೆ, ಆದರೆ ಸ್ಥಿತಿ ಪುಟ ಏನೇ ಹೇಳಿದರೂ ಸೇವೆ ಕುಸಿದಾಗ ಅಲ್ಲ...

ಏಕೀಕರಣಕ್ಕೆ, ಕನಿಷ್ಠ ಸವಲತ್ತಿನ ಮಾದರಿಯೊಂದಿಗೆ ಸರಿಯಾದ ACL ಗಳಿದ್ದರೆ ಅದು ಸುಲಭವಾಗಬಹುದು, ಉದಾ. ಬಳಕೆದಾರರು ಒಂದು ನಮೂದು ಅಥವಾ ಫೋಲ್ಡರ್‌ನಲ್ಲಿ ಓದು ಮತ್ತು ಬರೆ ಹಾಗೂ ಓದು-ಮಾತ್ರ ಎರಡನ್ನೂ ಹೊಂದಿದ್ದರೆ ಅವರಿಗೆ ಓದು-ಮಾತ್ರ ಅನುಮತಿಗಳು ಮಾತ್ರ ಸಿಗುತ್ತವೆ. ದುರದೃಷ್ಟವಶಾತ್ ನನ್ನ ಸಂಸ್ಥೆಯ ACL ಗಳು ಅತ್ಯುತ್ತಮವಲ್ಲ, ಆದ್ದರಿಂದ ನಮ್ಮ ನೂರಾರು ACL ಗಳ ಅವಲಂಬಿತ ಸ್ವಭಾವವು ಕನಿಷ್ಠ ಸವಲತ್ತಿನ ಮಾದರಿಗೆ ಚೆನ್ನಾಗಿ ಮ್ಯಾಪ್ ಆಗದ ಕಾರಣ ನಾನು JSON ಪ್ರೊವಿಷನಿಂಗ್ API ಮತ್ತು ~500 ಸಾಲುಗಳ python ಬಳಸಬೇಕಾಯಿತು. ಬಳಕೆದಾರರು ಇದ್ದ ಎಲ್ಲಾ ACL ಗಳನ್ನು ಪಡೆದು ಒಂದು ರೀತಿಯ ಅವಲಂಬನೆ ನಡಿಗೆ ಮಾಡಿದೆ.

ನಿಮ್ಮ ACL ಅಥವಾ ಗುಂಪು ರಚನೆಯನ್ನು ಈಗಾಗಲೇ ಕನಿಷ್ಠ ಸವಲತ್ತಿನ ರಚನೆಯನ್ನು ಮನಸ್ಸಿನಲ್ಲಿಟ್ಟುಕೊಂಡು ನಿರ್ಮಿಸಿದ್ದರೆ, Windows ಗಾಗಿ AD/LDAP ಸಿಂಕ್ ಸಾಧನ ಚೆನ್ನಾಗಿ ಕೆಲಸ ಮಾಡುತ್ತದೆ.

ಅವರ ಮಾರಾಟ ತಂಡವನ್ನು ಸಂಪರ್ಕಿಸಿ, ಅವರು ನಿಮಗೆ ದೀರ್ಘ ಎಂಟರ್‌ಪ್ರೈಸ್ ಪ್ರಯೋಗವನ್ನು ಜೋಡಿಸಿಕೊಡಬಹುದು. ಮುಂದುವರಿಯುವ ಮೊದಲು ಅದರ ಮಿತಿಗಳನ್ನು ಸಂಪೂರ್ಣವಾಗಿ ಅರ್ಥಮಾಡಿಕೊಳ್ಳಿ. ನಮಗೆ ಸಾಕಷ್ಟು ಬೆಳೆಯುವ ನೋವುಗಳಿದ್ದವು ಆದರೆ ಸರ್ವರ್ ಬದಿಯ ಸ್ಥಗಿತಗಳು ಅಥವಾ ದುರ್ಬಲತೆಗಳನ್ನು ಹೊರತುಪಡಿಸಿ ಅದು ನಂಬಲಾಗದಷ್ಟು ಸುಗಮವಾಗಿದೆ.
