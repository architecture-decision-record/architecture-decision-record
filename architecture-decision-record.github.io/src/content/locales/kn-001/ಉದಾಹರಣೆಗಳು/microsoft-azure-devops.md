## ಸಾರಾಂಶ


### ಸಮಸ್ಯೆ

ನಮ್ಮ ಯೋಜನೆಗಳನ್ನು ಬಿಲ್ಡ್ ಮಾಡಲು, ಏಕೀಕರಿಸಲು, ನಿಯೋಜಿಸಲು ಮತ್ತು ಹೋಸ್ಟ್ ಮಾಡಲು ನಾವು devops ಬಳಸಲು ಬಯಸುತ್ತೇವೆ. ನಾವು Microsoft Azure DevOps ಅನ್ನು ಪರಿಗಣಿಸುತ್ತಿದ್ದೇವೆ.

  * devops ನ ಸೆಟಪ್ ಉದಾ. ಸಂರಚನೆ ಹಾಗೂ ನಿರಂತರ ಬಳಕೆ ಉದಾ. ವೇಗದ ಬಿಲ್ಡ್ ಸಮಯಗಳಿಗೆ, ಡೆವಲಪರ್ ಅನುಭವ ವೇಗವಾಗಿ ಮತ್ತು ವಿಶ್ವಾಸಾರ್ಹವಾಗಿರಬೇಕೆಂದು ನಾವು ಬಯಸುತ್ತೇವೆ.
  
  * ಯೋಜನೆಯ ಅಪ್ಲಿಕೇಶನ್‌ಗಳು, ಡೇಟಾಬೇಸ್‌ಗಳು ಇತ್ಯಾದಿಗಳನ್ನು ಹೋಸ್ಟ್ ಮಾಡಲು Microsoft Azure ಅನ್ನು ಸಂಪೂರ್ಣವಾಗಿ ಬಳಸುವುದನ್ನು ಪರಿಗಣಿಸಲು ನಾವು ಬಯಸುತ್ತೇವೆ.

### ಸ್ಥಿತಿ

ನಿರ್ಧರಿಸಲಾಗಿದೆ. ಹೊಸ ಮಹತ್ವದ ಮಾಹಿತಿ ಬಂದರೆ/ಬಂದಾಗ ಪುನರ್ಪರಿಶೀಲಿಸಲು ಮುಕ್ತವಾಗಿದ್ದೇವೆ.


## ವಿವರಗಳು


### ಊಹೆಗಳು

Accelerate ಪುಸ್ತಕದಲ್ಲಿರುವಂತಹ ಎಲ್ಲಾ ಸಾಮಾನ್ಯ devops ಊಹೆಗಳು.

  * ವೇಗದ ಬಿಲ್ಡ್‌ಗಳು ಗಣನೀಯ ಸಹಾಯ. ಇದು ಪ್ರತಿಕ್ರಿಯೆ ಚಕ್ರಗಳನ್ನು ವೇಗಗೊಳಿಸುತ್ತದೆ.

  * ನಾವು ಪರ್ಯಾಯ ಮಾರಾಟಗಾರರ ತುಣುಕುಗಳನ್ನು ಒಳಗೆ/ಹೊರಗೆ ಬದಲಾಯಿಸಬಹುದು, ಅಂದರೆ ನಾವು ನಮ್ಮದೇ ಹೆಚ್ಚಿನ ವೇಗದ ಬಿಲ್ಡ್ ಸರ್ವರ್‌ಗಳನ್ನು ತರಲು, ಅಥವಾ ನಮ್ಮದೇ ಆಯ್ಕೆಯ ಆವೃತ್ತಿ ನಿಯಂತ್ರಣ ವ್ಯವಸ್ಥೆಯನ್ನು ಬಳಸಲು, ಅಥವಾ ಸ್ವಯಂ-ಹೋಸ್ಟ್ ಮಾಡಿದ ನಿರಂತರ ಏಕೀಕರಣ ಸರ್ವರ್‌ನೊಂದಿಗೆ ಸಮನ್ವಯ ಮಾಡಲು ಬಯಸಬಹುದು.
  
  * ಸುಗಮ ಬಳಕೆಯ ಸುಲಭತೆ ಡೆವಲಪರ್ ಅನುಭವಕ್ಕೆ, ಮತ್ತು ಪ್ರತಿಯಾಗಿ ಸ್ಥಿರತೆ, ಸ್ಪಷ್ಟತೆ, ಭದ್ರತೆ ಮತ್ತು ಕಲಿಕೆಯ ರೇಖೆಯ ಸುಲಭತೆಯಂತಹ ಸೂಕ್ಷ್ಮ ಕ್ಷೇತ್ರಗಳಿಗೆ ಗಣನೀಯ ಸಹಾಯ.

  * ಏನಾದರೂ ಮುರಿದಿದ್ದರೆ ಅಥವಾ ಸಮಸ್ಯಾತ್ಮಕವಾಗಿದ್ದರೆ, ಸಮಸ್ಯೆಯನ್ನು ವರದಿ ಮಾಡಲು ನಮಗೆ ಪರಿಣಾಮಕಾರಿ ಮಾರ್ಗ ಬೇಕು. ಇದು ಯಾವುದೇ ಭದ್ರತೆ-ಸಂಬಂಧಿತ ಸಮಸ್ಯೆಗಳಿಗೆ ವಿಶೇಷವಾಗಿ ಮುಖ್ಯ.


### ನಿರ್ಬಂಧಗಳು

ತಿಳಿದಿರುವುದು ಯಾವುದೂ ಇಲ್ಲ. ಬಾಹ್ಯ ಸಾಧನಗಳೊಂದಿಗೆ ಚೆನ್ನಾಗಿ ಕೆಲಸ ಮಾಡುವ ಬಗ್ಗೆ Azure ಪ್ರಕಟಿತ ಬದ್ಧತೆಯನ್ನು ಹೊಂದಿದೆ.


### ನಿಲುವುಗಳು

ಈಗಿರುವ AWS ವರ್ಸಸ್ Microsoft Azure Devops ಬಳಸುವುದನ್ನು ನಾವು ಪರಿಗಣಿಸಿದೆವು.

Azure DevOps, Azure Pipelines, Azure Repo ಮತ್ತು Terraform ಮೂಲಕ ಹೊಸ ಸರ್ವರ್‌ನ Azure ಆರಂಭದೊಂದಿಗೆ ನಾವು ಪ್ರಯೋಗ ಮಾಡಿದೆವು.

Microsoft ಪ್ರತಿನಿಧಿಗಳಿಂದ ಬೆಂಬಲ ಪಡೆಯುವುದರೊಂದಿಗೆ ನಾವು ಪ್ರಯೋಗ ಮಾಡಿದೆವು.

ಬ್ಲಾಗ್‌ಗಳು ಮತ್ತು Hacker News ನಲ್ಲಿ ಸಹೋದ್ಯೋಗಿಗಳಿಂದ ನಾವು ಮಾಹಿತಿ ಸಂಗ್ರಹಿಸಿದೆವು.


### ವಾದ

Azure DevOps ಅತ್ಯುತ್ತಮ ಕೊಡುಗೆಗಳ ಸಮೂಹವನ್ನು ಜಾಹೀರಾತು ಮಾಡುತ್ತದೆ, ಆದರೆ ಅವು ಪರೀಕ್ಷೆಗೆ ನಿಲ್ಲುವುದಿಲ್ಲ, ಅವು ಒಟ್ಟಿಗೆ ಚೆನ್ನಾಗಿ ಕೆಲಸ ಮಾಡುವುದಿಲ್ಲ, ಮತ್ತು ಬೆಂಬಲ ಕಳಪೆ.

ನಮ್ಮ ಪ್ರತ್ಯಕ್ಷ ಅನುಭವ:

  * Azure ಸೆಟಪ್ UI ಗಳ ಗೊಂದಲದ ಗೂಡು, ಅವುಗಳಲ್ಲಿ ಕೆಲವು Microsoft ಖಾತೆಗಳೊಂದಿಗೆ ಅತಿಕ್ರಮಿಸುತ್ತವೆ, ಕೆಲವು ಅತಿಕ್ರಮಿಸುವುದಿಲ್ಲ. ಉದಾ. Azure ಸೈನ್ ಇನ್, Microsoft.com ಸೈನ್ ಇನ್, Live.com ಸೈನ್ ಇನ್ ಇತ್ಯಾದಿ ಇವೆ, ಮತ್ತು ಎಲ್ಲವೂ ಏಕಕಾಲದಲ್ಲಿ ಚಾಲ್ತಿಯಲ್ಲಿವೆ.

  * ಸೆಟಪ್ ಸಮಯದಲ್ಲಿ ನಾವು ಒಂದು ಸಣ್ಣ ಭದ್ರತಾ ಸಮಸ್ಯೆಯನ್ನು ಎದುರಿಸಿದೆವು, ಮತ್ತು ಯಾವುದೇ ಪರಿಹಾರ ಕಂಡುಬರಲಿಲ್ಲ. ಅನೇಕ Microsoft ಪ್ರತಿನಿಧಿಗಳಿಗೆ ಅದನ್ನು ವರದಿ ಮಾಡಲು ನಾವು ಹಲವು ಮಾರ್ಗಗಳನ್ನು ಪ್ರಯತ್ನಿಸಿದೆವು, ಯಶಸ್ಸಿಲ್ಲದೆ. ನಾವು ಅದನ್ನು Microsoft ಭದ್ರತೆಗೆ ಯಶಸ್ವಿಯಾಗಿ ವರದಿ ಮಾಡಿದೆವು, ಅದು ಸರಿಪಡಿಸುವುದಿಲ್ಲ ಎಂದು ಉತ್ತರಿಸಿತು.

  * ದಾಖಲಾತಿ ಹೆಚ್ಚಾಗಿ ತಪ್ಪು ಅಥವಾ ಹಳೆಯದು. ಇದರಲ್ಲಿ ಕೆಲವು Microsoft ನ ಕಳಪೆ ಹುಡುಕಾಟ ಎಂಜಿನ್‌ನಿಂದ, ಮತ್ತು ಕೆಲವು ಸಾಧಾರಣಕ್ಕಿಂತ ಕಡಿಮೆ SEO ದಿಂದ.
  
  * Terraform ಸೆಟಪ್ ಚೆನ್ನಾಗಿ ದಾಖಲಿಸಲಾಗಿದೆ, ಮತ್ತು ಕೆಲಸ ಮಾಡುತ್ತದೆ. ಆದಾಗ್ಯೂ, Microsoft ಸರಣಿ-ಮೂಲಕ Terraform ಸೆಟಪ್ ಉದಾಹರಣೆಗಳನ್ನು ಮಾಡಲು ಮಾರಾಟಗಾರರೊಂದಿಗೆ ವ್ಯವಹಾರ ಸಂಬಂಧಗಳನ್ನು ನಿರ್ಮಿಸುತ್ತಿರುವುದರಿಂದ, AWS ಗೆ ಹೋಲಿಸಿದರೆ Terraform ಬೆಂಬಲ ದುರ್ಬಲ.

ನಮ್ಮ ಸಹೋದ್ಯೋಗಿಗಳ ಅನುಭವಗಳು:

  * ನಮ್ಮದೇ ಕುರುಡು ಮೌಲ್ಯಮಾಪನ ಮಾಡಿದ ನಂತರ, ನಾವು ಸಹೋದ್ಯೋಗಿಗಳ ಅನುಭವಗಳನ್ನು ಹುಡುಕಿದೆವು. ನಾವು ಕಂಡುಕೊಂಡದ್ದು ನಮ್ಮ ಅನುಭವಗಳನ್ನು ದೃಢಪಡಿಸಿತು.

  * ಬಿಲ್ಡ್ ಸಮಯಗಳೊಂದಿಗೆ ಹೆಚ್ಚುವರಿ ಸಮಸ್ಯೆಗಳನ್ನು, ಮತ್ತು ನಿಮ್ಮದೇ-ಬಿಲ್ಡ್-ಸರ್ವರ್-ತನ್ನಿ ಸಮಸ್ಯೆಗಳನ್ನು ಸಹೋದ್ಯೋಗಿಗಳು ವರದಿ ಮಾಡಿದರು. ಈ ಸಮಸ್ಯೆಗಳು UI ಸಮಸ್ಯೆಗಳಿಗಿಂತ ಗಣನೀಯವಾಗಿ ಹೆಚ್ಚು ತೀವ್ರ, ಏಕೆಂದರೆ ಬಿಲ್ಡ್‌ಗಳನ್ನು ಮಾಡುವುದು ಬಿಲ್ಡ್ ಪೈಪ್‌ಲೈನ್‌ನ ಮೂಲ ಉದ್ದೇಶ, ಮತ್ತು ನಾವು ದಿನಕ್ಕೆ ಹಲವಾರು ಮಾಡಬೇಕೆಂದು ನಿರೀಕ್ಷಿಸುತ್ತೇವೆ.

  * ಚರ್ಚಾ ಕ್ಷೇತ್ರಗಳಲ್ಲಿ Azure ಸಹೋದ್ಯೋಗಿಗಳ ಅತ್ಯುತ್ತಮ ಭಾಗವಹಿಸುವಿಕೆಯನ್ನು ನಾವು ಕಂಡೆವು. ಇದಕ್ಕಾಗಿ Microsoft ಗೆ ಅಭಿನಂದನೆಗಳು. Azure PM ಮತ್ತು ಕೋಡರ್ ಆದ Edward Thomson ಅವರ ಭಾಗವಹಿಸುವಿಕೆ, ನೇರತೆ ಮತ್ತು ತಾಂತ್ರಿಕ ವಿವರಣೆಗಳಿಂದ ನಾವು ವಿಶೇಷವಾಗಿ ಪ್ರಭಾವಿತರಾಗಿದ್ದೇವೆ.


### ಪರಿಣಾಮಗಳು

Microsoft Azure DevOps ಆರಿಸುವುದು, Azure ಆರಿಸದಿರುವುದಕ್ಕಿಂತ ಸಮಯ ಮತ್ತು ವೆಚ್ಚದಲ್ಲಿ ಹೆಚ್ಚು ದುಬಾರಿಯಾಗುವ (~3x) ಸಾಧ್ಯತೆ ಕಾಣುತ್ತದೆ.


## ಸಂಬಂಧಿತ


### ಸಂಬಂಧಿತ ನಿರ್ಧಾರಗಳು

ನಾವು Azure DevOps ಆರಿಸಿದರೆ, Azure Repo, Azure Pipeline ಇತ್ಯಾದಿ ಸೇರಿದಂತೆ ಅನೇಕ ಸಂಬಂಧಿತ ಕೊಡುಗೆಗಳಿವೆ. ನಾವು Azure Devops ಆರಿಸಿದರೆ, ಇದು ಹೆಚ್ಚಿನ Azure ಸಾಮರ್ಥ್ಯಗಳನ್ನು ಬಳಸುವುದನ್ನು ಸುಲಭಗೊಳಿಸಬಹುದು, ಅಥವಾ ಇತರ ಮಾರಾಟಗಾರರ ಸಾಮರ್ಥ್ಯಗಳನ್ನು ಬಳಸುವುದನ್ನು ಕಷ್ಟಗೊಳಿಸಬಹುದು ಎಂದು ನಾವು ನಂಬುತ್ತೇವೆ.

Microsoft ಡೆವಲಪರ್ ಅನುಭವದಲ್ಲಿ ಮಹತ್ತರ ಪ್ರಗತಿ ಸಾಧಿಸುತ್ತಿದೆ ಎಂದು ನಾವು ನಂಬುತ್ತೇವೆ, ಮತ್ತು ಡೆವಲಪರ್ ಸಾಧನಗಳ (ಉದಾ. GitHub) ಮತ್ತು ಅವಲಂಬನೆಗಳ (ಉದಾ. Citus) ದೊಡ್ಡ ಸ್ವಾಧೀನವನ್ನು Microsoft ಮಾಡುತ್ತಿರುವುದನ್ನು ನಾವು ಕಾಣುತ್ತೇವೆ.

ನಾವು Azure DevOps ಆರಿಸಿದರೆ, Microsoft ಸ್ವಾಧೀನ ಕೊಡುಗೆಗಳನ್ನು ಆರಿಸುವುದಕ್ಕೆ ನಾವು ಒತ್ತು ನೀಡಲು ಬಯಸಬಹುದು, ಮತ್ತು ಸಿಬ್ಬಂದಿ ವಹಿವಾಟು ಅಪಾಯದಂತಹ ಸಂಭಾವ್ಯ ಅಂಗಾಂಶ-ತಿರಸ್ಕಾರದ ಕಾರಣ ಸ್ವಾಧೀನ ಕೊಡುಗೆಗಳನ್ನು ಹೆಚ್ಚಿನ ಕಾಳಜಿ/ಮೌಲ್ಯಮಾಪನದೊಂದಿಗೆ ಸಮೀಪಿಸಲೂ ಬಯಸಬಹುದು.


### ಸಂಬಂಧಿತ ಅವಶ್ಯಕತೆಗಳು

ಬಿಲ್ಡ್ ಸಮಯಗಳು ಬಹಳ ವೇಗವಾಗಿರಬೇಕೆಂದು ನಾವು ಬಯಸುತ್ತೇವೆ. ಇದಕ್ಕಾಗಿ ಹೆಚ್ಚಿನ ಪ್ರೀಮಿಯಂ ಪಾವತಿಸಲು ನಾವು ಒಪ್ಪುತ್ತೇವೆ. ಇದಕ್ಕೆ ಕಾರಣ ನಾವು ಬಹಳ ವೇಗವಾಗಿ ಪುನರಾವರ್ತಿಸಲು ಬಯಸುವುದು.

ವಿಶ್ವಾಸಾರ್ಹತೆ ಬಹಳ ಹೆಚ್ಚಾಗಿರಬೇಕೆಂದು ನಾವು ಬಯಸುತ್ತೇವೆ. ಇದಕ್ಕಾಗಿ ಹೆಚ್ಚಿನ ಪ್ರೀಮಿಯಂ ಪಾವತಿಸಲು ನಾವು ಒಪ್ಪುತ್ತೇವೆ. ಇದಕ್ಕೆ ಕಾರಣ ಹಣಕಾಸು ವಹಿವಾಟುಗಳು, ಗೋಪ್ಯ ವಹಿವಾಟುಗಳು ಇತ್ಯಾದಿ ಸೇರಿದಂತೆ ಹೆಚ್ಚಿನ ಮೌಲ್ಯದ ಬಳಕೆಯ ಪ್ರಕರಣಗಳನ್ನು ನಾವು ಪರೀಕ್ಷಿಸುತ್ತಿರುವುದು.

ನಮ್ಮ ಅಗ್ರ 4 devops KPI ಗಳು ಚೇತರಿಕೆಯ ಸರಾಸರಿ ಸಮಯವನ್ನು ಒಳಗೊಂಡಿವೆ, ಇದು ವೇಗದ ಬಿಲ್ಡ್‌ಗಳು ಮತ್ತು ಹೆಚ್ಚಿನ ವಿಶ್ವಾಸಾರ್ಹತೆಯನ್ನು ಅಗತ್ಯವಾಗಿಸುತ್ತದೆ.


### ಸಂಬಂಧಿತ ಆರ್ಟಿಫ್ಯಾಕ್ಟುಗಳು

Artifactory ನಂತಹ ಇತರ ವ್ಯವಸ್ಥೆಗಳಲ್ಲಿ ಬಳಸಲು ಸೂಕ್ತವಾದ ಆರ್ಟಿಫ್ಯಾಕ್ಟುಗಳನ್ನು ಬಿಲ್ಡ್ ವ್ಯವಸ್ಥೆ ಔಟ್‌ಪುಟ್ ಮಾಡಬೇಕೆಂದು ನಾವು ಬಯಸುತ್ತೇವೆ.

### Windows ಅಭಿವೃದ್ಧಿ MVP

Windows Development MVP ಇಲ್ಲಿ. ಈ ಸಮಸ್ಯೆಗಳ ಬಗ್ಗೆ ಹೆಚ್ಚು ಧ್ವನಿಯೆತ್ತದಿದ್ದಕ್ಕೆ ಇಲ್ಲಿ ಸ್ವಲ್ಪ ಹೊಣೆ ನಾನು ಹೊರಬೇಕು ಎಂದು ನನಗೆ ಅನಿಸುತ್ತದೆ. ಆದರೆ UX ಸಮಸ್ಯೆಗಳ ಬಗ್ಗೆ ನೀವು "ಆಶ್ಚರ್ಯಗೊಂಡಿದ್ದೀರಿ" ಎಂದು ಕೇಳಿ ನಿರಾಶೆಯಾಗಿದೆ ಎಂದು ಹೇಳಲೇಬೇಕು. UX ಭಯಂಕರವಾಗಿದೆ ಎಂದು ನಾನು ನಿಮ್ಮ ಜನರಿಗೆ ಹೇಳುತ್ತಲೇ ಇದ್ದೇನೆ (ಉದಾ. ಬಿಡುಗಡೆಗೂ ಮೊದಲಿನಿಂದ), ಮತ್ತು "ನಮಗೆ ಗೊತ್ತು, ಸರಿಪಡಿಸುತ್ತಿದ್ದೇವೆ" ಎಂದು ಹಿಂತಿರುಗಿ ಕೇಳುತ್ತಲೇ ಇದ್ದೆ. ನಾನು ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಔಪಚಾರಿಕಗೊಳಿಸಲು ಪ್ರಾರಂಭಿಸಿ ಅದನ್ನು ಪೈಪ್‌ಗಳ ಮೂಲಕ ತಳ್ಳುತ್ತೇನೆ, ಕಾಯಿರಿ. ನಾನು ಸ್ಥಳೀಯನೂ (Bellevue), ಬಂದು ನಮ್ಮ ತುಲನಾತ್ಮಕವಾಗಿ ಸರಳವಾದ oss .net/wpf/uwp ಅಪ್ಲಿಕೇಶನ್ ಅನ್ನು ಪೈಪ್‌ಲೈನ್ ಮಾಡಲು ಪ್ರಯತ್ನಿಸಲು ಇಷ್ಟಪಡುತ್ತೇನೆ. ಇದು ನಮ್ಮಿಬ್ಬರಿಗೂ ಕಣ್ಣು ತೆರೆಸುವುದು ಎಂದು ನಾನು ಊಹಿಸುತ್ತೇನೆ.

ಕೆಲವು ಉದಾಹರಣೆಗಳು:

* ಸಬ್‌ಮಾಡ್ಯೂಲ್‌ಗಳನ್ನು ಹೊಂದಿರುವ git ರೆಪೊದೊಂದಿಗೆ ನೀವು ಪೈಪ್‌ಲೈನ್ ಅನ್ನು ಬಿಲ್ಡ್ ಮಾಡಲು ಸಾಧ್ಯವಿಲ್ಲ.

* ಕೆಲವು ಕಸ್ಟಮ್ ಸಾಧನಗಳಿಗಾಗಿ PATH ಅನ್ನು ಸಂಪಾದಿಸುವುದು ಅಸಾಧ್ಯವೆಂದು ಕಂಡುಬಂದಿತು.

* ಹೊಸ ಪೈಪ್‌ಲೈನ್ ಅನುಭವ ಹೆಚ್ಚು ಅರ್ಥವಾಗುವುದಿಲ್ಲ, ಹೊಸ ಬಳಕೆದಾರರು ಸುತ್ತಲೂ ಕ್ಲಿಕ್ ಮಾಡುತ್ತಾ ಅಂತಿಮವಾಗಿ ತಪ್ಪು ದಾಖಲಾತಿಗೆ ತಲುಪುತ್ತಾರೆ.
