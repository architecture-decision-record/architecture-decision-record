# आर्किटेक्चर फैसला रिकॉर्ड: REST API खातिर snake_case चाहे camelCase?

फैसला: REST API एंडपॉइंट खातिर snake_case नामकरण परंपरा इस्तेमाल कइल जाई

स्थिति: स्वीकार

## संदर्भ

REST API खातिर नामकरण परंपरा में, दू लोकप्रिय रूप बा: snake_case आ camelCase। snake_case रूप ऊ बा जेमें नाम के हर शब्द अंडरस्कोर से अलग कइल जाला, जबकि camelCase ऊ बा जेमें नाम के पहिला शब्द छोट अक्षर में होला, आ बाद के शब्द सब के पहिला अक्षर बड़ होला। ई फैसला तय करी कि REST API खातिर कवन नामकरण परंपरा इस्तेमाल करे के चाहीं।

## फैसला के प्रेरक

- परियोजना में मौजूदा नामकरण परंपरा संगे संगति

- API पर काम करे वाला कवनो भी आदमी खातिर पढ़े-लायकता आ स्पष्टता

- REST API नामकरण खातिर उद्योग सर्वोत्तम अभ्यास संगे तालमेल

- लागू करे आ संभाले में आसानी

## फैसला

REST API एंडपॉइंट खातिर snake_case नामकरण परंपरा इस्तेमाल कइल जाई। ई चुनाव ई कारक से संचालित बा:

1. **संगति**: परियोजना पहिलहीं सब एंडपॉइंट खातिर snake_case नामकरण परंपरा इस्तेमाल करेले, आ पूरा परियोजना में संगति पक्का करे खातिर ई परंपरा बनवले राखल फायदेमंद होई।

2. **पढ़े-लायकता आ स्पष्टता**: snake_case परंपरा जादा पढ़े-लायक आ समझे में आसान बा। अंडरस्कोर शब्द के बीच साफ पृथक्करण देला, नाम के मतलब के पार्स करे आ समझे के आसान बनावत।

3. **उद्योग सर्वोत्तम अभ्यास संगे तालमेल**: snake_case परंपरा उद्योग में व्यापक रूप से इस्तेमाल होला आ REST API खातिर सर्वोत्तम अभ्यास मानल जाला, जे एकरा के परियोजना खातिर नीमन चुनाव बनावेला।

4. **लागू करे आ संभाले में आसानी**: मौजूदा नामकरण परंपरा के साथ चलल लागू करे आ संभाले में जादा आसान बा काहेकि अगर नया परंपरा चुनल जाए त सब मौजूदा कोड आ दस्तावेज अपडेट करे के पड़ी।

## नतीजा

एह फैसला के संभावित नतीजा बा। 

* अगर परियोजना में शामिल होखे वाला कवनो नया टीम सदस्य snake_case नामकरण परंपरा से परिचित नइखे, त ई विकास में भ्रम आ गलती तक ले जा सकेला। लेकिन, चूँकि snake_case एगो व्यापक रूप से इस्तेमाल होखे वाला परंपरा ह, अइसन जोखिम न्यूनतम बा। 
  
* अगर परियोजना में आउर औजार चाहे फ्रेमवर्क इस्तेमाल कइल जात बा जे camelCase परंपरा पर बहुत आधारित बा, त नामकरण परंपरा के बीच बदले खातिर अतिरिक्त मेहनत के जरूरत हो सकेला। लेकिन, ई महत्त्वपूर्ण चिंता नइखे काहेकि परियोजना snake_case परंपरा पर मानकीकृत हो चुकल बा। 
 
कुल मिलाके, REST API एंडपॉइंट खातिर snake_case नामकरण परंपरा इस्तेमाल करे के फैसला एगो संगत, पढ़े-लायक, आ उद्योग-मानक तरीका के परिणाम देला जबकि लागू करे आ संभाले में आसान बा।
