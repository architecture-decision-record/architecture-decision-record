# Запис архітектурного рішення: оркестрація контейнерів Kubernetes

## Постановка проблеми 

Нам потрібно обрати платформу оркестрації контейнерів для нашого зростаючого портфеля хмарно-орієнтованих застосунків. Наше поточне розгортання на застарілій платформі надто повільне й недостатньо гнучке, щоб встигати за нашими зростаючими потребами. Ми шукаємо систему, яка дозволить масштабувати наші сервіси якомога ефективніше без шкоди для гнучкості чи простоти використання.

## Розглянуті альтернативи

1. Docker Swarm

2. Kubernetes

3. Apache Mesos

## Ухвалене рішення

Провівши ретельний аналіз кожної платформи оркестрації контейнерів, ми вирішили впровадити Kubernetes як найкращий варіант для потреб нашого підприємства. Наші причини вибору Kubernetes такі:

1. **Масштабованість:**  унікальна конструкція Kubernetes ідеально підходить для масштабування застосунків, і оскільки наші вимоги до масштабованості з часом змінюватимуться, Kubernetes має вбудовану здатність відповідати цим змінам без жодних проблем.

2. **Децентралізована архітектура:**  топологія master-worker у Kubernetes забезпечує децентралізовану архітектуру, яка гарантує відсутність єдиної точки відмови.

3. **Підтримка спільноти:**  Kubernetes має найбільшу й найактивнішу спільноту з відкритим кодом, а це означає велику кількість учасників, розробників і постачальників, що полегшує нам отримання допомоги та пошук ресурсів.

4. **Підтримка екосистеми:**  Kubernetes має екосистему, що зростає, з різноманітними сторонніми інструментами, інтеграціями з реєстрами контейнерів, конвеєрами CI/CD, сховищами даних тощо.

Тому ми вирішили впровадити Kubernetes як нашу платформу оркестрації контейнерів на сьогодні та найближче майбутнє.
