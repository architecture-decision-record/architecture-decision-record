# Шаблон запису рішення для важливих технічних рішень (ITD)

Це шаблон важливих технічних рішень (Important Technical Decisions, ITD), описаний у статті
[ITDs: a lean ADR for executive technical decision-making at scale - Ignacio Larrañaga](https://ignaciolarranaga.medium.com/itds-a-lean-adr-for-executive-technical-decision-making-at-scale-e18bb3f6a563).

ITD — це цілеспрямована еволюція ADR, оптимізована для швидкості, ясності та
схвалення керівництвом. Якщо ADR документує, що було вирішено, то ITD — це
ощадливий артефакт, у якому рішення стоїть на першому місці і яке саме можна
переглядати, тож зацікавлені сторони можуть швидко його проглянути й легко
поставити під сумнів. ITD добре підходять для технічних рішень, які не є
суто архітектурними, як-от вибір моделі, бібліотеки чи стратегії CI/CD.

У кожному файлі ITD напишіть такі розділи:

# Назва

Сформулюйте саме рішення, а не опис теми.
Наприклад, «Використовувати Qwen2.5 1.5B Instruct для перекладу на пристрої».

## Проблема

Одне речення про те, що ми намагаємося розв’язати.

## Розглянуті варіанти

Альтернативи, що були на столі, з обраним варіантом, виділеним **жирним**.

## Обґрунтування

Лише вирішальні чинники, що привели до вибору, а не вичерпний перелік
усіх плюсів і мінусів.

## Примітки

Необов’язково. Будь-який додатковий контекст, який варто зафіксувати, як-от обмеження,
припущення чи посилання.
