# آرکیٹیکچر فیصلے کا ریکارڈ: JSON یا gRPC استعمال کرنے والی API

## حالت

قبول شدہ

## سیاق و سباق

ہم ایک نئی سروس کے لیے API ڈیزائن کر رہے ہیں جسے متعدد کلائنٹس استعمال کریں گے۔ ہم API نافذ کرنے کے لیے دو اختیارات پر غور کر رہے ہیں: HTTP پر JSON یا gRPC۔

HTTP پر JSON، APIs بنانے کا ایک وسیع پیمانے پر استعمال ہونے والا طریقہ ہے اور بہت سی پروگرامنگ زبانوں اور فریم ورکس میں سپورٹ کیا جاتا ہے۔ یہ طریقہ سادہ، ہلکا پھلکا اور سمجھنے میں آسان ہے، جو اسے بہت سے منصوبوں کے لیے اچھا انتخاب بناتا ہے۔ تاہم یہ دوسرے اختیارات کے مقابلے میں کم مؤثر ہو سکتا ہے، خاص طور پر بڑی مقدار میں ڈیٹا سنبھالتے وقت۔

gRPC اس کے برعکس ایک نئی ٹیکنالوجی ہے جو APIs بنانے کا زیادہ مؤثر طریقہ پیش کرتی ہے۔ یہ ڈیٹا منتقل کرنے کے لیے بائنری سیریلائزیشن استعمال کرتی ہے جو JSON کے مقابلے میں تیز اور زیادہ مختصر ہو سکتی ہے۔ gRPC دو طرفہ اسٹریمنگ کو بھی سپورٹ کرتی ہے، جو اسے ریئل ٹائم ایپلیکیشنز کے لیے اچھا انتخاب بناتی ہے۔

## فیصلہ

دونوں اختیارات کے فوائد و نقصانات پر غور کرنے کے بعد ہم نے اپنی API کے لیے gRPC استعمال کرنے کا فیصلہ کیا ہے۔ اگرچہ HTTP پر JSON ایک سادہ اختیار ہے، ہمیں یقین ہے کہ gRPC ہماری سروس کے لیے زیادہ مؤثر اور وسعت پذیر حل فراہم کرے گی۔ ہم یہ بھی توقع کرتے ہیں کہ ہماری API بڑی مقدار میں ڈیٹا سنبھالے گی، اور اس استعمال کے لیے gRPC کی بائنری سیریلائزیشن زیادہ مؤثر ہوگی۔

اس کے علاوہ ہمیں یقین ہے کہ gRPC کی دو طرفہ اسٹریمنگ کی سپورٹ ان ریئل ٹائم ایپلیکیشنز کے لیے فائدہ مند ہوگی جو ہم مستقبل میں تیار کر سکتے ہیں۔

## نتائج

gRPC کا انتخاب کرنے سے ہمیں HTTP پر JSON کے مقابلے میں اپنی API بنانے کے لیے ٹولز اور لائبریریوں کا مختلف سیٹ استعمال کرنا ہوگا۔ اس کے لیے ان ٹیکنالوجیز کو سیکھنے اور نافذ کرنے میں اضافی وقت اور کوشش درکار ہو سکتی ہے۔ مزید برآں جو کلائنٹس ہماری API استعمال کرنا چاہتے ہیں انہیں gRPC سے ہم آہنگ لائبریریاں استعمال کرنی ہوں گی جو HTTP پر JSON لائبریریوں جتنی وسیع پیمانے پر سپورٹڈ نہ ہوں۔

تاہم ہمیں یقین ہے کہ gRPC استعمال کرنے کے فوائد ان ممکنہ نقصانات سے بڑھ کر ہیں، اور ہم پراعتماد ہیں کہ یہ فیصلہ زیادہ مؤثر اور وسعت پذیر API کا باعث بنے گا۔
