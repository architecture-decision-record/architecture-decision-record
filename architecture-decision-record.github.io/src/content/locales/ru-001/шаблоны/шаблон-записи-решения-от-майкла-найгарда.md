# Шаблон записи решения от Майкла Найгарда

Это шаблон из статьи [Documenting architecture decisions - Michael Nygard](http://thinkrelevance.com/blog/2011/11/15/documenting-architecture-decisions).
Для управления файлами ADR можно использовать [adr-tools](https://github.com/npryce/adr-tools).

В каждом файле ADR напишите эти разделы:

# Название

## Состояние

Каково состояние, например proposed, accepted, rejected, deprecated, superseded и т. д.?

## Контекст

Какую проблему мы видим, которая побуждает к этому решению или изменению?

## Решение

Какое изменение мы предлагаем и/или вносим?

## Последствия

Что становится проще или сложнее делать из-за этого изменения?
