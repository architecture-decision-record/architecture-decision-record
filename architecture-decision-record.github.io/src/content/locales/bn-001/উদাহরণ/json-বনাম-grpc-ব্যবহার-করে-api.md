# আর্কিটেকচার সিদ্ধান্ত রেকর্ড: JSON বনাম gRPC ব্যবহার করে API

## অবস্থা

গৃহীত

## প্রেক্ষাপট

আমরা একটি নতুন সেবার জন্য API নকশা করছি, যা একাধিক ক্লায়েন্ট ব্যবহার করবে। API বাস্তবায়নের জন্য আমরা দুটি বিকল্প বিবেচনা করছি: HTTP-র ওপর JSON অথবা gRPC।

HTTP-র ওপর JSON হলো API তৈরির একটি বহুল ব্যবহৃত পদ্ধতি এবং এটি অনেক প্রোগ্রামিং ভাষা ও ফ্রেমওয়ার্কে সমর্থিত। এই পদ্ধতি সরল, হালকা এবং বোঝা সহজ, যা অনেক প্রকল্পের জন্য ভালো পছন্দ। তবে অন্যান্য বিকল্পের তুলনায়, বিশেষ করে বড় পরিমাণ ডেটা সামলানোর ক্ষেত্রে, এটি কম দক্ষ হতে পারে।

অন্যদিকে gRPC একটি নতুন প্রযুক্তি, যা API তৈরির আরও দক্ষ উপায় দেয়। এটি ডেটা স্থানান্তরে বাইনারি সিরিয়ালাইজেশন ব্যবহার করে, যা JSON-এর চেয়ে দ্রুত ও আরও সংক্ষিপ্ত হতে পারে। gRPC দ্বিমুখী স্ট্রিমিংও সমর্থন করে, ফলে এটি রিয়েল-টাইম অ্যাপ্লিকেশনের জন্য ভালো পছন্দ।

## সিদ্ধান্ত

দুটি বিকল্পের সুবিধা-অসুবিধা বিবেচনা করার পর আমরা আমাদের API-র জন্য gRPC ব্যবহারের সিদ্ধান্ত নিয়েছি। HTTP-র ওপর JSON সরলতর বিকল্প হলেও আমরা বিশ্বাস করি gRPC আমাদের সেবার জন্য আরও দক্ষ ও সম্প্রসারণযোগ্য সমাধান দেবে। আমরা এও প্রত্যাশা করি যে আমাদের API বিপুল পরিমাণ ডেটা সামলাবে, এবং এই ব্যবহারে gRPC-র বাইনারি সিরিয়ালাইজেশন আরও দক্ষ হবে।

এ ছাড়া আমরা বিশ্বাস করি, gRPC-র দ্বিমুখী স্ট্রিমিং সমর্থন ভবিষ্যতে আমরা যেসব রিয়েল-টাইম অ্যাপ্লিকেশন তৈরি করতে পারি, তাদের জন্য উপকারী হবে।

## পরিণতি

gRPC বেছে নেওয়ার ফলে HTTP-র ওপর JSON ব্যবহারের তুলনায় আমাদের API তৈরির জন্য ভিন্ন একগুচ্ছ টুল ও লাইব্রেরি ব্যবহার করতে হবে। এই প্রযুক্তিগুলো শিখতে ও বাস্তবায়ন করতে অতিরিক্ত সময় ও প্রচেষ্টা লাগতে পারে। এ ছাড়া যেসব ক্লায়েন্ট আমাদের API ব্যবহার করতে চায়, তাদের gRPC-সামঞ্জস্যপূর্ণ লাইব্রেরি ব্যবহার করতে হবে, যেগুলো HTTP-র ওপর JSON লাইব্রেরির মতো এত ব্যাপকভাবে সমর্থিত নাও হতে পারে।

তবে আমরা বিশ্বাস করি, gRPC ব্যবহারের সুবিধা এই সম্ভাব্য অসুবিধাগুলোর চেয়ে বেশি, এবং আমরা আত্মবিশ্বাসী যে এই সিদ্ধান্ত আরও দক্ষ ও সম্প্রসারণযোগ্য API এনে দেবে।
