# Architektur-Decisiounsopzeechnung fir de Python-Django-Framework

Decisiounsdatum: 2021-07-15

Zoustand: Akzeptéiert

## Kontext

Eis Organisatioun plangt, eng Webapplikatioun z'entwéckelen, déi Clientedaten verwalt. Mir hunn Python als Programméiersprooch gewielt an iwwerleeë Django als Web-Framework fir d'Entwécklung vun der Applikatioun.

## Decisioun

Mir hunn decidéiert, de Django-Web-Framework fir d'Entwécklung vun der Webapplikatioun ze benotzen. Django bitt e robust Set vun Tools a Funktiounen, fir Webapplikatiounen séier an effizient ze bauen. 

## Faktoren

E puer vun de Faktoren, déi eis Decisioun beaflosst hunn, sinn:

1. Object-Relational Mapping (ORM): Django huet en agebaute ORM, deen eis erlaabt, mat der Datebank ze interagéieren, ouni SQL-Ufroen ze schreiwen. Dat mécht et méi einfach, d'Applikatioun z'entwéckelen an op laang Siicht z'erhalen.

2. MVC-Framework: Django follegt enger Model-View-Controller-(MVC)-Architektur, wouduerch et méi einfach ass, d'Geschäftslogik- an d'Presentatiounsschichten vun der Applikatioun ze trennen.

3. Skaléierbarkeet: Django ass fir seng Skaléierbarkeetsfäegkeeten bekannt, wouduerch et eng exzellent Wiel fir d'Entwécklung vu groussen Applikatioune ass.

4. Sécherheet: Django huet agebaut Sécherheetsfunktiounen, wéi Schutz géint gängeg Webattacken wéi Cross-Site-Scripting (XSS) a SQL-Injection.

5. Ënnerstëtzung vun der Communautéit: Django huet eng grouss an aktiv Communautéit, déi Ënnerstëtzung bitt an zur Entwécklung vum Framework bäidréit.

## Berécksiichtegt Alternativen

Mir hunn aner Web-Frameworks wéi Flask a Pyramid berécksiichtegt. Mir hu awer fonnt, datt Django e méi reife an etabléierte Framework mat engem robuste Set u Funktiounen ass.

Mir hunn och diskutéiert, d'Applikatioun ouni Web-Framework z'entwéckelen an Bibliothéiken wéi SQLAlchemy a Flask-RESTful ze benotzen. Mir hu awer fonnt, datt Django méi breet Funktionalitéit bitt, wouduerch et eng besser Wiel fir eng komplett Webapplikatioun ass.

## Konsequenzen

D'Unhuele vu Django féiert zu de folgende Konsequenzen:

1. Méi einfach, d'Applikatioun z'entwéckelen an z'erhalen, wéinst dem Django seng agebaute Tools a Funktiounen.

2. Trennung vu Geschäftslogik a Presentatiounsschicht, wat zu méi organiséierte Code féiert, deen einfacher z'erhalen ass.

3. Skaléierbarkeet a Robustheet vun der Applikatioun.

4. Agebaut Sécherheetsfunktiounen, déi hëllefen, d'Applikatioun géint gängeg Webattacken ze schützen.

5. Zougang zu enger grousser an aktiver Communautéit fir Ënnerstëtzung.

Mir verstinn, datt Django eng méi steil Léierkurve huet wéi aner Frameworks, mir fannen awer, datt et d'Investitioun fir déi laangfristeg Virdeeler wäert ass, déi et bitt.

## Conclusioun

Op Basis vun de berécksiichtegte Faktoren hu mir decidéiert, de Django-Web-Framework fir d'Entwécklung vun der Webapplikatioun ze benotzen. Mir gleewen, datt dem Django seng Funktiounen, d'Ënnerstëtzung vun der Communautéit an d'Skaléierbarkeetsfäegkeeten et zur bescht Wiel fir de Bau vun enger kompletter Webapplikatioun maachen. Mir formatéieren eis Entwéckler, fir Django ze benotzen, fir sécherzestellen, datt de Framework effektiv an effizient benotzt gëtt.
