# ఆర్కిటెక్చర్ నిర్ణయ రికార్డు: REST API కోసం snake_case లేదా camelCase?

నిర్ణయం: REST API ఎండ్పాయింట్లకు snake_case పేరు పెట్టే సంప్రదాయాన్ని వాడతారు

స్థితి: అంగీకరించబడింది

## సందర్భం

REST APIల పేరు పెట్టే సంప్రదాయాలలో రెండు ప్రజాదరణ పొందిన ఫార్మాట్లు ఉన్నాయి: snake_case, camelCase. snake_case ఫార్మాట్లో పేరులోని ప్రతి పదం అండర్స్కోర్లతో వేరు చేయబడుతుంది, camelCaseలో పేరులోని మొదటి పదం చిన్న అక్షరాలలో ఉంటుంది, తర్వాతి పదాల మొదటి అక్షరం పెద్ద అక్షరంగా ఉంటుంది. REST API కోసం ఏ పేరు పెట్టే సంప్రదాయాన్ని వాడాలో ఈ నిర్ణయం నిర్ణయిస్తుంది.

## నిర్ణయ చోదకాలు

- ప్రాజెక్ట్లో ఉన్న పేరు పెట్టే సంప్రదాయాలతో స్థిరత్వం

- APIపై పని చేసే ఎవరికైనా చదవగలిగే సౌలభ్యం, స్పష్టత

- REST API పేరు పెట్టే సంప్రదాయాలకు పరిశ్రమ ఉత్తమ ఆచరణలతో సమన్వయం

- అమలు, నిర్వహణ సౌలభ్యం

## నిర్ణయం

REST API ఎండ్పాయింట్లకు snake_case పేరు పెట్టే సంప్రదాయాన్ని వాడతారు. ఈ ఎంపికను ఈ క్రింది అంశాలు నడిపిస్తున్నాయి:

1. **స్థిరత్వం**: ప్రాజెక్ట్ ఇప్పటికే అన్ని ఎండ్పాయింట్లకు snake_case పేరు పెట్టే సంప్రదాయాన్ని వాడుతోంది, మొత్తం ప్రాజెక్ట్ అంతటా స్థిరత్వాన్ని నిర్ధారించడానికి ఈ సంప్రదాయాన్ని కొనసాగించడం ప్రయోజనకరం.

2. **చదవగలిగే సౌలభ్యం, స్పష్టత**: snake_case సంప్రదాయం మరింత చదవడానికి వీలుగా, అర్థం చేసుకోవడానికి సులభంగా ఉంటుంది. అండర్స్కోర్లు పదాల మధ్య స్పష్టమైన విభజనను అందిస్తాయి, పేరు అర్థాన్ని విశ్లేషించడం, అర్థం చేసుకోవడం సులభం చేస్తాయి.

3. **పరిశ్రమ ఉత్తమ ఆచరణలతో సమన్వయం**: snake_case సంప్రదాయం పరిశ్రమలో విస్తృతంగా వాడబడుతోంది, REST APIలకు ఉత్తమ ఆచరణగా పరిగణించబడుతుంది, ప్రాజెక్ట్కు మంచి ఎంపికగా చేస్తుంది.

4. **అమలు, నిర్వహణ సౌలభ్యం**: కొత్త సంప్రదాయాన్ని ఎంచుకుంటే ప్రస్తుత కోడ్, డాక్యుమెంటేషన్ అంతా నవీకరించాల్సి ఉంటుంది కాబట్టి, ఉన్న పేరు పెట్టే సంప్రదాయాన్ని కొనసాగించడం అమలు చేయడానికి, నిర్వహించడానికి సులభం.

## పర్యవసానాలు

ఈ నిర్ణయానికి సంభావ్య పర్యవసానాలు ఉన్నాయి. 

* ప్రాజెక్ట్లో చేరే కొత్త బృంద సభ్యులకు snake_case పేరు పెట్టే సంప్రదాయం పరిచయం లేకపోతే, అది అభివృద్ధిలో గందరగోళానికి, పొరపాట్లకు దారి తీయవచ్చు. అయితే, snake_case విస్తృతంగా వాడే సంప్రదాయం కాబట్టి, అలాంటి ప్రమాదం కనిష్ఠం. 
  
* ప్రాజెక్ట్లో camelCase సంప్రదాయంపై ఎక్కువగా ఆధారపడిన ఇతర సాధనాలు లేదా ఫ్రేమ్వర్క్లను వాడితే, పేరు పెట్టే సంప్రదాయాల మధ్య మార్చడానికి అదనపు శ్రమ అవసరం కావచ్చు. అయితే, ప్రాజెక్ట్ snake_case సంప్రదాయంపై ప్రామాణీకరించింది కాబట్టి ఇది గణనీయమైన ఆందోళన కాదు. 
 
మొత్తంమీద, REST API ఎండ్పాయింట్లకు snake_case పేరు పెట్టే సంప్రదాయాన్ని వాడాలనే నిర్ణయం స్థిరమైన, చదవడానికి వీలైన, పరిశ్రమ-ప్రామాణిక విధానాన్ని ఇస్తూనే అమలు చేయడానికి, నిర్వహించడానికి సులభంగా ఉంటుంది.
